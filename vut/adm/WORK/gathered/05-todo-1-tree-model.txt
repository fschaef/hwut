todo-1  THE MODEL IS A TREE
        decided, unbuilt -- parked behind a trigger

DECIDED
    The presentation model's shape is a TREE with annotations, not a
    flat record set:

        Report
          Directory  suite/TEST            good=False
            Node     test-a.sh one         ok
            Node     test-b.sh             test-failed
          Directory  compare/TEST          good=True
            Node     test-x.py             ok

    NOT a pure hierarchy -- three things do not sit as children:

        fault   attaches to the ROOT as readily as to a directory
        frame   attaches to a DIRECTORY, not to a node
        cause   is a CROSS-LINK between nodes
                ('test-built.c' <- 'build[make test-built.c]')

WHY THE TREE
    The wire already IS a tree walk: 'tree-begun / dir-begun /
    run-* / dir-done / tree-done'. Flat is the step that THROWS THAT
    AWAY, and the grouping is then rebuilt three times by filtering
    on key[0]:

        CPlainFlow._count()
        CPlainFlow._failure_key_list()
        CRunSummary.failure_db()

    Keeping what the orchestrator already sent is the cheaper
    representation, not the more elaborate one.

TRIGGER -- when this gets built
    The day a SECOND emitter is actually being written (html, pdf,
    json, sse). One emitter does not pay for the grouping; two do.
    Precedent: the pype foreign-executor seam, parked pending
    demonstrated need.

NOT AFFECTED
    'CRunSummary' stays FLAT, stays in 'orchestrator/run/', and stays
    the operational source for the 'E_ExitCode' decision. Two shapes,
    two questions:

        CRunSummary   "did anything fail"      -> exit status
        the tree      "what happened, grouped" -> presentation

WHAT IS STILL OPEN
    Whether the tree is built incrementally (fed by the receiver, so
    a live console walks it as it grows) or folded at the end (so a
    document emitter takes it whole). The console needs the first;
    pdf cannot use anything but the second. Terminal is the base
    case -- an incremental model yields the complete one, never the
    reverse -- so this likely settles itself, but it is NOT ruled.
