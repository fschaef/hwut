WHAT AN OWNER OWES (R-41, R-57): its configuration declared as a FROZEN
DATACLASS, with the default it judges least astonishing on each member --
its own members, in its own words. No face, no second declaration: where a
word of ours is several members of its, an ADAPTER in 'relation.py' bridges
the two, and the default is derived backwards through it.

THE MOVE, per owner:
  1  The owner declares its face.
  2  'RELATION' names the owner's class; member names change with it.
  3  The stand-in class is deleted; when the file is empty, it goes.

Nothing else changes, and '_assert_relation()' fails loudly at import if a
name does not match. 'test-defaults.py' prints every declared default, so
each step's GOOD file change IS the contract change.

THE PROVISIONAL VALUES were not ruled one by one. One is worth the owner's
eye: 'caps.network = True' -- the stand-in permits network access, and the
opposite is defensible. It is procsitter's call.
