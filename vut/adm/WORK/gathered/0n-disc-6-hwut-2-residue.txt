The tree holds     GOOD/test-group_table.py--groups.txt
The framework asks GOOD/test-group_table.py--groups.stdout

HALF OF THE 1.0 NAMING IS IN PLACE and half is not. The KEY is the
source file WHOLE ('key_name', E-14's ruling: 'test-x.lua' and
'test-x.py' must not share a record). The SUFFIX is still the
SUBJECT's -- '.stdout', '.stderr' -- where 1.0 names one file, '.txt'.

That single suffix is the whole of r-1. It was left deliberately: the

the framework the code base is actually tested with. E-14 holds the
open question -- the framework learns '.txt', or the files are moved
to '.out'/'.err' when 2.0 is functional. RULED: not now.

r-2   8 x  -- 'hwut-info.dat' IS NOT READ                     ** CLOSED **
----------------------------------------------------------------------------
    7  test-test_id_db.py [every choice]  'killed by the supervisor'
    1  benchmark-hwut_hocon.py            3 faults, read as a header

'engine/bookkeeper/TEST/hwut-info.dat' says

    python *.py
    --not config.py

and that is CORRECT AND SUFFICIENT for hwut 1.0: the file needs no
she-bang, because the directory states its interpreter. VUT 2.0 does
not read that file, so it launches the application BY ITS OWN NAME,
finds no she-bang, and reports a containment that never happened.

'test_writing_support/python/TEST/hwut-info.dat' likewise says
'--not benchmark*.py'; unread, the benchmark's SAMPLE HOCON is taken
for a header and faults three times.

THIS IS THE RENOVATOR GAP (todo-1), and it now accounts for more of
the residue than everything except the suffix. A tree that states its
own interpreter perfectly, to a framework that cannot hear it.

CLOSED (2026-08-30, R-73): the root cause was NO DERIVATION in the
exploration, not the unread file. 'language-setup' in 'hwut-root.conf'
now binds '.py' to python and names the interpreter, so the seven
choices run as 1.0 ran them, she-bang or none. What 'hwut-info.dat'
still says that the framework does not hear is the '--not' line; that
becomes 'ignore' in the directory's 'hwut.conf', and renovate (todo-1)
translates it. The benchmark is that case.

    4  test-procsitter_limits.py  wall_clock, pids, self_exit_codes,
                                  stderr_tail_cap

THE FRAMEWORK IS RIGHT IN BOTH. Measured: 'soduko' peaks at 1069 MB
against the 512 MB default -- a genuinely heavy test, wanting
'caps { memory_mb = 2048 }' in its header or a smaller puzzle.

The procsitter four are subtler: tests whose SUBJECT is exceeding
caps, run under caps. The outer supervisor contains the test that is
testing containment. Their own 'caps' key is the intended remedy, but
whether a containment test should be capped AT ALL is a question --
a cap it cannot exceed makes the test meaningless, and a cap it can
makes the outer report indistinguishable from the inner one.

r-4   A DOMAIN ERROR THROWN WHERE A REPORT IS OWED            ** CLOSED **
----------------------------------------------------------------------------
'RegionSyntaxError' escaped 'equivalence_check._compare' into the
scheduler and died as 'Task exception was never retrieved', twice in
one run, with the traceback on the terminal.

A BROKEN REGION FRAMING IS A VERDICT WITH A REASON. The text arrived;
it cannot be READ. 'E_TestRunResult.REGION_SYNTAX_ERROR' -- "region
framing is broken" -- and it ranks ABOVE completeness: a text that
cannot be read establishes nothing that follows it, not the terminal,
not the stderr note, not the verdict.

THE CLASS MATTERS MORE THAN THE CASE. This is the second of its kind
(a missing session sink was the first, 'test-app-no-output'). Both
were an exception raised through a boundary that owes a REPORT. A
third will exist. 'test-hygiene.py' is the natural place to forbid it:
no coroutine of the run may let a non-framework exception cross into
the scheduler.
