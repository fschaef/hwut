
C-1   THE CONTRACT -- A SHARED NAME BELONGS WHERE ALL ITS READERS
      SIT ABOVE IT

PROBLEM   'engine/compare' held seven MUTUAL import pairs among five
          sub-components and four of the tree's ten module-level
          cycles -- the one place in the tree with no readable
          direction. Measured ('adm/import_graph.py --shared'), four
          of those pairs rested on a SINGLE NAME travelling backwards
          against three to eight going forwards.

DECISION  'engine/compare/contract' holds the vocabulary in which the
          parties of a comparison name the same things: 'E_Verdict',
          'E_Chunk', 'E_ToleranceId', 'E_EditId' and the semantics
          that give them meaning; 'AnalogyDb' and 'FrozenAnalogyDb',
          the shapes an analogy is carried in.

          IT IMPORTS NOTHING OF THIS TREE, and that is the property
          which MAKES it a contract: every party sits above it, so no
          party can be made to wait on another.

          WHAT BELONGS: SHAPES. An enum has no behaviour at all and
          exists precisely so two parties may say the same word; a
          request shape is what one party asks of another; an error
          kind is part of an interface.
          WHAT DOES NOT: anything whose move would move BEHAVIOUR.
          THE TEST -- would moving it require moving behaviour? 'Line'
          has twenty methods and imports 'core'; 'PatternFinder'
          computes; 'Store' holds state. Those are shared because a
          REAL DEPENDENCY exists, and the layering must express it,
          never hide it behind a shared package.

COST      Thirty-six modules re-pointed. The door re-exports and says
          so with '__all__' -- a re-export is not an unused import,
          and saying so to the reader matters more than saying it to
          the tool.

VERIFIED  'reading -> engine' fell from 8 names to 1; 'region ->
          engine' from 6 to 1. Every shared name of 'compare' now
          reads 'from contract' except the three that carry
          behaviour. 301 declared choices unmoved.

WHAT IT DID NOT DO, and this is the honest half: THE SEVEN MUTUAL
          PAIRS STAND, and the module-cycle count is still ten -- the
          'enums <-> semantics' pair simply moved INTO the contract
          with them. What holds the remaining pairs shut is exactly
          the three names the test above forbids moving. A contract
          removes the cycles that a MISPLACED SHAPE caused; it cannot
          remove the ones a real mutual dependency causes, and
          'reading <-> region' looks like one: a reading contains
          regions, a region is made of readings.

          THAT REMAINDER IS NOW A QUESTION FOR ARCHITECTURE, not for
          a tool: state the mutual recursion as a design, or break it
          by moving behaviour. This entry does neither.

GRAVEYARD MOVING 'Line' AND 'PatternFinder' TOO -- rejected: both
          carry behaviour, and a 'contract' holding machinery is a
          package named for a property it does not have.

C-4   REGION FRAMING IS SWITCHABLE, LIKE EVERY OTHER FEATURE (2026-09-02)

PROBLEM   '##! <handler>' and '####' were read in EVERY text, always.
          Every other lexical feature has a flag -- 'analogy_f',
          'ignored_line_f', 'whitespace_f', 'backslash_f' -- and this
          one had none. A text that TALKS ABOUT framing therefore
          could not be read at all: this tree's own
          'test-equivalence-vs-association.py' prints a side-by-side
          table whose CELLS hold '##! potpourri', and the reader saw
          a shebang with a parameter '|'. Four choices of the compare
          suite failed on it, carried as open; 'hwut.play' on any of
          them ended in a traceback.

DECISION  'ConfigurationPatternFinder.regions_f: bool = True'. False:
          the markers are NO LONGER REGIONS -- they fall to the
          ordinary rules, where '##! ...' meets the ignored-line
          marker '##' and reads as a comment; with comments off too,
          as content. Switching regions off REMOVES A CLASS; it
          invents none.

          THE NAME, in two turns: 'region_f' was refused as too weak,
          'regions_enabled' proposed and built, then ruled back to
          'regions_f' -- the plural says what is switched and the
          '_f' keeps the habit of its five neighbours
          ('analogy_f', 'ignored_line_f', 'whitespace_f',
          'backslash_f', 'strip_whitespace_f'). One suffix for one
          kind of member is worth more than one member's clarity.

          JUDGED IN ONE PLACE: 'reading/line_scanner.classify()', the
          one function where a line becomes a class. Nothing
          downstream can see a region the reader was told not to
          read, so no second gate exists to disagree with the first.

          THE HWUT WORD IS 'tolerance.regions', beside
          'tolerance.whitespace' and 'tolerance.slash', stated per
          choice or per application:

              # @hwut { title = "..."  tolerance { regions = false } }

          Related in 'relation.py' to 'regions_f', so
          'hwut.show' prints its default like every other parameter
          and 'test-defaults.py' checks it.

COST      One member in compare's declaration, its mirror in
          'owner_faces_provisional.ConfigCompare', one leaf on
          'Tolerance', one line in the validator's vocabulary, one
          in the adapter's mapping. The hwut word is 'tolerance.
          regions' -- the word drops the suffix, as
          'tolerance.whitespace' does for 'whitespace_f'. Two tests of this tree state
          'regions = false' and stop failing:
          'test-equivalence-vs-association.py' (3 choices) and
          'reading/test-chunk_pipe.py' (1). Compare: 119 ok / 6 fail
          -> 123 ok / 2 fail, the two remaining being the memory-cap
          kills (disc-6 r-3), untouched.

GRAVEYARD Escaping the marker in the text -- rejected: the text is
          the subject, and a framework that requires the author to
          alter their program's output to be testable has failed at
          the one thing it is for.
          Auto-detection ("this looks like content") -- rejected: a
          reader that guesses would silently reinterpret a region
          somebody meant, which is the very thing 'RegionSyntaxError'
          exists to make loud.

C-8   A SLOTTED STRUCT REFUSES A MISSPELT FIELD                 (2026-09-04)
------------------------------------------------------------------------------
RECORDED 2026-09-04, on striking 'operations/DISCUSSIONS' todo-12, which
raised this and is now built. The number is the next free one in this
component's series; the ruling itself is older than the entry.
PROBLEM   'Configuration' was slotted and refused a misspelt field on
          itself. 'ConfigurationPatternFinder' was NOT, so

              c.pattern_finder.numeric_tolerence_ratio = 0.01

          was ACCEPTED and 'numeric_tolerance_ratio' stayed 0. The
          author believes a tolerance is in force; it is not. Under
          'absent and empty never collapse' this is the worst shape a
          defect can take: the test then passes or fails for a reason
          NOBODY WROTE DOWN, and no error is raised anywhere to say so.
          It is silent, and it is silent in the direction of a false
          pass.
DECISION  EVERY CONFIGURATION STRUCT IS SLOTTED.
          '@dataclass(slots=True)' on 'ConfigurationPatternFinder' as
          on 'Configuration', so a misspelt attribute raises at the
          point of the mistake rather than being kept as a new
          attribute nothing reads. A test choice demonstrates the
          refusal ('TEST/test-configuration.py', choice 'slots'), so
          the law is checked and not merely stated.
          Nothing changes for the callers: 'TestChoiceConfiguration'
          holds this struct verbatim either way.
COST      A field cannot be added to a configuration by assignment from
          outside; it must be declared. That is the point, and it is
          paid once per new field.
GRAVEYARD A validator that walks the struct after construction and
          reports unknown names: it runs LATER than the mistake, needs
          a list of legal names beside the class (a second place to be
          wrong), and catches nothing the language catches for free.


C-9   THE 'unaccepted' REGION: CONTENT NOBODY HAS JUDGED           (2026-09-09)
------------------------------------------------------------------------------
PROBLEM   A partial acceptance -- some lines of a candidate taken into
          the nominal, the rest left as found -- had no way to say
          which lines were left. A nominal is read as a whole; a line
          nobody decided about passes or fails on its content like any
          other, and a green run then proves less than it says.

DECISION  A REGION KIND, registered beside the others:

              ##! unaccepted
              <lines nobody has looked at>
              ####

          Its rule is the OPPOSITE of 'ignore': equivalence is False
          wherever either side holds a line, and the association shows
          every pair as DIFFERING -- a run meeting the region fails
          until someone decides. An EMPTY region on both sides is
          equivalent: nothing undecided stands in it, and the lawyer,
          who sees no pair, must agree with the judge.

          THE '!' IS LOAD-BEARING. '## unaccepted' is an IGNORED
          commentary line and passes silently; '##!' is REGION_BEGIN,
          recognised before the ignored-line rule
          ('reading/line_scanner.py'). No new grammar: a name in the
          registry, and the framing the language already had.

          WHICH SIDE: a nominal's. A subject carrying the framing is a
          test application that printed it itself.

OWED, NOT HERE: the verdict WORD. A run failing on an unaccepted
          region is not a regression and must not read as one; it
          wants its own word beside FAIL and STAINED, so the census
          can count it apart and the closing hint can name the way
          forward ('hwut.accept'). That is the display's and the
          book's, and comes with the partial acceptance that writes
          the region (services E-58).

COST      One more handler name in every 'known handlers:' message.

GRAVEYARD A new token ('<undefined>') -- rejected: every reader would
          learn a word meaning "we did not look"; the region framing
          already means "read these lines under this rule", and the
          rule here is "fail".


C-10  THE CLOSING TOKEN IS A CHUNK OF ITS OWN                       (2026-09-10)
----------------------------------------------------------------------------
PROBLEM   E-60's mirror puts '<hwut-end>' outside every region, and R-70
          needs it last. Fused into the block above it on the subject
          side, it faced a token standing alone on the nominal side --
          and neither could pair. Measured: both read as one-sided.

DECISION  compare's reader splits a trailing '<hwut-end>' into a chunk
          of its own, FOR EVERY STREAM. The display names its section
          'CLOSING-TOKEN' and sets it apart, at the foot: the screen
          reminds whoever reads it of a characteristic of an hwut test
          -- a stream ends with its own testimony that it completed.
          R-70 enforces it; the display teaches it.

          AN 'unaccepted' NOMINAL CHUNK PAIRS WITH ANY SUBJECT CHUNK.
          Every other handler says HOW a stretch is read, and two
          readings cannot both claim one line; 'unaccepted' says only
          WHETHER anybody looked, a statement about the nominal's
          history. The zip pairs them and 'region/unaccepted/
          associate.py' -- written for a subject side it never received
          -- zips the lines as SUBSTITUTE. Without this the two streams
          DOUBLE on screen.

          THE POST-TAKE SHAPE -- one subject chunk facing 'region |
          plain | region', which every take leaves behind -- is SPLIT
          to face the run, anchored by CONTENT: a taken line IS its
          subject line, byte for byte, so a plain nominal chunk is found
          in the subject exactly and monotone, and a region receives the
          subject lines between its neighbours' anchors. The zip keeps
          ONE CHUNK of nominal look-ahead for it. The cut fires ONLY
          beside a region: plain facing plain with no region in sight
          pairs as it always has, so compare's association is never
          second-guessed where nobody took anything.

COST      compare's own GOODs do not move for the token (measured: no
          fixture carries it). Fifteen downstream GOODs move, each by
          the one section line. The look-ahead changes WHEN the nominal
          is read, so 'test-associate-race.py's three arrival traces
          move -- their yielded pairs byte-identical -- and that test,
          older than R-70, now ends in the token it never printed.

GRAVEYARD Peeling the token in the session only -- rejected: the mirror
          stays off by one chunk. Tolerating a trailing extra nominal
          chunk in the zip -- rejected: measured to flush as
          BAD_SUBJECT_HAS. Pairing by line offset after a take --
          rejected: the first N != M take breaks it for good. Cutting a
          plain chunk wherever its lines are found -- rejected, measured:
          it re-associated ordinary plain/plain pairs in four standing
          suites where no region stood.

C-11  A NUMBER IS ALWAYS A NUMBER                                  (2026-09-15)
----------------------------------------------------------------------------
PROBLEM   The NUMERIC pattern was registered only where
          'numeric_tolerance_ratio' was non-zero. MEASURED: at the
          default 0, '23' was a STRING element, so '1.0' differed from
          '1' and '0.000' from '0.0' -- the ratio decided WHETHER a
          number was one, not how far two may differ. The reading could
          not mark a number either: the element kind the display wears
          IS the lexed kind, and there was none to wear.

          AND: '4.5s' lexed as NUMERIC '4' + STRING '.5s' -- the
          trailing '(?!\w)' made the pattern backtrack into half a
          number.

DECISION  NUMBERS ARE ALWAYS LEXED. The ratio is the band and nothing
          else: 0 means 'equal VALUES' -- '1.0' is '1', '1e3' is '1000',
          '007' is '7' -- and a number against a word is a type
          difference.

          THE NUMBER IS ATOMIC: taken whole or not at all. Glued to a
          word it is text, as 'x86' always was.

          The default ratio stays 0. Whether it should be 0.01 is a
          separate question, not ruled here.

COST      MEASURED on the whole tree: sixteen recorded pages moved --
          three readings gained '{...}', 'test-ui structure' reads
          '(NUM)' for '(STR)', 'test-association-cost' counts other
          search nodes (the knee stays between lines 30 and 32), three
          'test-pattern_finder' pages print the pattern, and six
          'test-main' pages gained the '<hwut-end>' that suite never
          printed (R-70), as 'test-pattern_finder' did. 'test-main
          numbers' pins the verdicts.

GRAVEYARD 'None' for 'not a number', 0 for 'exact' -- rejected: there is
          no case where a number should be read as text. A reading-only
          re-lex for colour -- rejected: the colour would say 'number'
          where compare reads text.
