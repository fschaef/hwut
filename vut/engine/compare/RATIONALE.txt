
C-1   THE CONTRACT -- A SHARED NAME BELONGS WHERE ALL ITS READERS
      SIT ABOVE IT

PROBLEM   'engine/compare' held seven MUTUAL import pairs among five
          sub-components and four of the tree's ten module-level
          cycles -- the one place in the tree with no readable
          direction. Measured ('adm/import_graph.py --shared'), four
          of those pairs rested on a SINGLE NAME travelling backwards
          against three to eight going forwards.

DECISION  'engine/compare/contract' holds the vocabulary in which the
          parties of a comparison name the same things: 'E_Verdict',
          'E_Chunk', 'E_ToleranceId', 'E_EditId' and the semantics
          that give them meaning; 'AnalogyDb' and 'FrozenAnalogyDb',
          the shapes an analogy is carried in.

          IT IMPORTS NOTHING OF THIS TREE, and that is the property
          which MAKES it a contract: every party sits above it, so no
          party can be made to wait on another.

          WHAT BELONGS: SHAPES. An enum has no behaviour at all and
          exists precisely so two parties may say the same word; a
          request shape is what one party asks of another; an error
          kind is part of an interface.
          WHAT DOES NOT: anything whose move would move BEHAVIOUR.
          THE TEST -- would moving it require moving behaviour? 'Line'
          has twenty methods and imports 'core'; 'PatternFinder'
          computes; 'Store' holds state. Those are shared because a
          REAL DEPENDENCY exists, and the layering must express it,
          never hide it behind a shared package.

COST      Thirty-six modules re-pointed. The door re-exports and says
          so with '__all__' -- a re-export is not an unused import,
          and saying so to the reader matters more than saying it to
          the tool.

VERIFIED  'reading -> engine' fell from 8 names to 1; 'region ->
          engine' from 6 to 1. Every shared name of 'compare' now
          reads 'from contract' except the three that carry
          behaviour. 301 declared choices unmoved.

WHAT IT DID NOT DO, and this is the honest half: THE SEVEN MUTUAL
          PAIRS STAND, and the module-cycle count is still ten -- the
          'enums <-> semantics' pair simply moved INTO the contract
          with them. What holds the remaining pairs shut is exactly
          the three names the test above forbids moving. A contract
          removes the cycles that a MISPLACED SHAPE caused; it cannot
          remove the ones a real mutual dependency causes, and
          'reading <-> region' looks like one: a reading contains
          regions, a region is made of readings.

          THAT REMAINDER IS NOW A QUESTION FOR ARCHITECTURE, not for
          a tool: state the mutual recursion as a design, or break it
          by moving behaviour. This entry does neither.

GRAVEYARD MOVING 'Line' AND 'PatternFinder' TOO -- rejected: both
          carry behaviour, and a 'contract' holding machinery is a
          package named for a property it does not have.

C-2   THE SEAL -- 'NOTHING LEAVES' IS CHECKABLE, AND SO IT IS CHECKED

PROBLEM   C-1 stated that a contract imports nothing of this tree, and
          nothing could test it: 'adm/LAYERING.txt' is written at
          depth 2, where the whole of 'engine/compare' is one
          component and everything inside it is invisible. A law
          nobody can check is a law that decays.

DECISION  'SEALED <glob>' in the declaration, JUDGED AT MODULE DEPTH.
          A direction is about a PAIR and needs both named; a seal is
          about ONE COMPONENT and needs no depth at all, so it holds
          at whatever depth the rest is read with.

          VERIFIED BY BREAKING IT: one import added to
          'contract/enums.py' reaching for 'region/registry.py', and
          the check at DEPTH 2 -- where it cannot see inside 'compare'
          at all -- names the module and its target and answers 1.

COST      A second line shape in the declaration, and a second kind of
          reading. The refusal message names both, so a malformed line
          says which shapes exist.

C-3   THE ORIGIN OF A LIFT DOES NOT STAY BEHIND            (2026-09-01)

PROBLEM   C-1 lifted the four shared names -- 'enums', 'semantics',
          'analogy_db', 'frozen_analogy_db' -- into 'contract/'. The
          copies in 'engine/' were never removed. Nothing imported
          them (the two that imported at all imported each other),
          so 'import_graph.py' could not see them: a reachability
          tool is blind to what nothing reaches. They had drifted:
          'engine/enums.py' lacked 'RegionSyntaxError'. Fourteen
          docstrings and documents still pointed at 'engine/...' as
          the single source, naming a file that was the stale one.
          Found by clone detection (PMD CPD, identifiers ignored),
          which sees what the import graph cannot.

DECISION  The four files in 'engine/' are deleted. Every pointer
          'engine/<name>.py' in code comments, README, ARCHITECTURE,
          SEMANTICS and IMPLEMENTATION-happy-constraints now reads
          'contract/<name>.py'. The DOC history files are left as
          they were: they record what was, not what is.

COST      None in behaviour: the compare tree answers 119 ok, 6 fail
          before and after, the same six (region framing, memory
          cap -- both open elsewhere). 'import_graph.py --check'
          answers the same twelve findings before and after.

GRAVEYARD Re-exporting from 'engine/' for compatibility -- rejected:
          there was nobody to be compatible with.

C-4   REGION FRAMING IS SWITCHABLE, LIKE EVERY OTHER FEATURE (2026-09-02)

PROBLEM   '##! <handler>' and '####' were read in EVERY text, always.
          Every other lexical feature has a flag -- 'analogy_f',
          'ignored_line_f', 'whitespace_f', 'backslash_f' -- and this
          one had none. A text that TALKS ABOUT framing therefore
          could not be read at all: this tree's own
          'test-equivalence-vs-association.py' prints a side-by-side
          table whose CELLS hold '##! potpourri', and the reader saw
          a shebang with a parameter '|'. Four choices of the compare
          suite failed on it, carried as open; 'hwut.play' on any of
          them ended in a traceback.

DECISION  'ConfigurationPatternFinder.regions_f: bool = True'. False:
          the markers are NO LONGER REGIONS -- they fall to the
          ordinary rules, where '##! ...' meets the ignored-line
          marker '##' and reads as a comment; with comments off too,
          as content. Switching regions off REMOVES A CLASS; it
          invents none.

          THE NAME, in two turns: 'region_f' was refused as too weak,
          'regions_enabled' proposed and built, then ruled back to
          'regions_f' -- the plural says what is switched and the
          '_f' keeps the habit of its five neighbours
          ('analogy_f', 'ignored_line_f', 'whitespace_f',
          'backslash_f', 'strip_whitespace_f'). One suffix for one
          kind of member is worth more than one member's clarity.

          JUDGED IN ONE PLACE: 'reading/line_scanner.classify()', the
          one function where a line becomes a class. Nothing
          downstream can see a region the reader was told not to
          read, so no second gate exists to disagree with the first.

          THE HWUT WORD IS 'tolerance.regions', beside
          'tolerance.whitespace' and 'tolerance.slash', stated per
          choice or per application:

              # @hwut { title = "..."  tolerance { regions = false } }

          Related in 'relation.py' to 'regions_f', so
          'hwut.show' prints its default like every other parameter
          and 'test-defaults.py' checks it.

COST      One member in compare's declaration, its mirror in
          'owner_faces_provisional.ConfigCompare', one leaf on
          'Tolerance', one line in the validator's vocabulary, one
          in the adapter's mapping. The hwut word is 'tolerance.
          regions' -- the word drops the suffix, as
          'tolerance.whitespace' does for 'whitespace_f'. Two tests of this tree state
          'regions = false' and stop failing:
          'test-equivalence-vs-association.py' (3 choices) and
          'reading/test-chunk_pipe.py' (1). Compare: 119 ok / 6 fail
          -> 123 ok / 2 fail, the two remaining being the memory-cap
          kills (disc-6 r-3), untouched.

GRAVEYARD Escaping the marker in the text -- rejected: the text is
          the subject, and a framework that requires the author to
          alter their program's output to be testable has failed at
          the one thing it is for.
          Auto-detection ("this looks like content") -- rejected: a
          reader that guesses would silently reinterpret a region
          somebody meant, which is the very thing 'RegionSyntaxError'
          exists to make loud.

C-5   THE ONE FAULT A CALLER MUST CATCH, CAUGHT ON EVERY ROAD (2026-09-02)

PROBLEM   'RegionSyntaxError' stands in the contract BECAUSE THE
          CALLER CATCHES IT -- its own docstring says so, and
          'consume/equivalence_check.py' states the law with the
          reason: "a broken region framing is a VERDICT WITH A
          REASON, not an exception". Of the three roads into
          compare's door, only that one obeyed. 'consume/
          difference_display.py' and 'services/compare.reading_view'
          let it through, so 'hwut.play' and 'hwut.compare' answered
          a text they could not read with a Python traceback -- which
          tells the person the framework broke when it was their text
          that could not be read.

DECISION  Each ROAD catches once, in the operation that owns it, and
          says it in that road's own vocabulary:
              VERDICT   consume/equivalence_check   (unchanged)
              DISPLAY   consume/difference_display  -> the report
                        'region-syntax-error', diagnosed by name
              READING   services/compare.reading_view -> a REFUSED
                        line naming the line, and a FAULT exit; the
                        one place for both faces that show a reading
                        ('hwut.compare' and 'hwut.play')
          Not four faces each rolling their own: three roads, three
          catches.

COST      'reading_view' answers a bool where it answered None, and
          takes a 'write'. Both its callers read it: play and compare
          return FAULT where the reading could not be shown, rather
          than OK with a refusal printed in the middle.

C-6   A STRESS TEST SAYS WHAT IT COSTS                          (2026-09-02)

PROBLEM   'solver/TEST/test-csp_backtracking_mrv.py' was killed on two
          of its four choices -- 'massive-pipe' and 'soduko' -- for
          exceeding the 512 MB default memory cap. The two build the
          whole pairing space in memory; that is what they are for.
          Open since disc-6 r-3.

DECISION  The application states 'caps { memory_mb = 2048 }'. Raised,
          not removed: a cap nobody can exceed catches nothing, and
          2048 still catches a regression that doubles the space
          again. Measured UNCONSTRAINED, the two need 1069 MB.

FOUND     THE KILL MESSAGE'S 'peak' IS NOT THE REQUIREMENT. It is
          where the process stood when it was killed, so it tracks
          the cap: 518 MB reported at cap 512, 1048 MB at cap 1024,
          for the same run. Two caps were set on that reading before
          the pattern was visible. Only an unconstrained measurement
          answers "how much does it need"; the message is worth a
          word saying so, and 'procsitter' is the place for it.

COST      compare answers 131 ok / 0 fail, where it answered 129 / 2.
