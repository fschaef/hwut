VUT-SANDBOX: SPECIFICATION (2.0)
============================================================================

Status:   implemented (component-sandbox.txt); spec kept in sync
Decided:  2026-07-19 (discussion Frank-Rene / Claude); reframed
          2026-07-20: (a) the sandbox is THE SUPERVISED SYSTEM CALL,
          not a testing-only facility; (b) running and judging are
          strictly separated; (c) generalized to the SANDBOX SEQUENCE:
          pipe-construction is THE interface between sandboxes and
          toward compare; one attribution record per stage; pype is a
          DETERMINISTICALIZATION stage, not a filter; (d) THE RUN
          SPECIFICATION: subjects (channel LIVE, files POST-EXIT)
          mapped to comparators, one verdict per subject; (e) stderr
          tail captured; the judging layer decodes the tail itself
          (text face); (f) E_TestRunResult -- THE BRIEF REPORT: 'ok'
          or one reason token per run (vut.auxiliary).


----------------------------------------------------------------------------
1  PURPOSE
----------------------------------------------------------------------------

THE SUPERVISED SYSTEM CALL: HWUT's replacement for 'subprocess'. EVERY
subprocess goes through the sandbox -- test applications, build and
helper tools ('make', 'scp', maintenance scripts), pype stages. The
call is CONTAINED against unintentional misbehavior and ATTRIBUTED: a
violation is reported as the failure of the call that caused it, with
the exhausted resource named.

Testing is ONE application of the primitive -- the special one whose
output is connected to the comparison engine. The layering is strict
and lightweight:

    APPLICATIONS     plain calls            the judged test app run:
                     (make, scp, ...)       a sequence whose subjects
                          |                 (channel, files) are judged
                          |                 per specification on two
                          |                 axes -- equivalence,
                          |                 association
    COMPOSITION           |                 SandboxSequence: supervised
                          |                 calls chained stdout->stdin;
                          |                 SandboxPipe -- THE interface
                          |                 between sandboxes AND toward
                          |                 compare
                    +-----+---------------------------+
    THE GROUND      |  Sandbox.run()                  |
                    |  containment + attribution      |
                    +---------------------------------+

The called process is written or invoked by a trusted colleague; its
intent is never in question -- its correctness is. The sandbox
protects the RUN from the process's BUGS: disk flooding, fork bombs,
runaway memory growth, endless loops, hangs.

THE SANDBOX IS PLATFORM-INDEPENDENT, PERIOD. One implementation,
stdlib + psutil, no wrapper binaries, no per-OS backends.


----------------------------------------------------------------------------
2  IN SCOPE / OUT OF SCOPE
----------------------------------------------------------------------------

IN SCOPE -- the sandbox does three things, for EVERY call:

1  RESOURCE CONTAINMENT
   Per-call caps on wall-clock time, CPU time, memory, process count,
   and created-file size. A runaway call dies alone; the session
   survives; the report names the call and the exhausted resource.

2  PROCESS HYGIENE
   Each call runs in a work directory in its own process group. On
   termination -- natural, contained, or stopped -- the whole group is
   reaped: no leftover processes, ever. Stragglers that outlive the
   main process are reaped by the watchdog; no call's leftovers can
   stall a pipeline.

3  DECLARED NEEDS (metadata only)
   A call that needs more than the default DECLARES it (for tests: in
   the test specification, beside the CHOICES): network use, bound
   ports, writable paths beyond the scratch dir, raised caps. The
   sandbox RECORDS and REPORTS these; it does not enforce them. They
   are reviewable and available to whoever orchestrates runs
   (scheduling, partitioning, honest skips). The vocabulary is SMALL
   and ENUMERATED; it never grows into a policy language.

OUT OF SCOPE -- resolved independently, above this level:

  SECURITY.        Callers and authors are trusted; malice is not
                   defended against. No forbidden-binary lists, no
                   syscall filters, no whitelists.
  ISOLATION.       Namespaces, read-only roots, private network
                   stacks, containers -- the security administrator /
                   orchestrator chooses and operates the outer
                   boundary (container, VM, dedicated runner) entirely
                   independently of this level.
  REPRODUCIBILITY. Pinning the execution environment belongs to the
                   outer boundary likewise.

Honest reporting rule: a cap the sandbox cannot enforce on the running
platform (e.g. no psutil -> no RSS cap) is REPORTED in the result
(.unenforced), never silently ignored.


----------------------------------------------------------------------------
3  TOOLING
----------------------------------------------------------------------------

Dependencies:

  stdlib    asyncio, resource (where available), os, shlex, signal,
            tempfile
  psutil    THE one third-party dependency: RSS polling and process-
            group enumeration, identical API on Linux/macOS/BSD/
            Windows. Degradable: without psutil, no RSS/pid-count caps
            (reported in .unenforced); wall-clock and rlimits still
            work.

Mechanisms:

  - preexec hook (POSIX): own process group (setsid via
    start_new_session) + resource.setrlimit for RLIMIT_CPU,
    RLIMIT_FSIZE, RLIMIT_NPROC (NPROC set relative to the current
    per-UID count). On platforms without 'resource' (Windows):
    watchdog only, reported.
  - watchdog task: async task beside the stream pumps; period 0.25 s;
    sums RSS and counts members over the process group; enforces
    max_wall_clock_sec, max_memory_mb, max_pids; records peaks for
    attribution; reaps stragglers that outlive the main process
    beyond 1 s.
  - kill ladder: killpg(SIGTERM) -> grace (2 s) -> killpg(SIGKILL) ->
    post-mortem sweep of observed descendants (pid + create-time
    guarded against pid reuse).
  - RLIMIT_AS is NOT used (breaks interpreters that reserve large
    address spaces); memory containment is watchdog-based (RSS).
    Adequate against accidents; adversaries are out of scope.
  - Wall-clock is the primary hang-catcher: a process blocked on a
    dead socket burns no CPU time; RLIMIT_CPU never fires on it.
  - CPython ignores SIGXFSZ: at the file-size cap it gets EFBIG and
    fails by its own exception (COMPLETED, nonzero) instead of
    FILE_SIZE_EXCEEDED. The cap holds either way; assertions must
    accept the normalized outcome. Same for NPROC-vs-watchdog races
    on fork bombs.


----------------------------------------------------------------------------
4  API
----------------------------------------------------------------------------

Design decisions:

  - CONFIG CLASS: yes. SandboxConfig is the DECLARATION RECORD -- the
    per-call contract. Two labeled halves: caps (enforced) and
    declared needs (metadata).
  - ONE CONCRETE CLASS, NO HIERARCHY. No platform variance, no
    isolation backend, no factory.
  - CONSUMERS BY COMPOSITION, NOT DERIVATION. The sandbox hands
    output chunks to handlers; sequences and judging are wiring ABOVE
    the ground.
  - RUNNING AND JUDGING STRICTLY SEPARATED: the SandboxSequence
    produces the subject stream; the judge_* functions consume it.
  - PIPE-CONSTRUCTION IS THE INTERFACE, in both directions: between
    sandboxes SandboxPipe links the stages (BYTES); toward compare
    the judge_* functions read the tail through their own TEXT face
    ('_TextLineReader': decoded lines, unbounded line buffer) -- the
    judging layer assumes NOTHING about compare's byte handling.
  - ONE ATTRIBUTION RECORD PER STAGE, ONE VERDICT PER SUBJECT, ONE
    BRIEF REPORT PER RUN -- nothing disappears; mismatches and
    contained stages are NAMED; the headline is one token.

THE GROUND (sandbox.py):

  E_Network:     NONE | LOOPBACK (default) | HOST      -- metadata
  E_Containment: COMPLETED, WALL_CLOCK_EXCEEDED, CPU_TIME_EXCEEDED,
                 MEMORY_EXCEEDED, FILE_SIZE_EXCEEDED, PIDS_EXCEEDED,
                 STOPPED, LAUNCH_FAILED

  @dataclass SandboxConfig:
      # CAPS -- enforced:
      max_wall_clock_sec: float = 60.0
      max_cpu_time_sec:   int   = 60
      max_memory_mb:      int   = 512     # watchdog RSS, process group
      max_pids:           int   = 32
      max_file_size_mb:   int   = 10
      # DECLARED NEEDS -- metadata (orchestrator's interface):
      network:     E_Network      = E_Network.LOOPBACK
      ports:       tuple[int,...] = ()
      extra_write: tuple[str,...] = ()

  @dataclass SandboxResult:                  # THE ATTRIBUTION RECORD
      containment:    E_Containment
      exit_code:      int | None             # None unless COMPLETED
      wall_clock_sec: float
      cpu_time_sec:   float | None
      peak_memory_mb: float | None
      unenforced:     tuple[str, ...]        # honest reporting
      stderr_tail:    str                    # last 4 KiB of stderr,
                                             # captured when no
                                             # stderr_handler given:
                                             # the WHY beside a nonzero
                                             # exit
      .ok             property: COMPLETED and exit_code == 0

  class Sandbox:
      __init__(config, work_dir)
      async run(command_line,
                stdout_handler=None, stderr_handler=None,
                stdin_reader=None, stop_event=None,
                backup_file_set=None) -> SandboxResult
          -- Misbehavior of the called process never raises; it is a
             RESULT. run() raises only on harness faults.
          -- stdout without a handler is drained; stderr without a
             handler is CAPTURED (tail) into the result.
          -- backups: '<name>-<n>.BACKUP', counter, deterministic.

COMPOSITION (sandbox.py):

  class SandboxPipe:
      .feed / .reader / .close()
      -- stdout -> stdin link between two supervised calls.

  class SandboxSequence:
      __init__(stage_list, stop_event=None)
          -- stage_list: [(Sandbox, command_line), ...]; construction
             LAUNCHES; consecutive stages linked by SandboxPipe.
      .tail          SandboxPipe: the chain's stdout end
      .sandbox_list  the stages' sandboxes (stage 0 = the test app;
                     its work_dir anchors relative file subjects)
      .stop_event    stops every stage at once
      .running() / .collect() -> tuple[SandboxResult, ...] per stage
      -- rules: EOF propagates downstream stage by stage; a stage that
         ends while an UPSTREAM stage still runs stops the whole
         sequence (SIGPIPE semantics, supervised); every stage has its
         own sandbox -- own caps, own attribution.

THE BRIEF REPORT (vut/auxiliary/test_run_result.py):

  E_TestRunResult -- 'str(result)' prints the token; meant to GROW
  (e.g. 'make' helper-call outcomes later):
      OK                            "ok"
      NOT_EQUIVALENT_WITH_NOMINAL   "not-equivalent-with-nominal"
      TEST_APP_LAUNCH_FAILED        "test-app-launch-failed"
      TEST_APP_CONTAINED            "test-app-contained"
      TEST_APP_NO_OUTPUT            "test-app-no-output"
      OUTPUT_FILE_NOT_FOUND         "output-file-not-found"
      NOMINAL_FILE_NOT_FOUND        "nominal-file-not-found"
      PYPE_INTERPRETER_NOT_FOUND    "pype-interpreter-not-found"
      PYPE_FILE_NOT_FOUND           "pype-file-not-found"
      PYPE_FILE_SYNTAX_ERROR        "pype-file-syntax-error"
      PYPE_CONTAINED                "pype-contained"
      PYPE_FAILED                   "pype-failed"
  Classification: test-app reasons outrank pype reasons outrank
  subject/nominal reasons; pype classification of nonzero exits rests
  on the CAPTURED STDERR TAIL ("can't open file" = interpreter
  missing; 'pype:'-prefixed = script problem: Errno-2/"cannot find
  import" = not found, else syntax/script error).
  'test-app-no-output': channel judged False with ZERO subject bytes.

THE JUDGED TEST APP RUN (run_test_app.py) -- judging only; the run is
an ordinary SandboxSequence. The pype triad, one concern per stage:
the test app PROVOKES and REPORTS; pype ANALYZES -- NOT a filter, it
DETERMINISTICALIZES non-deterministic output; compare JUDGES.

  Channel primitives (single subject = the sequence tail):

  async judge_equivalence(sequence, nominal_provider, compare_config)
      -> (tuple[SandboxResult, ...], bool)
      -- 'is_equivalent', THE JUDGE: quick correctness, fast-fail
         both ways over the sequence's stop_event.
      -- THE VERDICT RULE: every stage COMPLETED (or STOPPED by the
         fast-fail), else False; the report names the stage.
  async judge_association(sequence, nominal_provider, compare_config,
                          consumer) -> tuple[SandboxResult, ...]
      -- 'associate', THE LAWYER: alignment ChunkPairs to 'consumer';
         no fast-fail. THE LAW: reduction equals the Judge's verdict.
  async judge_output_file(file_path, nominal_provider,
                          compare_config) -> bool

  THE RUN SPECIFICATION (channel vs. comparator):

      subject     judged     deterministicalization (pype)
      ----------  ---------  -----------------------------------
      channel     LIVE       a pype STAGE of the running sequence
                             (fast-fail applies)
      file        POST-EXIT  applied post-exit by the comparator:
                             a file may change at ANY moment while
                             the test lives

  @dataclass Comparator:
      nominal                 '.readline()' provider or path
      compare_config
      pype_sandbox      = None   # FILE subjects only: post-exit
      pype_command_line = None   # deterministicalization

  @dataclass TestRunSpec:
      channel: Comparator|None   # None: stdout drained, unjudged
      file_db: dict              # file name -> Comparator

  @dataclass TestRunJudgement:  # THE COMPLETE ACCOUNT
      stage_result_list         # live stages, pipeline order
      subject_verdict_db        # "stdout"/file name -> bool: NAMED
      file_stage_db             # file -> post-exit pype records
      result                    # E_TestRunResult: THE BRIEF REPORT
      .verdict                  # every subject equivalent AND every
                                # stage (live + post-exit) accounted

  async judge_test_run(sequence, spec) -> TestRunJudgement
      -- order mandatory: channel LIVE first, files only AFTER the
         run terminated; files judged even when the channel already
         failed (complete account). Post-exit file
         deterministicalization: a ONE-STAGE SandboxSequence, pype
         reading the file as its INPUT-FILE argument.
  async associate_test_run(sequence, spec, consumer)
      -> TestRunJudgement
      -- THE LAWYER over the whole spec: consumer(subject_name,
         chunk_pair); verdicts by THE LAW's reduction; same brief
         report classification (minus no-output detection).


----------------------------------------------------------------------------
5  HARNESS OBLIGATIONS (above the sandbox)
----------------------------------------------------------------------------

  - Route EVERY subprocess through the sandbox; never 'subprocess'
    directly. 'make' and 'scp' deserve wall clocks too.
  - Reporting: the BRIEF REPORT token first; then every stage's
    containment, .unenforced and (on failure) .stderr_tail, and every
    subject's verdict; peaks on failure for attribution.
  - Declarations live per test in the test specification
    (hwut-info.dat / --hwut-info, beside CHOICES), never in global
    config.
  - The pype interpreter location: <project root>/tools/hwut_pype/
    hwut_pype.py by convention; overridable per environment via
    VUT_HWUT_PYPE (the TEST suite resolves it this way and reports
    absence actionably).

8  RESOLVED / OPEN QUESTIONS
----------------------------------------------------------------------------

  RESOLVED: per-stage attribution; channel vs. comparator (files
  POST-EXIT only); stderr tail (decided by a real incident: pype exit
  2 with drained stderr left no WHY); byte/text boundary (the judging
  layer decodes; compare's AsyncIterator_ensured does not); brief
  report (E_TestRunResult in vut.auxiliary, expandable toward 'make'
  outcomes).

    hwut-info.dat?

    stage (e.g. feeding recorded input through a pipeline)?
