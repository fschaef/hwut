DISCUSSIONS -- luau/ support modules
=====================================

-------------------------------------------------------------------------------
D-1.  Wrapper-as-oracle (luau_fragment.py)
-------------------------------------------------------------------------------
Mechanism: candidate span wrapped in a role-specific frame before parse.
  CONDITION/EXPRESSION: 'local __guard__ = ( <inner> )'
  STATEMENT_BLOCK:      'function __frag__()\n<inner>\nend'
Effect: a premature '}' cut leaves an unterminated '(' or 'function...end';
  parse fails. Only the true closer produces a complete construct.
Cost: one 'luau-ast' subprocess call per candidate '}' scanned.
Mitigation: typical fragments have zero interior braces; cost = one call.
Invariant: wrapper name '__guard__'/'__frag__' must not collide with user code.

-------------------------------------------------------------------------------
D-2.  Temp-file I/O (LuauOracle)
-------------------------------------------------------------------------------
Constraint: 'luau-ast' accepts only a file path; no stdin, no flags.
Cost: mkstemp + unlink on every 'parse()' call.
Mitigation: call count bounded by the count of '}' chars in the span.
Failure detection: non-empty stderr => parse error; empty stderr => ok.
  (zero exit code alone is insufficient; luau-ast exits 0 even on some errors)

-------------------------------------------------------------------------------
D-3.  Gap -> None (Source2TargetLocationMapper)
-------------------------------------------------------------------------------
Policy: target lines not covered by any registered interval resolve to None.
Cost: caller must account for every emitted line via advance() or
  register_fragment(). A forgotten advance() silently widens a gap and shifts
  all subsequent fragment intervals.
Invariant: sum of all advance() counts + sum of all register_fragment()
  lengths == total lines in the emitted file.

-------------------------------------------------------------------------------
D-4.  Two-delta column model (Source2TargetLocationMapper)
-------------------------------------------------------------------------------
Fragments may be spliced mid-line (e.g. 'if <fragment> then').
First line: source_col = target_col - indent - first_line_prefix.
Other lines: source_col = target_col - indent.
Cost: caller must supply first_line_prefix at registration time. If the
  emitted prefix changes after registration, the column mapping is void.
Clamp: source_col < 0 is clamped to 0 (analyzer points into the prefix).

-------------------------------------------------------------------------------
D-5.  Verbatim-copy invariant (Source2TargetLocationMapper)
-------------------------------------------------------------------------------
The linear map source_line = target_line - target_base + source_base holds
only when the fragment is copied verbatim and contiguously: same line count,
same line order, no injected blank lines.
Not asserted by the mapper. Caller's contract.
Violation: silent wrong-line attribution with no error.

-------------------------------------------------------------------------------
D-6.  Strict-mode directive placement (GeneratedCodeChecker)
-------------------------------------------------------------------------------
'--!strict' must be part of the emitted text (registered via advance(1)), not
injected by the checker. Injection would shift all target lines by the count
of injected lines, breaking trace-back silently.

-------------------------------------------------------------------------------
D-7.  LocalUnused in gaps
-------------------------------------------------------------------------------
A 'LocalUnused' diagnostic landing on a gap line (is_in_generated_code=True)
indicates the transpiler emits a local variable it never reads. This is a
transpiler emission quality issue. The correct fix is in the emitter, not via
global suppression of LocalUnused, which would also silence author warnings.

-------------------------------------------------------------------------------
D-9.  Reactor containers + slot protocol (bootstrap.lua 3e)
-------------------------------------------------------------------------------
Mechanism: a spawned aggregate is offered to a CONTAINER, admitted under a
three-call slot protocol -- slot_reserve() -> int key | NO_SLOT(0);
slot_set(key, instance); slot_free(key).
Why a key, not a bool 'can_add': the returned key IS the reservation, so the
check and the hold are one atomic act -- closes the time-of-check/time-of-use
gap a bool query would leave open between "may add" and "added".
Mutex scope: the RESERVE alone is the critical section. construct() runs after
a successful reserve and OUTSIDE the lock, so a possibly-blocking construct
(sprite, socket) does not serialize all spawns. The slot is marked taken at
reserve and committed at slot_set.
slot_free idempotent: free on an unknown/already-freed key is a no-op, so
ending an existence is safe to call once even after a host already released.
Two base classes, differing only in slot_reserve:
  ScalarReactorContainer  0..1; reserve fails when occupied.
  MultiReactorContainer   0..N; reserve mints a fresh key unless an admit
                          predicate rejects. The DEFAULT per-kind container is
                          a Multi whose admit rejects a parameterisation
                          already present (identity = parameters, R-29).
Static/runtime line: the protocol is a RUNTIME contract honoured in Luau; the
rule-file parser and the semantic layer never see the container -- 'in {lvalue}'
is opaque Luau. Container-ness is a run-time fact. (Design rationale: top-level
R-39; semantic L-11/L-12 for the static unspawn check that pairs with this.)
Cost: a custom container author must implement all three calls correctly; a
half-implemented container fails at run time, not at transpile time.
Mitigation: the two base classes cover scalar and multi; a custom container is
the exception, and the contract is three short methods.

-------------------------------------------------------------------------------
D-8.  Graveyard
-------------------------------------------------------------------------------
luau-ast --json: binary version available here has no flags; rejected.
luau-ast stdin ('-'): binary does not support; rejected.
Hand-written Luau lexer (aux.lua / R-27 design): superseded by
  wrapper-as-oracle; the wrapper makes the lexer unnecessary.
Per-fragment luau-analyze with generated type preamble: requires a
  type-preamble generation step not yet built; deferred.
Mock oracle in tests: removed once GOOD files promoted from real binary runs.

-------------------------------------------------------------------------------
D-10. Reference collection (collect_references) and the pseudo-symbol planes
-------------------------------------------------------------------------------
Implements core D-1 (semantic ledger): LuauOracle.collect_references wraps the
measured span in the SAME role frame find_close used, parses through the new
parse_ast JSON seam (one _run helper backs parse and parse_ast), and walks the
luau-ast JSON for GLOBAL-rooted dotted chains, mapped back to source offsets
as neutral core Reference pairs. Explicit-stack walk; a computed index breaks
a chain at its resolvable head; locals never surface (Luau resolves them at
parse time -- globals ARE the references to the world outside the span).

THE VALIDATION WRAPPER DELIBERATELY BINDS NOTHING. If the frame declared
'local e, sm, mg, m', the pseudo-symbols would parse as AstExprLocal and
vanish from the reference set -- exactly the names pass 2 must see. So:

    validation/collection frame:  pseudo-symbols stay GLOBAL  (this module)
    GENERATED guard frame:        binds 'e'/'sm'/'mg'/'m' as locals at run
                                  time -- one spelling on both planes; an
                                  EMITTER OBLIGATION, owed by the code-
                                  generation session (no emitter exists yet).

Schema note: the JSON walk targets luau-ast's encoder (AstExprGlobal /
AstExprIndexName / AstExprIndexExpr, 'l,c - l,c' locations, 0-based). The
fake-backed choices pin the walk and the offset arithmetic; the 'real_binary'
choice of test-collect-references.py pins schema fidelity and is promoted only
on infrastructure carrying the binary (it prints a loud SKIP elsewhere).
