GRAVEYARD -- discussions and settled ideas from the FIRST semantic unit
========================================================================
The semantic unit is being TRASHED and rebuilt from a now-clear design. This file
preserves WHAT WE LEARNED so the rewrite starts from settled ideas, not a blank
page. Nothing here is binding on the new unit; it is the distilled thinking, for
the human to lift what still holds and discard what does not.

The root cause of the trash-and-restart (stated plainly, for the next time): the
design was steered LIVE, mid-implementation, over many turns, until the human
lost track of what was being built. The lesson encoded for the rewrite: SETTLE
THE WHOLE UNIT'S DESIGN FIRST, on paper, before any code. The ideas below are the
raw material for that settling.


THE IDEAS THAT SURVIVE (the clear model, late-arrived)
------------------------------------------------------
1. A MODULE IS TWO THINGS + A DECORATION.
     ast                 the parser's frozen tree -- a PURE value, NEVER mutated
     symbol_table        declared names + scopes
     ast_decoration_db   id(node) -> resolved Symbol, a SEPARATE id()-keyed unit
   The AST is never decorated in place. The decoration is a side table bound to
   one AST instance (id() keys; valid only while that AST is alive). One-way
   dependency: semantic -> ast; the parser knows nothing of resolution.
   (was RATIONALE D-33)

2. ONE UNIFORM RESOLUTION RULE, EVERYWHERE.
   Head resolves innermost-out through open enclosers; the dotted tail
   (name0, name1, ...) descends into subspaces by sequence. A name that does not
   resolve this way is [NAME] -- full stop. No special axis for any site.
   (was D-34)

3. AGGREGATE MEMBERS ARE ENCAPSULATED; the GLOBAL SCOPE IS ITSELF AN AGGREGATE.
   A mode/state is a member of its aggregate (mode_group / state_machine),
   addressable ONLY from within that aggregate's body. From outside, the sole
   interface is EVENTS. The global scope is a mode_group (for its modes) AND a
   state_machine (for its states) at once -- so a global mode arms from global
   scope by the SAME rule, no exception. Global vs grouped is one rule over
   different enclosing aggregates, not two rules. (was D-34; proven by the
   reference-report net: global mode arms, grouped-from-outside is [NAME].)

4. DIAGNOSTICS ARE RAW AND MINIMAL; ENRICHMENT IS A SEPARATE SHELL.
   The resolver emits 'resolved' or '[NAME] at offset' -- nothing more. Existence
   hints across namespaces, Levenshtein 'did you mean', user formatting: all
   DOWNSTREAM, in a separate shell consuming raw diagnostics. Keep the core free
   of UX. (was D-35)

5. RESOLUTION AS A JOIN OVER THREE TABLES, FROM ONE DESCENT.
   SCOPE (scope_id, kind, parent), SYMBOL (name, kind, scope_id), REFERENCE
   (node_id, segments, offset, enclosing_scope). The descent that builds scopes
   and records declarations ALSO emits REFERENCE rows -- WITH enclosing scope in
   hand for free. Resolution = a join per REFERENCE row against its enclosing
   scope (+ proxies). NO second walk of the AST. 'Walking the tree twice' is the
   alarm bell for a relational structure that should be one table-fill + join.
   (was D-32)

6. THE GENERAL / APPLICATION SEAM: TABLES DECLARED IN CORE, FILLED BY THE APP.
   core/ owns the table TYPES (Scope, Symbol, Reference) and the JOIN; it names
   no rule kind. The rule-flavoured facts the join needs (which kinds open a
   scope, which heads are pseudo) arrive as an injected ResolutionPolicy. The
   application walks its OWN ast to emit rows (the ETL) and owns the (A)/(B)
   regime decision. core = schema + query engine; app = the loader. (was D-32)
   CAVEAT THAT WAS NEVER CLEANED: E_ScopeKind in core still hardcoded rule kinds
   (NAMESPACE/MODE_GROUP/STATE_MACHINE) -- the seam was clean in the join but not
   in the scope-kind enum. (was todo-8) Fix in the rewrite: core holds a general
   scope tag; the app owns the vocabulary.

7. STATIC, TOTAL RESOLUTION; REPLACEMENT IS STOP-THE-WORLD, RE-LINK-ALL.
   Every reference is seated at analysis time or is an error then -- nothing
   deferred. So NO lazy load, NO unload, NO evictable/seat-unseat machinery. The
   only runtime change is whole-module REPLACEMENT: halt, swap, re-link
   everything (a replaced module's export surface can shift arbitrarily, so the
   affected set is everything; the pause pays for one full re-link), resume.
   Plug-in LOAD is reachable from the same op; plug-in UNLOAD is deferred and its
   real cost is runtime-object lifetime, not resolution. (was D-31)

8. IMPORT = A MOUNTED VIEW, NOT A COPY.
   An imported module is analysed once into its own table; an import DERIVES a
   mounted view (the importer prefixes it under a mount path). Binding is a LINK,
   not a copied entry. ModuleProxy = a thin (path, table, mount) addressing view
   with covers()/lookup(); no presence state, no loader (static). Cross-file
   lookup = local scope chain first, then a covering proxy. (was D-31, kept half
   of the old SETTLED 6)

9. NODE FINALIZATION (for the '=>' collapse) IS SHALLOW SUBSTITUTION.
   With '=> arm: Mode' collapsed to '=> Mode' (grammar, see below), the parser
   cannot name the operation -- only pass 2, after resolving the target's kind,
   finalizes a provisional '=> X' into Emit / Arm / etc. This is a SHALLOW,
   interface-preserving node SWAP: the replacement shares the SAME interface and
   GRAFTS the original branches (args, target, guard) unchanged -- subtrees are
   the same objects, never copied or rewalked. The decoration STAYS a table (NOT
   inlined): linking is a table access, and inlining would force a tree walk
   (reviving the deleted second descent) and need mutable value-equal nodes
   (reviving the twin-collapse). RE-KEY RULE: a swapped node has a new id(); the
   substitution must carry the decoration entry old-id -> new-id. (was D-36)


REFERENCE-SITE TAXONOMY (what resolves, and how) -- from disc-5
---------------------------------------------------------------
LEXICAL-SCOPE sites (resolve by rule #2 from enclosing scope), all PROVEN by a
reference-report net (a test that prints every candidate site + its enclosing
scope + its seated symbol, so each admission is a single reviewable flip):
    Trigger, BoolRef, DefaultRef, CauseRef, EffectRef, Spawn, Unspawn, HasRef,
    ModeArming (encapsulation-bounded, idea #3).
A DECLARATION's own name is NOT a reference (do not resolve it).
DEFERRED, a DIFFERENT axis (NOT lexical scope):
    Comparison operands, Arg(NAME) values -- resolve against the firing EVENT's
    MEMBERS (TYPE-descent), not enclosing scope. Handle as their own shape.
    Spawn.into_container / Spawn.key -- extra segment-list fields needing
    per-field extraction (the walk read only 'name').

WHAT IS KEPT OUTSIDE THE SEMANTIC UNIT (do NOT trash)
-----------------------------------------------------
- The PARSER and its grammar, INCLUDING the just-landed '=> arm:' collapse:
  '=> arm: Mode' and the clockwork 'arm:' step are GONE; an arm-target now parses
  as a bare emission/name-step ('=> Mode(args)' / 'Mode(args)'), to be FINALIZED
  to ModeArming in pass 2 by resolved kind (idea #9). ModeArming survives as a
  DORMANT ast node = that finalization target; the parser does not construct it.
  Precondition that made the collapse safe: event vs mode names are disjoint in a
  scope (a duplicate name is already a duplicate-symbol error), so '=> X' is
  unambiguous. Parser suite green at 32/32 after the change.
- disc-7 (the grammar collapse) is now LANDED on the parser side; its STRUCTURAL
  half (idea #9) is settled. The DORMANT ModeArming + pass-2 finalizer are the
  semantic unit's to (re)build.


A PARTING METHOD NOTE FOR THE REWRITE
-------------------------------------
The net (reference-report) was the single most valuable tool: a test that makes
resolution OBSERVABLE (every site, every seat) so each change is one reviewable
diff. Build its equivalent FIRST in the new unit. And settle the whole design on
paper before coding -- that is the lesson the restart is paying for.
