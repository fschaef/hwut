todo-1  FOLLOW-SET VALIDATOR  (engine)
===============================================================================
SCOPE     parser engine. Decided to want it; the validator is unbuilt.

STATE TODAY:
    The engine validates OR-branch disjointness but NOT optional/repetition
    against FOLLOW. An OPT (or repetition) that shares its FIRST set with what
    follows it compiles 'clean' though it is ambiguous. The current grammar
    sidesteps this by left-factoring (e.g. the named-arg form), so no live rule
    is ambiguous -- but nothing in the engine PROVES that.

TO IMPLEMENT:
    A FOLLOW-set computation and a load-time check: for every OPT/STAR/PLUS,
    its FIRST set must be disjoint from the FOLLOW set at that position. A
    violation is a load error, same class as an OR-branch conflict.
