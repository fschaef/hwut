THE RULE (Frank-Rene)
    A grammar rule's reduce action produces EITHER a plain CST node (the
    default, no AST_MAP entry) OR exactly ONE AST node (a factory). It must NOT
    invent a third kind of thing -- a bare tuple, a dict, a {'kind':...}
    discriminated union, or a shaping list -- that exists only for a PARENT
    reduce action to disassemble.

    STRICT reading (chosen): ALL dicts/tuples/lists returned by reduce actions
    go. Even a segment list becomes a node or a typed value carried BY a node.

-------------------------------------------------------------------------------
ADDRESSING MODEL (settled during step-3 design; see RATIONALE 'roles vs positions')
-------------------------------------------------------------------------------
  Position addresses; role classifies; role NEVER addresses.
    - node[i]          positional, the only locator. Captured-terminal drift is
                       cured at source by SILENCING non-value tokens.
    - node[i, "role"]  positional + ROLE ASSERTION: returns children[i], raises
                       AssertionError if slot i did not carry that role. Drift
                       smoke-detector (coarse drift + same-type transposition);
                       not total ('sometimes'); GOOD suite stays the backstop.
                       Recovers D-18's drift-protection WITHOUT conscripting the
                       role axis into uniqueness-bound addresses.
    - node["role"]     role SEARCH, lenient (None on miss). RETAINED ONLY for the
                       forced case: a value-bearing terminal that cannot be
                       silenced because its spelling is shared with a rule that
                       reads its text -- the container-type angle bracket '<'/'>',
                       shared with the comparison operators. DictType/ListType
                       locate key/value/element by role THERE, and only there.
  The elective half of D-18/D-22 (role-as-address as a future-drift hedge) is
  DECLINED: if a discriminant is later prepended, update the index then, in the
  open, rather than carry standing children-list noise to pre-absorb it. Built:
  __getitem__ gains the (int, str) assertion branch; int and str paths byte-
  identical; no call-site conversion (check-and-pass-through, opt-in).

O-2 RESOLUTION (name-dotted: decl vs ref, and the raw list)
-------------------------------------------------------------------------------
FINDING (from disc-3 DONE, disc-4 DONE): the declaration/reference SPLIT is
  already made AT THE CONSUMER and built. Every reference name is a ReferenceLeaf
  (_ref), every declaration a DeclarationLeaf (_decl), wrapped per-factory AFTER
  dispatch -- disc-3 chose explicitly "wrap AFTER dispatch, NOT in _name_dotted".
  CauseDef is the mixed witness: .name=_decl, .for_event=_ref, one rule, two
  bindings -- proving per-ROLE (not per-rule) is the right granularity.

  The GRAMMAR already differentiates decl from ref, cleanly and TOTALLY: of all
  name-dotted role tags, exactly 'name' (signature) and 'namespace' (import/
  namespace mount) are DECLARATIONS; every other tag (operand, event, cause,
  emission, aggregate, instance, container, key, base, member) and the lone
  untagged name-step site are REFERENCES. No site's binding kind is undetermin-
  able at parse time -> NO semantic mutation of a neutral leaf is needed; the
  spawn/mode 'mutate-later' pattern does NOT apply to names. (Were a Case-2 site
  -- binding kind not fixable from any role -- ever to appear, THEN a neutral
  leaf mutated in pass-2 would be the answer. None exists today.)

  A reduce action CANNOT read the role of the slot IT fills: reduces run bottom-
  up (child before parent placement); the role lives on the PARENT's parallel
  roles tuple, assigned after fn(value) returns (ll2_engine ~498). So name-dotted
  cannot self-select its leaf kind. The selection lives -- as built -- in the
  CONSUMER, which can see its own slot's role.

DECISION: keep the consumer as the decl/ref decision point (status quo, disc-3/4
  DONE -- not reopened). The ONLY disc-8 debt at name-dotted is that _name_dotted
  RETURNS A RAW list[str] (the STRICT offender) which each consumer rewraps via
  _ref/_decl.
  Resolve at step 5 by ONE of (decided then, per the head-set carrier of step 5):
    (a) _name_dotted reduces to a binding-NEUTRAL leaf (segments+begin) and the
        consumer NARROWS it -- _ref/_decl read .segments off the neutral leaf
        instead of off a raw list. STRICT-clean (no raw list returned); minimal
        consumer change (one field access); the consumer still owns the decl/ref
        choice, now optionally role-DRIVEN via node[i,"role"] assertion + a fixed
        role->kind table {name,namespace -> DECL; else REF} rather than hardcoded.
    (b) the consuming RULE reduces name-dotted directly to ReferenceLeaf/
        DeclarationLeaf by pushing the leaf kind into that rule's factory; the
        name-dotted sub-rule yields the neutral leaf as in (a). Same neutral-leaf
        producer; differs only in where the narrow is spelled.
  LEAN (a): one neutral producer, consumers narrow; the binding role becomes the
  authority for the kind (table-derived), ending the per-factory hardcoded
  _ref-vs-_decl knowledge. NOT built yet -- step 5 work. todo-2 (dotted-name-
  returns-list) is SUBSUMED here: the list becomes the neutral leaf's .segments
  field, satisfying both disc-8 (no raw list) and todo-2 (segmentation kept).

O-4 (governs B): RESOLVED consistent with O-2(a): everything is strictly a node;
  segments live ONLY inside a leaf (neutral at production, narrowed at consume).
  No blessed "raw leaf-payload value" category; the carrier is always a leaf.
