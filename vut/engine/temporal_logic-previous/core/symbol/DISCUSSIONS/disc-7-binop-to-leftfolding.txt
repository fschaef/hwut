===============================================================================
disc-7  BinOp REMOVED -> LeftFolding (mount the STAR; associativity typed)
===============================================================================
STATUS    DONE. 60/60 green.

THE INSIGHT (Frank-Rene)
    BinOp names its ARITY, not its action -- a meaningless name and structure;
    it does not say what it is doing. And the binary tree was IMPEDANCE
    MATCHING: the ladder rule is (head, STAR((op, operand))) -- a repetition the
    engine ALREADY built as a STAR_Node. _left_fold unrolled that star into a
    deep nest of binary BinOps purely to fit a binary shape. There is no
    repetition to fold: you receive a STAR_Node and simply MOUNT it.

THE NODE (core/symbol, general)
    LeftFolding(head, star, begin)
        head : the first operand (Leaf or node)
        star : the engine's STAR_Node, MOUNTED not copied -- items are
               (op_token, operand) pairs in source order.
    RightFolding(head, star, begin) : the dual (right grouping), provided for a
    right-associative tier; not produced by the current all-left ladders.

    ASSOCIATIVITY IS THE NODE'S IDENTITY, not a downstream convention. The
    earlier worry -- a flat mount loses '(a-b)-c' vs 'a-(b-c)' for the
    non-associative '-' '/' -- is answered: a LeftFolding MEANS left grouping by
    its TYPE. A consumer reads the discipline off the node, cannot mistake it.
    Mixed associativity => one node type per tier (Left/Right), typed not
    conventional.

    GENERAL: zero VUT vocabulary -- a pure operator-grammar concept ("a
    same-precedence operator sequence associating in direction D"). Belongs in
    core/symbol beside Leaf/Root. Children are the common base (head + operands),
    generically walkable. Mounting a STAR_Node depends core/symbol ->
    core/parser_generator (DOWN the pipeline, permitted); STAR_Node is a
    general-engine type, not application vocabulary -- so the mount does NOT
    leak CST/VUT vocabulary into the AST. (a) mount-the-star was chosen over (b)
    copy-steps-to-a-list because the fold CHARACTER is meaningful only with the
    foldable structure present; "mounting is addressing, not copying".

    PRECEDENCE is carried by grammar rule nesting (or>xor>and>...>mul>un), not
    by any fold: each ladder rule stars ONE operator tier, so every step in one
    LeftFolding is the same precedence -- the flat mount loses no precedence.
    Verified: the six ladder rules each STAR a single <op-TIER>.

SCOPE (Frank-Rene): ONLY the ladder. UnOp (unary, one operand) and Comparison
    (left/op/right, no star) are NOT folds -- left as-is. Their names share the
    shape-not-action smell but that is a separate question.

AS BUILT
    - _left_fold rewritten: empty star -> bare head (a level with no operator
      collapses to its operand); else LeftFolding(head, star). No loop.
    - BinOp class DELETED; mentions swept to LeftFolding.
    - renderer (test-engine): walks head + star.items left-to-right, same
      left-associated parenthesisation -- meaning preserved.
    - 9 GOODs regenerated on real infra.

RESULT -- the unrolling was self-inflicted
    monkey-fuzz 'math': total AST nodes 13007 -> 353; BinOp 6364 -> LeftFolding
    81 (+ 81 mounted STAR_Node). 6283 nodes of pure impedance-matching deleted.
    Information identical (renderer output unchanged, left-association preserved);
    representation collapsed. The clearest proof BinOp's nesting was waste.

NOTE
    Consumers of a ladder expression now walk LeftFolding(head, star) via a
    left-to-right pass over star.items (one shared helper), instead of .left/
    .right recursion. The obligation is NAMED by the type, not silent.
