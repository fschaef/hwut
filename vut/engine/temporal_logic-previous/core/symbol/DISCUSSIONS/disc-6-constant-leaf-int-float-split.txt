STATUS    DONE. 60/60 green.

THE CHANGE (two coupled parts)
  GRAMMAR: t_re_number (\d+(?:\.\d+)?) SPLIT into two terminals:
        t_re_float = \d+\.\d+    DECLARED FIRST
        t_re_int   = \d+
     Lexer disambiguation is DECLARATION ORDER (tier-6, first-match
     alternation), so float-before-int gives maximal munch: 5 -> int, 5.0 ->
     float. Verified against re alternation semantics. No lexer change needed.

     New ROOT-scope rule  "<number>": (t_re_float OR t_re_int).  Root scope
     because both atom (expr block, nested) and def-clock (root) reference it,
     and bare references resolve scope-local OUTWARD to root (D-21): a root rule
     is visible from any nested block. A nested definition would be invisible to
     def-clock -- the first attempt put it in the algebr block and failed with
     'undefined non-terminal number (scope <root>)'.

     Clock period accepts BOTH int and float (Frank-Rene): def-clock period slot
     is "<number>", not a single terminal. ROLES: both t_re_float and t_re_int
     carry the "period" role.

     LL(2): t_re_float and t_re_int are DISTINCT terminals, so FIRST(float)=
     {t_re_float}, FIRST(int)={t_re_int} -- no overlap; LL(1) suffices, the
     check passes.

  LEAF: ConstantLeaf reworked to carry text + kind.
        E_ConstantKind(INT, FLOAT, STRING, BOOL) -- new enum in core/symbol.
        The kind RIDES FROM THE TERMINAL, not re-derived from text (common
        compiler practice: lexer records kind + spelling; interpretation to a
        machine value is DEFERRED to the static layer, which decides against the
        compared side's kind -- unchanged from the old Literal contract). kind
        is what makes the const-fold license real.

        Literal (parser node) COLLAPSED into ConstantLeaf, wholesale (as
        OpaqueCode -> OpaqueLeaf): class deleted; reduce actions build
        ConstantLeaf:
          <number> rule       -> _number(OR_Node): triggered_index 0=FLOAT,
                                 1=INT (arm order).
          atom OrMap          -> arm 2 (<number>) PASS (already a ConstantLeaf);
                                 3=string -> _string_const (STRING);
                                 4,5=true/false -> _bool_const (BOOL);
                                 6=opaque -> OpaqueLeaf; 0,1,7 pass.

FACTORY NORMALISATION (follow-up)
  ConstantLeaf gained from_text(text, kind, begin) -- a GENERAL factory taking
  PURE PRIMITIVES (no CST/token type), matching the ast.X.from_* pattern used by
  ~40 AST_MAP entries. The three ast_map literal builders (_number,
  _string_const, _bool_const) now DELEGATE construction to it; they retain only
  the CST-shape DISPATCH (which arm/terminal matched -> which kind).

  PRINCIPLE (reusable across ast_map): a reduce action splits into
    (a) CST-shape dispatch -- triggered_index, children, OR-arm selection:
        parser-generator knowledge, STAYS in ast_map; and
    (b) construction from resolved values: can be a GENERAL factory on the
        node/leaf, taking primitives or a duck-typed shape (cf.
        OpaqueLeaf.from_span reading .text/.mode/.begin).
  This is WHY the bulk of ast_map's free functions correctly stay free
  functions: _left_fold (a fold transform), _clockwork_name_step (a 3-way
  dispatcher), _operand (may return list[str], not a node) are dispatch/
  transform, NOT single-node construction -- forcing them onto a class would be
  artificial or scatter shared logic. Zero-diff refactor; 60/60 green.
