    Notes within Bin A (handled, NOT excluded):
      - Trigger.name may be [keyword] for a SYSTEM trigger -- still a name-access
        leaf; the keyword case is a ReferenceLeaf whose segments are the keyword
        (it does not resolve against the user symbol table, a semantic concern,
        not a representation one). Any existing keyword flag rides alongside,
        as is_void does on HasRef.
      - lvalues are assignment TARGETS -- still names that must resolve to a

      - HasRef/DefaultRef carry (segments, is_void): the segments become the
        ReferenceLeaf; is_void stays a sibling field on the node.

BIN B -- DECLARATIONS (a name INTRODUCED here, not resolved)  -> NOT this pass.

    These are definition sites: disc-1's dual, a Declaration leaf, later. Making

-------------------------------------------------------------------------------
DECIDED -- the seam is PER-FACTORY, not the shared name-builder
-------------------------------------------------------------------------------
_name_dotted (ast_map) reduces the <name-dotted> rule to a bare list[str] and
feeds BOTH bins (via _signature it reaches Mode/StateMachine/ModeGroup/Clockwork
-- declarations). So the list[str]->ReferenceLeaf wrap CANNOT live in
_name_dotted: that would convert declaration names too.

The wrap lives at each BIN A FACTORY, where the role is known: BoolRef.from_*
wraps its name in ReferenceLeaf; Mode.from_* leaves its name a raw list
(declaration). The raw segment list stays the carrier out of _name_dotted; the
consuming node decides reference-vs-declaration. This is disc-1 exactly: the
leaf kind follows HOW the name is used, which only the consumer knows.

-------------------------------------------------------------------------------
OPEN -- the one fork (NOT picked): the ReferenceLeaf 'begin'
-------------------------------------------------------------------------------
By the time a factory runs, the name is already a bare list[str]; the head
token's offset is gone. Two ways to seat ReferenceLeaf.begin:

  (A) begin = node.begin (the construct's offset). Zero change to _name_dotted;
      each Bin A factory wraps. Offset is the construct, not the name head --
      but that is exactly what these nodes use for diagnostics TODAY, so it is
      behaviour-preserving. Smaller, cleaner pass.
  (B) _name_dotted returns (segments, head.begin); factories seat the PRECISE
      name-head offset. Finer diagnostics, but EVERY consumer (both bins,
      _signature) must unpack the pair -- a ripple beyond Bin A.

RECOMMENDATION: (A). It preserves today's offset behaviour, confines the pass to
Bin A, and a finer offset can be lifted later if diagnostics ever need it.
(Reserved: Frank-Rene picks.)
