WHERE REMOTE PLUGS IN (O-13). 'CTreeScheduler.run' makes one
CDirectoryWork per entry and awaits 'unit.run(emit, budget)'. A
placement backend is the thing that answers THAT call for a unit: the
local backend is the unit's own 'run' (dispatcher made here, lock taken
here); a remote backend ships the unit's (root, entry) to a host that
holds the directory, takes the lock THERE, runs the same Scheduler there,
and streams the same vocabulary events back into 'emit' -- the receiver
and 'fold()' do not learn where an event was made. The budget is HOST-
global by word (O-12): a remote host states its own; how a remote slot
and a local slot relate is the first fork of stage 2, not ruled here.
The seam to keep narrow: 'submit(unit) -> events + CDirDone', no display,
no bookkeeper across the edge. WHERE a unit goes is the strategy's word
(O-15): 'may_start' grows a host, or a sibling hook names one -- the
contract's next step, shaped by what 'linear' and 'successor' taught.

OWED BY STAGE 2: the backend interface and its local implementation;
the per-host budget word; the subject provision (the GOOD the remote
host compares against).
