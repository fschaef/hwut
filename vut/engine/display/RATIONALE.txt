==============================================================================
display -- RATIONALE
==============================================================================

Settled decisions, read-only. Ruled by Frank-Rene, 2026-08-19.

----------------------------------------------------------------------------
D-1  THE FLOW LINE FORMAT
----------------------------------------------------------------------------
PROBLEM   Tests run in parallel; the reader needs to know what is
          happening NOW and how many threads are live, without reading
          a clock of their own or polling.

DECISION  One line per event:

              hh:mm:ss | NNN | [EVENT] NICK:base [choice] ...

          'hh:mm:ss' relative to the stream's first 'when'; unparseable
          'when' prints verbatim, right-aligned to 8. 'NNN' is the
          parallel count AFTER the event. '[SKIP ]' for a 'run-ended'
          that never had a 'run-begun'. Failing lines carry the phrase
          inline. Cause appended with '<-'. Width fixed 78 (constructor
          arg; COLUMNS honoured only on a tty, at the face, once).

          DIRECTORIES roll-call after the flow; FAILURES last. Per-
          directory dotted block from HWUT 1.0: GRAVEYARD (confusing,
          no longer needed -- the roll-call and FAILURES carry all of it).

COST      One line per event means a long run produces a long log; the
          QUIET tier is the answer for callers that want the summary only.

GRAVEYARD Per-directory dotted progress block (HWUT 1.0) -- retired in
          favour of the linear flow + closing roll-call.

----------------------------------------------------------------------------
D-2  THE COLOUR DECISION
----------------------------------------------------------------------------
PROBLEM   Colour helps on a terminal; it is noise in a file, a CI log,
          or a 'diff'. Gates are not obvious ('TERM=dumb' under ssh,
          Windows without ANSI, NO_COLOR, CI).

DECISION  ALL gates must pass for colour to be on: isatty, NO_COLOR
          unset, CI unset, TERM set and not 'dumb', not Windows-without-
          ANSI. '--colour' ('force_f') beats every gate, NO_COLOR
          included. '--no-colour' ('veto_f') refuses. Both together:
          REFUSED. Decision taken once at 'main', handed down as a
          flag; no line re-sniffs. The test verifies the DECISION
          (escape presence) not the escape spelling.

COST      '--colour' beside '--no-colour' is refused, not silently
          chosen; the caller must be unambiguous.

GRAVEYARD Escapes-as-literals test idea -- the test would be tautological
          (it only exercises what the test itself writes). The decision
          is the right thing to test.

----------------------------------------------------------------------------
D-3 / E-1  THE EXIT STATUS LAW
----------------------------------------------------------------------------
PROBLEM   Five faces, five sets of magic integers. A caller checking
          '$?' against a literal had no guarantee two faces agreed.

DECISION  One enum, 'E_ExitCode' (services/_exit.py), IntEnum so
          'sys.exit()' takes a member unchanged:

              OK=0  FAULT=1  REFUSED=2  EMPTY=3  SIGPIPE=141

          Every face returns members and nothing else. The import is
          delayed past '_config' adoption for the three faces
          (compare, merge, report) that may be run by path without
          '-m': 'from ._exit import E_ExitCode' moved to after the
          'if __package__' guard so the relative import resolves in
          both invocation modes.

COST      The five faces needed surgical edits; their GOODs that print
          status numbers changed.

GRAVEYARD Bare integer returns -- every 'return 0/1/2' replaced.

----------------------------------------------------------------------------
D-4  THE DEFAULT TIER
----------------------------------------------------------------------------
PROBLEM   What should 'hwut.run' show without a flag?

DECISION  '--plain' is the default, statable redundantly; the name is
          explicit so a script can pin the rendering even if the
          default changes later.

COST      None.

----------------------------------------------------------------------------
D-5  THE TIER LADDER
----------------------------------------------------------------------------
PROBLEM   Some callers want every event (debugging, audit); others
          want the summary only (CI gate); others want nothing on
          stdout (pipe the exit status).

DECISION  Four tiers, each a strict subset of the one above:

              VERBOSE  every event, the swallowed ones included
              PLAIN    the flow, the roll-call, FAILURES (default)
              QUIET    no flow; the roll-call, FAULTS, FAILURES
              SILENT   nothing on stdout; faults to stderr, prefixed

          SILENT governs stdout only -- faults go to stderr with the
          same prefix and nickname as in the flow (the curl -sS law:
          '--silent' means 'quiet on stdout', not 'swallow errors').
          Tiers are mutually exclusive; two together: REFUSED.

COST      '--plain' beside another tier flag is REFUSED, not silently
          ignored; callers that state it redundantly must omit it when
          adding another tier flag.

GRAVEYARD Stderr-silent SILENT -- rejected; hides faults from the
          operator and violates the curl -sS precedent.

----------------------------------------------------------------------------
D-6  ONE ENGLISH DOOR
----------------------------------------------------------------------------
PROBLEM   Wire tokens (e.g. 'terminated-without-hwut-end') are
          machine words; prose renderings had appeared ad hoc in
          several places, giving the impression of misaligned
          components.

DECISION  'word.py' is the ONE place a token becomes English. Every
          rendering draws from 'phrase()'; the wire keeps its tokens.
          PHRASE_DB covers every verdict word and every E_TestRunResult
          value. A token not in the table prints with its hyphens
          opened -- the stability promise.

          One voice throughout: 'not supported here' is always 'not
          supported here', never sometimes 'unsupported'. No mental
          effort wondering whether two renderings name the same thing.

COST      A token the table does not know prints hyphens-opened, which
          may surprise a user on first sight; the fallback is explicit
          and consistent with the stability promise.

GRAVEYARD Token-in-flow / phrase-in-block split -- rejected; two
          vocabularies in one report are harder to read than one.

----------------------------------------------------------------------------
D-7  ONE HOME FOR RENDERING
----------------------------------------------------------------------------
PROBLEM   Human-facing output had three possible homes: 'compare/
          feeder' (which both computed a difference AND rendered it),
          'operations/interaction' (TuiDisplay), and 'display/'. Three
          homes is what makes a tree look like misaligned components --
          the very appearance D-6 was ruled to prevent.

DECISION  'compare' COMPUTES, 'display' RENDERS. Compare emits an
          association structure carrying tolerance marks; display turns
          it into text. One English door ('word.py') therefore covers
          artifact differences as well as the run report, and the
          renderer is reusable by 'accept' and 'merge' without either
          importing compare's presentation.

COST      Compare must emit structure where it previously emitted text;
          TuiDisplay's place (absorbed, kept as the interactive layer
          above the renderer, or retired) is NOT yet ruled.

GRAVEYARD (a) compare renders its own differences -- rejected; it puts
          a second vocabulary beside word.py with nothing keeping the
          two aligned.

----------------------------------------------------------------------------
D-8  THE FACE IS OPERATIONAL; DISPLAY OWNS THE RENDERING WORDS
----------------------------------------------------------------------------
PROBLEM   'orchestrator/run/' was verified free of rendering -- no
          print, no write, no format string, no display import. The
          FACE was not: 'services/run.py' held the tier table, the
          three rendering refusals, the tty sniff, the colour gates,
          the width policy and the ink construction. An operational
          face was deciding how things look.

DECISION  Three kinds of word, three parsers, each owned by whoever
          understands it:

              selection   the wish         plan/wish.py   parse_wish()
              execution   --jobs --no-store  the face
              rendering   tier, colour     display/console.py
                                              parse_rendering()

          'parse_rendering()' mirrors 'parse_wish()': it takes the
          words, yields what it understood and what it did not touch,
          and raises 'RenderingError' where the words cannot want
          anything. The face turns the raise into REFUSED, by name,
          with the usage line -- exactly as it already did for
          'WishError'.

          'console_view()' hands back a constructed view: tier, ink and
          width already decided. The face keeps ONE piece of rendering
          knowledge -- whether its own stdout is a terminal -- because
          it alone knows its sink ('write' given, or 'print').

          'orchestrator/run/' remains operational only. That is now a
          LAW in its README, not an accident.

          Side effect, and the reason this shape was chosen over a
          simple helper call: the REST split becomes STRUCTURAL rather
          than a rule in a document. Selection and execution are
          exposed; rendering never is. A type, not a convention.

COST      One more module in display/. The alternative (growing
          'plain.py') was rejected because a second view (html, pdf)
          will want its own option vocabulary and none of the console's
          tty gates; 'console.py' names the tier that owns them, so a
          future 'html.py' sits beside 'plain.py' as a peer.

VERIFIED  A pure refactor must move zero GOODs. All 14 display GOODs
          byte-exact after the move, the 'refused' choice -- which
          exercises all three rendering refusals -- included.


D-9  THE FLOW LINE CARRIES WHAT WAS ASKED FOR, AND NAMES WHAT RAN

PROBLEM   Every flow line opened with a clock and a job count nobody
          had asked for, carried its badge in brackets and its choice
          in braces, repeated the directory nickname on every line,
          and announced the beginning of tests that had already
          finished. Four columns of furniture around one fact.

DECISION  THE COLUMNS ARE ASKED FOR. '--show-timing' gives seconds
          (a suite is read in seconds; a column of zeroed hours says
          nothing); '--show-jobs' gives '|3|', no blank inside the
          bars. Absent both, the line carries the badge and the name.
          THE BADGES LOSE THEIR BRACKETS and keep their alignment,
          five characters wide. THE CHOICE LOSES ITS BRACES: it has a
          column of its own, and a column needs no punctuation to say
          where it begins.
          THE LINE ELIDES, as a sorted wishlist does (disc-8): ':/'
          where the directory repeats, ':/:' where the application
          does. Columns are FIXED, not grown as names arrive -- a
          width that widens mid-run moves every column under it.
          SESSION AND BUILD ARE SILENT unless '--show-details', the
          VERBOSE tier, or FAILURE: a failed precondition is a test
          result, never a silence.
          THE 'START' IS HELD '--start-delay' seconds, 2 by default.
          A test finishing inside the window never announces its
          beginning; one outliving it does, so a slow or hanging test
          is visible while it stands. The consumer WAKES on its own
          (run.py, TICK_SECONDS) -- a run that merely takes long
          emits no event, and a held line nobody released would never
          be seen.
          A BROKEN SPECIFICATION IS A FAILING TEST, emitted like a
          [MISDEP] node, counted in its directory and named in
          FAILURES -- the same law that makes a failed BUILD a test
          result rather than a suite-aborting precondition.
          THE VERDICT TAG CARRIES A GROUND, white on green and white
          on red; the phrase beside it does not. The tag is what an
          eye SCANS for, and a block of colour is found at a glance
          where a coloured word is read for.
          THE WIDTH is the terminal's, held between 40 and 120: a
          line drawn across a very wide terminal is a line the eye
          must travel, and the dots stop joining name to verdict.

COST      Every display GOOD moves. The default flow no longer shows
          when a test ran, which '--show-timing' restores.

VERIFIED  337 declared choices green across ten suite families.

GRAVEYARD A FIXED 2-SECOND DELAY, unstatable -- rejected: whether a
          line EXISTS would depend on the speed of the machine, which
          is the one thing a GOOD file may never hold.


D-10  THE RUN'S GOOD IS A DIGEST, AND THE DIGEST IS PART OF THE ORACLE

PROBLEM   'hwut.run' launches in parallel, so the ORDER of its flow
          is decided by a race. Order is not a fact about the
          subject, and a GOOD that records it records the morning.

DECISION  THE RUN SUITE RECORDS THROUGH A PYPE ('test-run.pype').
          The digest collects the flow, EXPANDS the elision, SORTS on
          (directory, application, choice), RE-ELIDES, and prints.
          EXPANSION COMES FIRST because a live line elides against
          ARRIVAL order: sorting lines still in that form would
          attach ':/: two' to whichever run sorted above it. And only
          then may it elide again -- ONLY A WRITER THAT SORTS MAY
          ELIDE (disc-8), which is why the live flow's elision and
          the digest's are different acts upon one notation.
          THE DIGEST MASKS what belongs to the machine and the
          morning: the timing column, the job column, machine paths,
          the wall clock, and the DOTTED FILL -- whose length is the
          width less the body, and whose body carries the live
          elision mark, so two runs of one suite differed in nothing
          but a count of dots.
          IT MASKS NOTHING ELSE. Masking the clock is
          deterministicalization; masking a verdict is blindness.
          THE PYPE IS THEREFORE PART OF THE ORACLE, and a defect in
          it is a defect in the oracle -- see
          adm/WORK/gathered/06-todo-2-pype-is-part-of-the-oracle.txt,
          which
          the developer's manual must carry.

COST      What a person reads in the run suite's GOOD is the digest's
          account, not literally what the terminal printed. The price
          of determinism under parallel launch.

VERIFIED  Byte-identical across '--jobs=1, 2, 4' and over three
          consecutive runs. Three defects were caught by that check
          and not by inspection: the varying dotted fill, a ':/:'
          that named nothing where a run had no choice, and 'DIR'
          lines printed on arrival while everything else was sorted.

GRAVEYARD MASKING IN TWO PLACES, shell and pype -- rejected as
          policy: one place, or the two disagree. The raw choices,
          which no digest reads, are masked in the suite; the
          digested ones in the pype; both swallow the same kinds of
          fact.

D-11  THE JUNCTION AND THE PLACE                                (2026-09-02)

PROBLEM   Every node of the DIRECTORIES tree ended in the same "o",
          whether it had run something or only led somewhere:
          "'---o region/potpourri" and "'---o solver/TEST" read alike,
          and the eye had to parse the name to tell a branch point
          from a test directory.

RULED     (Frank-Rene) drop the "o"; a node that only branches ends
          in ".".

DECISION  A PLACE ends in nothing, "'---  solver/TEST"; a JUNCTION
          ends in a dot, "'---. region/potpourri". Both six columns
          wide -- the indent below is four per level, and two widths
          would step the whole subtree sideways.

ALSO      'test-run.sh' now prints '<hwut-end>' as its last line.
          None of its sixteen GOODs carried the token, so
          'hwut.accept' refused every one of them and the suite could
          not be corrected -- three of them recorded 'STATUS: 120', a
          timed-out run accepted as the oracle, with nobody able to
          replace it. The token stands after 'esac', so the
          '--hwut-info' arm exits before reaching it. All sixteen
          re-recorded; no GOOD records a timeout any more.

          'jobs-budget' had looked like a timeout for days. It was
          'test-run--jobs-budget.pype' with its EXECUTE BIT LOST -- a
          mode a patch does not carry -- dying on 'Permission denied'
          every run. Restored, with five more pypes under 'test_
          writing_support/hwut_pype/examples/' that had lost theirs.

          Four 'test-plain.py' GOODs were stale since the display
          rework and read as "skip lines vanished". They had MOVED:
          the reason left the flow line for HINTS, as ruled. Every
          differing line named before blessing.

COST      display 20 ok / 4 fail -> 24 ok / 0 fail.

D-12  THE TREE'S INK                                            (2026-09-02)

RULED     (Frank-Rene) one blank after a leaf's connector; everything
          that is TREE in the directory's orange, a junction's name
          included; a leaf's name green up to and including the '/',
          the TEST directory itself red.

DECISION  As ruled, in 'plain.py's tree emitter:

              <208>   +--- <32>alpha/<196>TEST
              <208>   +---. <208>deep
              <208>   |   +--- <32>inner/<196>TEST

          Orange is 256-colour 208, the one colour a directory has
          wherever it is named (DIR band, HINTS head, now the tree).
          Red is 196, pinned, for the reason FAIL_CODE gives: a
          theme may paint palette slot 1 orange, and the place must
          not share a hue with the road. Green is base 32.

          A leaf's connector is five wide, a junction's six. A leaf
          hangs nothing below it, so its width is free; a junction's
          must not step the indent below it sideways. A place that
          ALSO branches keeps six.

          The fill and the tag are measured on the UNPAINTED text and
          painted after, so the dots land where they landed before.

CHECKED   'test-run.sh tree-ink' reduces the coloured tree to its SGR
          codes -- which colour paints which part, and nothing else --
          so the ruling has an oracle. The display's other GOODs are
          the plain rendering and cannot see ink.

COST      Eight GOODs re-recorded for the one blank ('tree-green',
          'tree-fail', 'busy', 'jobs-budget', 'labels', 'linear-raw',
          'short-form'; 'test-plain mixed'); the width was their only
          difference. display 24 ok / 0 fail -> 25 / 0.
