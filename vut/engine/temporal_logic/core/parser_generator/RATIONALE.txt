-------------------------------------------------------------------------------
C-1  ADVISORY ROLE HINTS: TRANSPARENT TAGGING + A CHECKED VOCABULARY
-------------------------------------------------------------------------------
The core MECHANISM behind the language-level role-hint decision (parser A/G
ledger); the language decision -- which positions are tagged, the kind
vocabulary -- lives there.

DECISION
    A grammar position may be tagged with the KIND a reference or terminal is
    expected to denote (a namespace at 'open:', an aggregate at 'spawn:', a mode
    at 'arm:'), to aid the reader and hand pass-2 a per-position expectation,
    WITHOUT changing what the parser lexes, interns, analyses, or builds. Two
    pieces, both in core:
      1. Tagged_Spec -- a TRANSPARENT Operator_Spec wrapper holding one body
         element plus a role string. FIRST_2, the conflict scan, nullable, and
         expand all delegate to the body, so it contributes nothing to the value
         stream. The two authoring forms (a terminal call t("role"), a reference
         suffix '<name(role)>') lower to it.
      2. ROLES -- a checked vocabulary passed to Grammar(roles=...): a dict from
         each role-bearing pattern to the roles it may carry. _validate_roles
         walks the compiled grammar at load and raises RoleVocabularyError on an
         undeclared pattern or unlisted role, beside the LL(2) gate -- so a typo
         ('evnet') fails at COMPILE, not as a far-off pass-2 misresolution.

INVARIANTS (future changes must not violate)
    - NON-IDENTITY. A role never enters a terminal's _name(). If it did,
      t_re_id("event") and t_re_id("clock") would intern as different terminals
      and fracture the one-keyword-one-token guarantee; '<name-dotted(event)>'
      and '<name-dotted(clock)>' would become different references.
    - ADVISORY for pass-2. A declared role is a resolution expectation, never a
      substitute for a kind check; a missing hint is never an error there. The
      LOAD check is the only enforcement, and it checks SPELLING against the
      vocabulary, not semantics.
    - OPT-IN. roles=None skips the check, so the core's toy grammars and any
      consumer not using hints are untouched.

COST (load-bearing, kept)
    Terminals must be dict KEYS for ROLES, so Terminal_Spec gained content
    __hash__/__eq__ on _name(). Because interning yields exactly one object per
    _name(), content equality and identity coincide -- the engine's pervasive
    'is' comparisons are unaffected (a byte-identical suite confirms it). The
    full decoration pass (29 hints, 19 kinds) left the entire suite
    byte-identical; that regression is what proves the wrapper transparent.
    Not chosen: carrying the role as a VALUE wrapper through the CST (would force
    every positional factory to unwrap); folding the role into terminal identity
    (breaks NON-IDENTITY above).

A-NA  ABSENCE AS A TYPED SINGLETON (NodeAbsent)                     [RATIFIED FR]
===============================================================================

PROBLEM
    OPT is the only grammar shape whose admissible, expected outcomes include
    "no node at all". Present -> a node (possibly itself structureless). Absent
    -> nothing, a legitimate result, not an error. OPT needs a value that MEANS
    absence. The value was bare None (OptMap absent arm), while the CST reduce
    used a separate ABSENT sentinel for "body produced no surviving value". Two
    tokens for one idea, meeting in the present-but-empty OPT_Node where the
    sentinel leaked into the AST. None is also overloaded (missing slot, failed
    lookup) and carries no relation to the CST world.

DISTINCTION
    Absence and emptiness are different KINDS and must not be confusable:
      - OPT: outcome is a node OR absence. Absence = the whole node is gone.
      - STAR/PLUS and every node with children: outcome is ALWAYS a list (or the
        node). Empty body -> empty list, length 0 -- present-and-empty, NOT
        absent. A list of NodeAbsent elements is still a list of a certain
        length. There is no "the whole list vanished" case.
    Absence is an OPT-only phenomenon; emptiness is a STAR/PLUS/structured
    phenomenon.

DECISION
    NodeAbsent: a singleton-like typed value meaning exactly "an OPT that did not
    fire". Unlike bare None it carries the relation to the CST world, so wherever
    it surfaces it is unambiguous.
      - OptMap absent arm returns NodeAbsent (was None). A-13 restated: absent ->
        the typed absence value, non-negotiable, no author parameter.
      - ABSENT and None-for-OPT-absence unify into the ONE noun NodeAbsent
        (terminological invariance). The CST-internal "empty body" marker and the
        AST-level "OPT absent" value are the same typed singleton.
      - OPT present arm UNCHANGED: presence gates, the leaf fires, and it now runs
        on an unambiguous NodeAbsent when the body was empty (this is what makes
        the present-but-silent case blessable -- opt_factory).
      - STAR/PLUS/structured nodes UNTOUCHED: they never yield the absence
        singleton at top level; it appears only as an OPT result or a child slot.

COST
    - test-ast-map-router opt_absent GOOD regenerated (absent -> NodeAbsent).
    - test-ast-map-router opt_factory GOOD regenerated and blessed; disc-1
      (opt-present-empty-body) closed.
    - test-cst absent_optional / silent_optional GOOD regenerated (pure rename).
    - A behaviour change (None -> NodeAbsent) plus a rename (_Absent/_NodeAbsent,
      ABSENT/NodeAbsent) swept tree-wide, tests and docstrings included.

GRAVEYARD
    - Rejected: keep bare None for OPT absence. Overloaded; no CST relation;
      forces every consumer to disambiguate None-the-absence from None-the-slot.
    - Rejected: suppress the present arm when child is empty (collapse-to-None).
      Wrong -- a fired optional IS present; the fix is a typed value, not hiding
      the present arm.
