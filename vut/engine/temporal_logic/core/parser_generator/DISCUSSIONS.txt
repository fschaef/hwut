-------------------------------------------------------------------------------
C-1  ADVISORY ROLE HINTS: TRANSPARENT TAGGING + A CHECKED VOCABULARY (2026-06-13)
-------------------------------------------------------------------------------
PROBLEM
    The language layer wants to annotate a grammar position with the KIND a
    reference or terminal is expected to denote ('<name-dotted>' at 'open:' is a
    namespace; at 'spawn:' an aggregate; at 'arm:' a mode). The annotation must
    aid the reader and hand the semantic layer a per-position expectation,
    WITHOUT changing what the parser lexes, interns, analyses, or builds. A
    free-form string annotation also invites a silent typo ('evnet') that
    surfaces only as a pass-2 misresolution far from its cause.

IDEA
    Two pieces, both in core:

    1. A TRANSPARENT spec wrapper, Tagged_Spec, holding one body element plus a
       role string. It is an Operator_Spec, so the FIRST_2 fixpoint and the
       conflict scan descend through it by 'body'/children() like any operator;
       nullable / FIRST_2 / expand all delegate to the body. It contributes
       NOTHING to the value stream. The two authoring forms -- a terminal call
       (t("role")) and a reference suffix ('<name(role)>') -- lower to it.

    2. A CHECKED VOCABULARY, ROLES, the grammar passes to Grammar(roles=...): a
       dict from each role-bearing pattern (a terminal object, or a '<name>'
       reference string) to the tuple of roles it may carry. _validate_roles
       walks the compiled grammar at load time, resolves each Tagged_Spec to its
       key, and checks the role against the declared tuple, raising
       RoleVocabularyError on an undeclared pattern or an unlisted role. It runs
       beside the LL(2) gate, so a typo fails at compile, not in pass 2.

COST
    1. A wrapper node type in the spec tree, plus one transparent case in each
       grammar-WALKING helper that switches on spec type by hand (the engine's
       FIRST_2 and conflict walks get it free via the Operator_Spec 'body'
       fallback; the test-support walkers needed an explicit Tagged_Spec case).
       MITIGATION: the wrapper delegates every analysis method to its body, so
       "transparent" is enforced by construction, not by each caller remembering
       to unwrap. The full decoration pass (29 hints, 19 kinds) leaves the entire
       test suite byte-identical, which is the regression that proves it.

    2. Terminals must be dict KEYS for ROLES. A Terminal_Spec is interned (one
       object per _name()) and never mutated after construction; it gained
       content __hash__/__eq__ on _name() to make the value-key contract
       explicit rather than resting on the interning invariant alone.
       MITIGATION: because interning yields exactly one object per _name(),
       content equality and identity coincide -- the engine's pervasive 'is'
       comparisons are unaffected, confirmed by a byte-identical suite.

    3. The check is one more thing that can reject a grammar at load.
       MITIGATION: it is OPT-IN (roles=None skips it), so the core's own toy
       grammars and any consumer not using hints are untouched.

INVARIANTS (future changes must not violate)
    - NON-IDENTITY. A role never enters _name(). If it did, t_re_id("event")
      and t_re_id("clock") would intern as different terminals and fracture the
      one-keyword-one-token guarantee; '<name-dotted(event)>' and
      '<name-dotted(clock)>' would become different references.
    - The vocabulary is ADVISORY for the semantic layer: a declared role is a
      resolution expectation, never a substitute for a kind check, and a missing
      hint is never an error there. The LOAD check is the only place a role is
      enforced, and it enforces spelling against the vocabulary, not semantics.

GRAVEYARD
    - Carrying the role as a VALUE wrapper through the CST (the first sketch):
      rejected. Every AST factory reads its children positionally; a value
      wrapper would force each one to unwrap, reintroducing the per-position
      coupling the spec-tree collapse removed. The role rides on the spec, keyed
      by position, instead.
    - A per-role distinct terminal (folding the role into identity): rejected,
      see the NON-IDENTITY invariant.
