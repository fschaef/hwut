# 6. Host Language Integration (The Lua World)

While the Temporal Engine provides the structure and the "clock," Lua provides the "brain" for data handling, shadow modeling, and environment abstraction.

### 6.1 State-Triggered Meta-Events (The Bridge)
Lua provides the ability to synthesize events based on the internal state of the Shadow Model.
* **Syntax:** `{ condition }` (e.g., `{ player.live_n == 0 }`)
* **Behavior:** When the expression inside the braces evaluates to TRUE, the Engine treats it as a discrete event.
* **Utility:** This allows the test specifier to trigger GuardS or Rules based on complex internal logic rather than just raw external packets. It effectively turns "State" into "Signal."

### 6.2 Data Normalization & Codecs
* **The Role:** Lua acts as the **Codec Layer**, transforming opaque or binary payloads into the structured objects used by the Rule Space.
* **Transformation:** A raw buffer can be decoded into a Lua table, allowing the Rule Space to use clean dot-notation (e.g., `Packet.header.id`) instead of bit-masking.

### 6.3 The Shadow Model (Reference Oracle)
* **The Role:** Lua maintains a persistent **Shadow State** of the SUT.
* **Determinism:** Because the Lua VM is stepped only within the `process(Event)` cycle, the model is perfectly synchronized with the Engine's logical time.
* **Reference Checking:** Rules can call Lua functions to verify if the reported event matches the expected state (e.g., `violation if not Lua.verify_checksum(E.data)`).

### 6.4 Complex Predicates & Math
* **The Role:** Delegation of heavy lifting.
* **Usage:** For properties that are mathematically intense (Statistical distributions, Signal Processing, Fourier Transforms), Lua provides a mature environment to perform calculations that would be too verbose for pure temporal logic.

### 6.5 Environment & Mocking Helpers
* **Configuration:** Lua can hold environment-specific constants (IP addresses, timeouts, version flags).
* **Mocking:** When the Engine is in "Active Stimulation" mode, Lua can generate the payloads for Command Events, allowing the test to simulate complex SUT responses or environment behaviors.

### 6.6 Safety Boundary: The "Next-Jiffy" Action
To preserve the Deterministic Guarantee:
* Any event produced by a Lua state change (e.g., `{ x == 0 }`) or an action block follows the **Causal Chain**. 
* These events are queued and processed in the **subsequent Jiffy**. This prevents "Zero-Time Loops" where a state change triggers an event that changes the state back within the same evaluation cycle.
