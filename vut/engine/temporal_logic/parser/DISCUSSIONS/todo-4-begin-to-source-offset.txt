todo-4  AST/CST/token field 'begin' -> 'source_offset'  (deferred, high churn)
===============================================================================
SCOPE     parser. Decided in direction; a deferred high-blast-radius rename
          kept OUT of the _ast.Module / typestate pass so a GOOD-file break can
          be attributed to one rename at a time.

STATE TODAY:
    Every AST node (and the CST nodes, and the lexer tokens) carries 'begin' --
    the absolute source offset where the construct starts. 'begin' names that
    it is a START but not start OF WHAT KIND: it reads as a generic beginning,
    when the thing it holds is a POSITION IN SOURCE TEXT. The diagnostics layer
    already names the same fact 'source_offset' (Diagnostic.source_offset). The
    node field and the diagnostic field are the same concept under two names;
    the dataflow node.begin -> Diagnostic.source_offset has to be read, not seen.

TARGET:
    Rename the node-origin field 'begin' -> 'source_offset' so node-origin and
    diagnostic-origin share one word, and the flow node.source_offset ->
    Diagnostic.source_offset is self-evident. Terminological invariance: one
    name, one concept, across the layers it threads through.

WHY DEFERRED:
    303 occurrences across 20+ files, and 'begin' is a substring risk (begin_block,
    comments, prose) -- not a blind sed. ~6x the blast radius of the RuleFile ->
    Module rename. Folding it into the Module/typestate pass would mean a GOOD-file
    break could not be attributed to one rename. It is independently verifiable
    and independently valuable: its own pass, its own GOOD-file run.

SEAM INTERACTION (settle before implementing):
    'begin' lives on THREE node families: CST nodes (cst_nodes.py, neutral side),
    the VUT AST nodes (ast_nodes.py), and the lexer tokens. The neutral
    parser-generator's node field names are part of ITS public surface (see
    core/parser_generator/DISCUSSIONS/seam-1). Decide whether the neutral side
    keeps a generic 'begin'/'offset' while only the VUT AST adopts 'source_offset',
    or whether the rename crosses the seam. A seam question, not just a rename --
    another reason it does not ride on the current pass.

PROVENANCE -- RELATED, BUT SEPARATE (recorded so it is not re-conflated):
    The load stage gained per-file import provenance (which import pulled a file
    into the closure, and from where; see semantic/ typestate work). That is the
    SAME idea -- ORIGIN -- at a different granularity: 'begin' is intra-file
    (where in this text), provenance is inter-file (which import, which line).
    They must be named RELATEDLY, NOT IDENTICALLY: one word for both would
    re-commit the layer-conflation error (RuleFile in a new costume). The parser
    stays single-file and carries NO import-chain concept; provenance is a
    load-stage concept only. Do not push provenance down into the parser.

TO IMPLEMENT:
    Settle the seam question above. Then rename the field on the chosen node
    families and update every consumer (factories, ast_map, scope_tree, cascade,
    checks, the span oracles, and the tests). Count-checked edit; GOOD-file
    regen as its own batch.
