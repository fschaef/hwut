PART I -- FRONT-END ARCHITECTURE  (the CST/AST machinery)

-------------------------------------------------------------------------------
A-1  CANONICAL CST BASELINE WITH A PARTIAL TRANSFORMER OVERLAY  (was D-5)
-------------------------------------------------------------------------------
PROBLEM
    The original reduction model was hand-written _build_* functions in an
    ACTIONS dict, one per rule. It was fragile three ways: every grammar change
    demanded synchronised edits in three files (grammar, AST node, builder);
    positional unpacking of a sparse frame was silent-failure-prone (silent
    terminals dropped and absent optionals left no gap, so frame index i was not
    grammar position i); and a forgotten ACTIONS entry was a silent
    pass-through, not an error.

DECISION
    The engine ALWAYS reduces a parse, bottom-up, to a canonical CST of five
    frozen node kinds, one per authoring operator (OR_Node / OPT_Node / SEQ_Node
    / PLUS_Node / STAR_Node). This is a PRUNED CST: silent terminals contribute
    nothing, so syntax is discarded while structure -- which operator matched,
    which OR branch, how many repetitions -- is preserved. An optional, PARTIAL
    transformer dict (AST_MAP, keyed by rule name) overlays it: a rule with a
    transformer has its finished CST node handed to a constructor that returns a
    typed AST node; a rule without one passes its CST node through untouched.
    Children are transformed first (a consequence of eager bottom-up reduction,
    not a feature): by the time a parent's constructor runs, each child slot
    already holds the child's finished output.

COST
    1. The CST node is built even for a rule whose transformer immediately
       discards it -- one frozen-wrapper allocation per transformed reduction.
    2. The PASS_THROUGH / DEFAULT sentinels of the old model are retired;
       "forward the child" is "no transformer plus read OR_Node.child", "build
       the generic node" IS the default.
MITIGATION
    Allocation is bounded and small: a CST node holds REFERENCES to
    already-reduced children, so it is one allocation over a child list that
    already exists; only transformed rules pay the build-then-discard wrapper.
    The order is N allocations for N reductions -- the same order the old _build_*
    path paid. Retiring the sentinels deletes real validation surface.
GRAVEYARD
    - "Lazy transformation" (deferring child transforms): a miscategorisation --
      both orderings are eager; they differ only in the child TYPE the parent
      sees, and the transformed-child type is the cheap and useful one.
      Re-wrapping finished children back into CST for a parent would cost
      machinery for a case that never arises (the grammar already encodes
      structural distinctions a parent might want as SEPARATE rules with
      distinct output types).
    - A per-grammar-position factory list (the sparse "PART-1" frame): rejected
      with the sparse frame; the single-transformer-per-rule shape matches the
      natural CST node and needs no positional list.
INVARIANT
    Optionality is expressed by an OPT_Node's 'present' STATE, never inferred
    from a missing downstream slot: an absent inline optional keeps its stable
    SEQ slot, so a parent's child count is identical present or absent.

-------------------------------------------------------------------------------
A-2  THE COMPLETENESS GUARANTEE IS REINSTATED AS A LOAD-TIME COVERAGE GUARD
-------------------------------------------------------------------------------
PROBLEM
    The partial overlay (A-1) gave up the "every rule mapped" guarantee: a
    forgotten transformer became silent at load (the consumer received a CST node
    where it expected an AST node), moving the failure to runtime-at-the-consumer.

DECISION
    validate_ast_map(GRAMMAR) runs at compile time, beside the LL(2) gate, and
    requires every grammar rule to be mapped (to a constructor, a plain-value
    function, a dispatch function, or _passthrough). A forgotten mapping is again
    a loud load-time error naming the rule.
COST
    The map must be kept in step with the grammar -- but at load, not at runtime.
MITIGATION
    The check is mechanical and runs on every compile; it cannot be skipped.
GRAVEYARD
    Leaving the gap "bounded by typing" (A-1's first mitigation -- frozen CST
    nodes fail an isinstance check visibly): kept as a backstop, but the load
    guard is the primary defence; a diagnosable runtime failure is weaker than a
    named load failure.

-------------------------------------------------------------------------------
A-3  CONSTRUCTORS LIVE ON THE NODE CLASSES AND READ THE CST DIRECTLY  (was D-10)
-------------------------------------------------------------------------------
PROBLEM
    An intermediate migration kept the _build_* bodies as free functions speaking
    a dense-frame idiom, fed through a flatten bridge. Right as a migration step
    (zero transcription risk, byte-exact parity), wrong as an end state:
    construction logic did not live on the classes it constructs, the bodies
    still read positional dense lists, and the map module carried displaced logic.

DECISION
    Each node-producing rule maps to a classmethod ON its AST node class
    (Spawn.from_seq, HasRef.from_seq, ...). A rule producing a PLAIN VALUE (a
    dotted-name segment list, a signature tuple, an arg list, a kind dict, a
    ref-member pair) maps to a small function in ast_map.py -- there is no class
    to host it. A rule whose node KIND the input decides (the merged named tails;
    the declaration family) maps to a DISPATCH function in ast_map.py. A
    PASS-THROUGH rule (an OR forwarding its single child) maps to _passthrough.
    Every constructor reads the CST node's STRUCTURE: SEQ children by stable slot,
    OR branches by triggered_index, repetitions off the STAR/PLUS slot, optionals
    as OPT_Nodes whose 'present' flag is on the node. The dense-frame bridge is
    deleted; with it die count-sniffing, the bases/members boundary scan, and the
    trailing-run until split.
COST
    Logic spreads across the node classes instead of sitting in one map module.
MITIGATION
    It sits where it is read -- on the class it builds -- which is the point;
    ast_map.py shrinks to a rule->constructor map.

THE SURFACED BUG (recorded; the fix was kept, not reverted for parity)
    The old trailing-run split recognised an 'until' only as a trailing run of
    Cause nodes. An 'until' whose <cause> took the cause-ref branch yielded a
    CauseRef, not a Cause, so it was never counted AND the scan stopped there,
    cutting off every until before it; all of those fell into the member list,
    matched no case, and were SILENTLY DISCARDED -- full Cause-with-guard subtrees
    among them. The slot-reading constructor preserves them all (the grammar slot
    says what is an until; nothing is type-scanned). Per "fix at the source, not
    the assertion", code was NOT written to replicate the loss for byte-parity;
    the only GOOD-side change was empty '[]' until placeholders becoming the
    recovered subtrees.

-------------------------------------------------------------------------------
A-4  FACTORIES ARE NAMED FOR THEIR INPUT'S CST SHAPE  (was D-11)
-------------------------------------------------------------------------------
PROBLEM
    Uniformly naming the A-3 constructors 'from_cst' left the reader to consult
    the grammar to learn the node parameter's shape, which the signal interface
    (A-6) already states.
DECISION
    Single-factory classes use shape-named factories: from_seq / from_or /
    from_token / from_span -- so the call site states the grammar operator the
    rule has, the spec subtype the parameter is, and what the body reads.
    Terminal-leaf rules use from_token / from_span (single-terminal rules, no
    operator node). Multi-factory classes keep rule-derived names where the rule
    distinction is the meaningful disambiguator and the shape is already carried
    by the signal interface.
SIDE-BENEFIT
    A shape-named factory on a class whose signal disagrees (from_seq on an
    OR_Interface class) is wrong at a glance -- a reader-level correspondence
    check atop the test-ast-signals guard.

-------------------------------------------------------------------------------
A-5  actions.py IS RETIRED INTO ast_map.py; the outer layer is two files + wiring
-------------------------------------------------------------------------------
DECISION
    The outer (language) layer is ast_nodes.py (the typed node shapes) and
    ast_map.py (rule -> constructor), plus grammar.py (the GRAMMAR dict +
    terminal preamble + ROLES) and rule_parser.py (the facade that wires the
    grammar to core and exposes parse()). actions.py and the dead ACTIONS dict
    are deleted.
COST
    The AST node names appeared in printed ASTs, so a GOOD rendering an old name
    changes mechanically on a rename (handled at edit time, never fabricated).
GRAVEYARD
    The dual-path parity harness (TEST/parity-check.py) was a migration scaffold;
    with actions.py gone there is no second path, and it is removed.

A-6  OPERATOR INTERFACES ARE SHAPE-IDENTITY SIGNALS, NOT ACCESSOR CONTRACTS
-------------------------------------------------------------------------------
(The MECHANISM lives in core; see core/RATIONALE C-2. This entry owns the
OUTER-layer consequence: which AST nodes derive from which signal.)
DECISION
    Every operator-shaped AST node derives from the core interface matching its
    rule's top-level operator (OR_Interface / SEQ_Interface / ...). Because the
    'top-level' rule is itself an OR rule, TopLevel derives from OR_Interface, and
    a top-level construct built from a SEQ rule is e.g.
    StateMachine(SEQ_Interface, TopLevel) -- cooperative multiple inheritance of
    two fieldless ABC signals. A node whose rule is itself an OR and is also a
    top-level construct derives from TopLevel alone (TopLevel already signals OR;
    adding OR_Interface would be MRO-inconsistent and redundant).
THE ONE PRINCIPLED EXEMPTION
    Single-terminal rules (guard-luau -> OpaqueCode, mutation -> Mutation,
    report-string -> ReportString) derive from NO operator interface: their rule
    has no operator, so there is nothing to signal. They are also the rules whose
    factory receives the raw leaf (OpaqueTerminal / Token) rather than an operator
    node.
WHY SIGNALS, NOT ACCESSORS  (the crux)
    A digested AST node does not retain a raw triggered_index -- the branch choice
    was translated into typed fields at the factory -- and nothing ever asks a
    held child for its operator internals (the which-branch question is asked once
    at the OR's own reduce, then baked in). An accessor contract would force every
    digested node to fabricate an answer no caller reads, splitting core into two
    dialects (CST answers richly, AST fakes it). The honest general law is the
    truthful intersection: every node carries 'begin', is placeable, and DECLARES
    its shape by which interface it derives from. Error analysis, the load-time
    shape validator, and a category-dispatching semantic pass READ THE SHAPE; none
    call an accessor.

A-7  OpaqueCode: a neutral node naming no embedded language; lazy references
-------------------------------------------------------------------------------
(Pairs with semantic D-1/D-2 and core span-oracle rationale.)
PROBLEM
    The AST node for an opaque span was named 'Luau' with a 'role' field typed by
    the Luau component's Role -- the one remaining parser->luau import. Everything
    span-related should speak 'oracle', not 'Luau'.
DECISION
    ast.OpaqueCode{text, mode, begin}; 'role' -> 'mode', typed as core's SpanMode.
    ast_nodes.py drops its luau import; the parser package names no embedded
    language. OpaqueCode.get_references(oracle) is the lazy seam to the span's
    insides: computed on first call through the abstract
    SpanOracle.collect_references, begins rebased onto the node's absolute
    position, cached in ONE compare=False/repr=False slot written once via
    object.__setattr__ -- pure data in identity and print; the oracle is an
    argument per call, never held.
COST
    The class name appears in printed ASTs, so GOODs rendering 'Luau(...)' moved
    to 'OpaqueCode(...)' and 'role' to 'mode' (one regeneration batch, never
    fabricated). A second oracle invocation per span when references are first
    requested.
MITIGATION
    Lazy: only spans the resolver actually opens pay; the cache means each pays
    once. (A single-pass fusion -- collecting references from the same parse the
    brace-finder already runs -- stays open behind collect_references; nothing
    here blocks it. See luau RATIONALE D-10.)
INVARIANT
    The cached references slot is never part of identity or repr; the node stays
    pure data.

PART II -- THE GRAMMAR SURFACE  (the rule-file language)
===============================================================================

-------------------------------------------------------------------------------
G-1  AUTHORING VOCABULARY: tuple = sequence, list = optional, OR = sentinel
-------------------------------------------------------------------------------
(was R-50/R-51; the combinator MECHANISM is core C-3.)
DECISION
    A GRAMMAR rule body is plain Python literals plus three named operators, so
    the dict reads like a grammar table: a bare tuple is a SEQUENCE; a bare list
    is an OPTIONAL (one element [x] = x optional; more = optional sequence); the
    OR sentinel placed BETWEEN branches inside a tuple is an ALTERNATION
    ('a | b | c'); PLUS(x) / STAR(x) are one-/zero-or-more; a "<name>" angle-
    bracketed string is a reference to GRAMMAR rule 'name'; a bare "literal" is a
    silent keyword.
GRAVEYARD
    - OPT(x) as a wrapping call: retired. It doubled visual nesting on the common
      case and the bracket already means optional everywhere in the prose.
    - OR(a, b, ...) as a variadic call, and an overloaded '|' operator: rejected.
      The between-branches sentinel reads as BNF with no wrapping parens; '|'
      needs combinator objects on both sides, reintroducing the noise the change
      removed.
    - '~name' for a rule reference: rejected. Its only edge (no keyword can
      collide with the sigil) guards a hypothetical that does not exist, and it
      reintroduces a translation step between code and the "<name>" prose spelling.
ESCAPE HATCH
    A keyword literally spelled '<...>' is written T.string("<...>"); the
    "<...>"-means-reference convention applies only to bare strings.
INVARIANT
    A single-element optional produces NO list wrapper in the value stream:
    optionality is PRESENCE or ABSENCE among the surviving values; whatever the
    inner element builds flows up unwrapped. Builders that type-spot values rely
    on this flattening (see G-2).

-------------------------------------------------------------------------------
G-2  WHEN A RULE COLLAPSES TO A BARE ROLE-BEARING TERMINAL (and when not)
-------------------------------------------------------------------------------
(was R-52/R-53.)
FINDING
    A terminal's content KIND (how the oracle parses a span) is not its AST type:
    the same opaque STATEMENT_BLOCK terminal serves mutation, init, and deinit --
    one terminal, one role, three node types, separated only by grammatical
    position. The role cannot carry that distinction; the rule (or its keyword
    prefix) does.
DECISION
    A rule collapses to a bare role-bearing terminal ONLY when the role is unique
    to one grammatical position AND the constructor merely forwards (no distinct
    AST type). guard-luau qualifies (a bare opaque-condition terminal used
    nowhere else). report-string and mutation do NOT: report-string's terminal is
    the role-less string class shared with rvalues/imports (the rule assigns
    meaning by position -- a quoted string in effect position is a ReportString);
    mutation's STATEMENT_BLOCK is shared three ways and Mutation is a distinct
    node the effect-walker expects. AST type is a function of grammatical
    position, not of a terminal's intrinsic properties.

-------------------------------------------------------------------------------
G-3  THE 57-RULE MIGRATION AND ITS RESERVED-WORD CONSEQUENCE  (was D-6, since grown)
-------------------------------------------------------------------------------
(The grammar has since grown past 57 rules with the expression band G-9 and the
clockwork band G-7; the migration installed the structure those extend.)
DECISION
    Functionality-prefixed rule names (def-event, kind-container, cond-term,
    ref-has, elm-mode, list-arg, parens-decl, name-dotted, ...), one scheme across
    the dict, grammar.txt, and the AST-map keys; the five-kind declaration family;
    merged named tails ("the parens decide"); the cond ladder with bare boolean
    terms and symmetric comparison sides; 'for:'-bound cause definitions;
    'import:'/'into:'; 'via:' spawn keys; CHANGE as a system trigger.
RESERVED WORDS (lexer-level)
    Discriminating the kind-decl slot by CAPTURED keywords makes those words
    reserved EVERYWHERE on the rule-file plane: mode, state, mode_group,
    state_machine, struct, container, int, float, string, bool, true, false
    (joining and/or/not, ANY/BEGIN/END/CHANGE, VOID) can no longer be
    identifiers -- not even as member segments. This is inherent to the
    keyword-discriminated slot; bare ids in the kind slot are not LL-decidable.
    The trailing-colon definition keywords ('mode:', ...) are unaffected -- longer
    tokens, earlier lexer tier.
TWIN REF CLASSES OVER ONE ref-member VALUE
    ref-member reduces to a plain (segments, is_void) pair; 'has:' and 'default:'
    wrap it into HasRef / DefaultRef -- same shape, distinct classes, so the
    aggregate assembler dispatches by type, never by provenance.

-------------------------------------------------------------------------------
G-4  BRACKET-CONDITION GUARD AS A TRANSPARENT ALTERNATIVE TO A LUAU GUARD (D-1)
-------------------------------------------------------------------------------
PROBLEM
    A Luau guard span is opaque: the static layer cannot see which members it
    reads, and a trace cannot attribute a fired guard to a subcondition -- against
    the reviewer-attention principle.
DECISION
    A second guard form, a bracket condition: a boolean algebra of comparisons
    over the triggering event's members, building an explicit Condition tree the
    static layer can validate. The Luau guard is RETAINED, not replaced -- the
    bracket form is the transparent path for the common case, Luau the escape
    hatch for anything computed. The two coexist on a guard position.
COST / MITIGATION
    Reserved words ('and'/'or'/'not'), six comparison operators, and '['/']' as
    new tokens -- the standard keyword cost, matched on word boundaries.
    Expressiveness ceiling: the algebra cannot express computed terms -- the Luau
    guard remains for those. Two guard node kinds a consumer handles -- but they
    are type-distinguishable (Condition vs OpaqueCode), not shape-spotted.
DEFERRED TO PASS-2
    Binding a member to a declared event member and type-checking a comparison are
    semantic concerns; the parser only builds the tree.

-------------------------------------------------------------------------------
G-5  EFFECT-DEFINITION SIGNATURE; AGGREGATE INHERITANCE VIA 'is:'  (D-2, D-3)
-------------------------------------------------------------------------------
DECISION
    Effect-def takes the same <signature> a cause-def uses, so an effect bundle
    parameterises the way a cause can; EffectDef and CauseDef become structurally
    parallel. Zero-or-more 'is: <base>' statements after an aggregate's signature
    record inheritance bases, collected in source order onto the aggregate node.
COST
    Inheritance is non-local: understanding a derived aggregate requires holding
    its bases in mind -- the reviewer-attention cost 'has:' composition avoids.
MITIGATION
    The PARSER only records base names; ALL inheritance semantics (additive vs
    override, collisions, linearization) are deferred to pass 2 (semantic D-14
    resolves bases and checks reactor category; full semantics undefined until the
    runtime object model defines what a derived machine IS).

-------------------------------------------------------------------------------
G-6  EFFECT VERBS ARE TRAILING-COLON KEYWORDS: spawn:/unspawn:/arm:  (D-8)
-------------------------------------------------------------------------------
PROBLEM
    The verbs were sigils ('+!' spawn, '-!' unspawn, '!' arm) -- the only
    punctuation-verbs in a language whose every other connective is a trailing-
    colon keyword. The clockwork construct (G-7) made the cost acute: a clockwork
    body carries these as BARE commands with no '=>', so a line opening with '+!'
    is cryptic punctuation alone.
DECISION
    'spawn: T(args) [in: C [via: k]]', 'unspawn: T', 'arm: M(args)'. One spelling
    per concept on BOTH planes (a causality effect after '=>' and a bare clockwork
    command). The AST node names (Spawn, Unspawn, ModeArming) were already
    keyword-aligned, so only the grammar terminals and the prose moved.
COST / MITIGATION
    GOOD churn on every recording rendering an effect verb (edit-time, never
    fabricated). The lexer SHRINKS: two punctuation tokens leave the symbol tier
    and the '+!'-vs-'+' longest-first concern vanishes.
GRAVEYARD
    Keeping '+!' in effects and 'spawn:' in clockworks: two spellings for one
    concept, the inverse of one-noun-per-entity.

-------------------------------------------------------------------------------
G-7  THE 'clockwork' CONSTRUCT: a tick-scripted stimulus actor  (D-11, renamed D-12)
-------------------------------------------------------------------------------
(The NAME rationale is root X-7. This entry owns the SHAPE.)
PROBLEM
    A golden-master test needs a deterministic stimulus. With no in-language
    construct the author writes stimulus by hand in Luau -- outside the
    transparent plane and its checks.
DECISION
    'clockwork: <signature> on: <cause> <elm-clockwork>+ :end'. The 'on:' target
    reuses the full <cause> (trigger + optional guard, the heartbeat shape); pass
    2 resolves the trigger to kind CLOCK. The signature parameters ARE the
    instance members, read through the 'cw' self-binding (the counterpart of
    sm/mg). init/deinit as on a state machine; no 'is:' bases. The script is the
    lifetime: last step done -> deinit -> existence ends.
    TICK LAW. Only a PACED event emission consumes a tick; every other step is
    tick-free (the bare commands, instant:, wait:, select:, the control heads).
    'instant: EVENT(args)' injects one event into the CURRENT queue at the present
    instant -- tick-free, off the beat; the weighty keyword warns that instant
    injection pours dynamics into a running cascade. 'wait: <cause> (=> effect)*'
    suspends until the cause fires, the optional tail running co-temporally with
    'e' bound; 'select: <wait>+ :end' is first-of-many. Control frames if/elif/
    else (one :end per chain) and while (its own :end) reuse <guard>. After a wait
    fires, the clockwork resumes at the NEXT tick of its own clock.
    FENCE. The imperative constructs are legal ONLY inside a clockwork body --
    structurally, the grammar admits them in the clockwork step rule alone.
COST / MITIGATION (the determinism the resumption rests on)
    Resuming only at the clockwork's own ticks (the wait tail the sole co-temporal
    exception) keeps every scripted emission attributable to a tick, so a
    recording is a pure function of the trace and the clock periods.
GRAVEYARD
    - Co-temporal continuation after a wait: would interleave tick-free commands
      with the delivering cascade, making dispatch position a scheduler subtlety
      the recording depends on.
    - A '++' tick sigil: there is none; consuming a tick is a property of being an
      emission, not of a marker.
    - 'and:' / 'flush:' co-temporal frame: dropped; same-instant injection is
      per-event via 'instant:'.
    - 'or:' for shared-tail multi-wait: dropped for 'select:'.
    - Emission via a marked verb or a retained '=>': '=>' means "it follows that"
      (causality); a clockwork step is a command, so the bare event-spec IS the
      emission.

-------------------------------------------------------------------------------
G-8  'cause:' RETURNS WITH A MANDATORY 'for:' EVENT BINDING  (semantic D-6 -> D-8)
-------------------------------------------------------------------------------
(Surface decided in the semantic round; installed in the grammar.)
PROBLEM
    A CauseDef that bundled the trigger with the guard left a rule using a
    CauseRef with no locally visible trigger, so 'e.member' in its effects could
    only be checked through the referenced definition.
DECISION
    A definition binds its event INTO itself, statically:
    'cause: TOO_HOT(limit:int) for: TEMPERATURE & [ e.temp > limit ]'. 'for:'
    names the event (resolved by the ordinary rule, not parameterisable, (A):
    defined before the cause def). Cause definitions are themselves (A). The guard
    is MANDATORY and introduced by '&', so the def reads exactly like the use site.
    The def body is a concrete guard only (Luau span or bracket condition), never
    another cause-ref -- no alias chains.
GRAVEYARD
    - 'condition:' abstracting only the guard (an intermediate semantic D-6
      decision): superseded BEFORE implementation -- a free-floating predicate has
      no event to be checked against; paper-only churn, no code ever existed.
    - Requiring at least one '.member' in a cause def's guard: dropped; a
      variable-only guard ('& [ GHOSTS_AT_HOME == 1 ]') is legitimate.
CONSEQUENCE
    'until: TOO_HOT(75)' is legal -- the run closes on the def's event gated by the
    def's guard.

-------------------------------------------------------------------------------
G-9  THE EXPRESSION BAND: TWO PRECEDENCE LADDERS, GUARDED MUTATIONS  (D-13)
-------------------------------------------------------------------------------
DECISION
    The bracket-condition grammar grows into two LL(2) precedence ladders with an
    explicit, asymmetric crossing:
      cond ladder:   or/nor < xor/nxor < and/nand < not < comparison;
      algebr ladder: shl:/shr: < +/- < * < unary-minus < atom;
      the sole num->bool crossing is <comparison>; the sole bool->num crossing is
      the '?'-bridge ('? <cond> then: <algebr> else: <algebr>').
    '[ ]' groups conditions, '( )' groups algebra -- the bracket names the world.
    <rvalue> folds into <algebr> (arguments are full expressions). Four
    clockwork-fenced mutation statements: 'gets:' (assign), 'incr:'/'decr:'
    (saturating step), and 'recip:' (guarded reciprocal). Reads are GLOBAL (every
    guard); the four mutations are clockwork-only.
RATIONALE
    [ ] vs ( ) splits the two worlds so the parser never decides at '(' which
    ladder it is in (a real LL(2) conflict otherwise) and makes the type boundary
    syntactic. Numbers are UNSIGNED; negation is the unary-minus operator -- a
    signed literal makes binary '-' ambiguous (maximal-munch lexes 'x - 2' as
    'x' '(-2)'); carving '+'/'-' as their own atoms removes it. shl:/shr: are
    keywords so '>>' never collides with nested 'container<...>' closes. ONE
    BinOp / ONE UnOp serve both ladders (the operator read verbatim); a two-
    operator level (or/nor) cannot be an op-by-level n-ary node, so the
    binary-with-explicit-op shape subsumes the retired BoolOp/Not. Mutations are
    clockwork-fenced so every write has a tick-anchored time; reads are not, so
    the ladder stays global. 'by:' introduces the incr/decr amount because a bare
    optional '[<algebr>]' collides with the next (also name-led) statement under
    LL(2).
GRAVEYARD
    - A '/' operator: a silent div-by-zero / int-vs-float liability. 'recip:' with
      a MANDATORY 'else:' zero-branch is the only division -- total by
      construction, the zero spark kept prominent; the operand promotes to float
      (the one implicit-promotion site).
    - 'recip:' as a general rvalue: the zero-branch is control flow and would drag
      a ':end' block into the expression grammar.
    - Signed number literals; '( )' for both worlds; bracketing unary minus -- each
      buys no safety and either reintroduces the '(' conflict or the binary-'-'
      ambiguity.
NOTE (shared-walker fix)
    The bridge/paren cycle makes OR rules where every branch can re-enter an
    active rule, so the canonical and budget-spent walker fallbacks choose the
    shortest-derivation branch (min_terminal_distance) instead of branch[0], and
    WalkContext.active is a Counter so a rule re-entered through a cycle stays
    marked until its own frame exits.

-------------------------------------------------------------------------------
G-10  COMPARISON OPERATORS SHARE THE CONTAINER '<' / '>' TERMINAL  (D-4)
-------------------------------------------------------------------------------
DECISION
    One captured terminal per lexeme: the comparison rule and the container
    type-parameter rule both reference the same t_op_lt / t_op_gt. Two terminals
    for one lexeme (a bare-string '<' beside a captured '<') is the latent bug --
    the lexer would emit two competing patterns -- not the fix.
COST
    The container type-param rule carries the now-captured '<' / '>' tokens in its
    frame; its constructor slices positionally and ignores them -- inert.

-------------------------------------------------------------------------------
G-11  ADVISORY ROLE HINTS ON TERMINALS AND REFERENCES  (D-10)
-------------------------------------------------------------------------------
(The MECHANISM -- Tagged_Spec, the checked ROLES vocabulary -- is core C-2. This
entry owns the LANGUAGE decision: which positions are tagged.)
DECISION
    An optional, advisory role hint, a plain string, attaches two ways: on a
    terminal via a call ('t_re_id("event")') and on a reference via a suffix
    ('"<name-dotted(clock)>"'). It states what the author INTENDS a name to
    resolve to and hands pass 2 a per-position expectation, walked by position.
    It is recorded on the compiled grammar (the transparent Tagged_Spec), renders
    in repr for legibility, and is PURELY advisory: the parser core never acts on
    it, and pass 2's binding kind checks are the enforcement, never the hint.
COST / MITIGATION
    A small extension to the reference-string parser and a call operator on the
    terminal spec; the grammar-walking test support gains one transparent case.
INVARIANT (the crux that makes the hint safe)
    The hint is NON-IDENTITY: it never enters a terminal's _name(), never affects
    lexing, interning, or the FIRST_2 analysis, and adds nothing to the value
    stream. If it entered identity, 't_re_id("event")' and 't_re_id("clock")'
    would intern as different terminals and fracture one-keyword-one-token, and
    '<name-dotted(event)>' and '<name-dotted(clock)>' would become different
    references.
GRAVEYARD
    Folding the load-bearing opaque MODE and the advisory hint into one 'role'
    field: rejected. The mode changes what the oracle DOES and MUST be in
    identity; the hint MUST NOT be. One field cannot be both.

-------------------------------------------------------------------------------
G-12  'until switched' REMOVED; STATE BLOCKS END STRUCTURALLY  (R-2)
-------------------------------------------------------------------------------
DECISION
    The 'until switched' state-closer is gone and 'switched' is no longer a
    keyword. A <state> block ends structurally (at the next state-machine element
    or ':end'); its trailing 'until' causes are optional (STAR, not PLUS). The
    sibling-armed transition 'switched' spelled is now implicit in the state
    machine's mutual-exclusion semantics; it was never a runtime event. This stays
    LL(1): 'until:' is not in FOLLOW(state).
MIGRATION CAVEAT (not special-cased)
    With 'switched' no longer a keyword, an old 'until: switched' lexes 'switched'
    as an ordinary identifier and parses as "until an event named switched" --
    silently. Authors updating old rule files must remove the clause.

-------------------------------------------------------------------------------
G-13  OPAQUE-SPAN MODE IS A CORE-OWNED E_SpanMode ENUM  (D-7, D-9)
-------------------------------------------------------------------------------
The span positions a rule file names (condition / expression / lvalue /
statement-block) are a fact of the RULE LANGUAGE, not of Luau. Core owns them as
E_SpanMode; grammar.py mints 'T.opaque(E_SpanMode.CONDITION)' from core and
imports no embedded language. The opaque terminal still carries the mode unread
to the oracle; only its defining module moved (luau -> core). Closes the last
parser->luau import. Every enum carries the 'E_' prefix.

-------------------------------------------------------------------------------
G-14  dict<K,V> / list<V> REPLACE THE GENERIC container<...>  (D-14)
-------------------------------------------------------------------------------
Two purpose-named container kinds with mandatory, fixed type-parameter arities
replace one generic 'container<...>'. A <type> parameter is a built-in scalar, a
named type, or a nested dict/list, so 'list<dict<...>>' nests (relies on '>>'
NOT being one token). The optional 'by:' storage accessor moves off the type
onto the DECLARATION level, keeping <type-dict>/<type-list> pure type
expressions that nest without a dangling tail. Mandatory parameters: a bare
'list'/'dict' has no meaning the resolver could fill; the old optionality existed
only to make one keyword serve both arities -- two keywords remove it.

-------------------------------------------------------------------------------
G-15  STANDARD MEMBER FUNCTIONS ON BUILT-IN TYPES  (D-15)
-------------------------------------------------------------------------------
Operands gain a postfix '.id' (member) / '.id(args)' (method) form, chaining via
a postfix STAR. Member-vs-call splits on the trailing '(' -- a clean 2-token
decision once '.id' is left-factored into one <postfix> rule. The separator is
'.', not Luau's ':' (the lexer's 'id:' tier would mis-lex 'e.tags:has(..)'); the
transpiler maps '.method' to ':method' where self is needed. The method
CATALOGUE per receiver type is NOT in the grammar -- it is a pass-2 table; the
grammar admits any '.id(args)'. This is what lets the opaque Luau guard be
removed: the predicates the old '& { ... }' demonstrated are now method calls in
transparent bracket conditions.

-------------------------------------------------------------------------------
G-16  'do:' IS A CODE BLOCK; SPAWN/WRITES ARE CLOCKWORK-ONLY  (D-16, D-17)
-------------------------------------------------------------------------------
A statement-block site is a CODE BLOCK: opaque Luau '{ ... }' OR 'do: <step>+
:end'. 'spawn:' leaves <effect> and container writes were never effects -- these
imperative, state-mutating statements run only from a clockwork (named, or the
anonymous 'do:' sweep). The sweep stands wherever Luau statements stand (a
mutation effect, init:, deinit:), reached through <mutation>, so it composes in
an effect list; the causality stays the plain effect list. A 'do:' body is
heartbeat-free -- one sweep per cause. The one-sweep restriction (which steps are
fatal without a tick) is a pass-2 table keyed by an advisory role hint, not a
grammar rule. (D-16 first placed 'do:' as a causality tail; D-17 made it a code
block at every statement-block site -- strictly more general, removing the
init:/deinit: asymmetry.)

-------------------------------------------------------------------------------
G-17  GRAMMAR SUBSPACES AND PATH NAMESPACES  (D-20, D-21, D-22)
-------------------------------------------------------------------------------
A grammar value may be a SUBSPACE: a TOP-keyed dict whose other keys are member
rules, nesting arbitrarily. Inside a subspace the category prefix drops
('cond-xor' authored 'xor'); the 'cond/' path supplies it. Every rule has a
QUALIFIED name ('cond/xor'); a qualified reference resolves from any scope, a
bare reference is scope-local (walks up enclosing subspaces to the root, first
hit wins) -- so a private member of an unrelated subspace is simply not in scope,
the natural privacy. flatten() lowers a nested grammar to the flat
qualified-keyed map the engine compiles, plus each rule's body-resolution scope;
the engine owns flatten (Grammar.__init__ calls it). Four subspaces today
(algebr, cond, declaration, step, with step/spawn nested). A TOP rule's body
resolves at the MEMBER path, not the root.
    Privacy is a RESOLUTION property (D-21), not the hard encapsulation GATE D-20
    first shipped -- the two could not both stand; the namespace model is more
    flexible and reaches in by spelling the path. 'clockwork' stays a flat root
    rule because its step vocabulary is shared (do-sweep, elm-clockwork); the
    clean boundary is the 'step' subspace, not 'clockwork'.

-------------------------------------------------------------------------------
G-18  DIVISION '/' WITH AN 'undef:' MATH FALLBACK; FREE CALLS  (D-23, D-24)
-------------------------------------------------------------------------------
'/' joins the multiplicative ladder beside '*'. A division can be undefined, so
an expression carrying a '/' needs a fallback: the parser accepts ONE trailing
'undef:' on a whole expression (algebr TOP = ("<shift>", ["undef:", "<shift>"]))
and builds an Expr{body, fallback} only when it fired. Pass 2 makes 'undef:'
mandatory iff a '/' appears and dead otherwise. The fallback keyword is 'undef:',
NOT 'else:' -- naming the cause (an operation with no defined result) and
structurally unable to collide with the three existing 'else:' meanings (bridge,
recip, clockwork if/else). That distinctness removes the greedy-parse collision
at the source, so bridge and recip-rhs arms stay full '<algebr>' and may each
carry their own 'undef:'. A sub-expression needing its own fallback uses the
parens that already exist.

===============================================================================
PART III -- FRONT-END MACHINERY, CONTINUED  (CST access + the router family)
===============================================================================

-------------------------------------------------------------------------------
A-8  ROLE-KEYED CHILD ACCESS FOR SEQ FACTORIES  (D-18)
-------------------------------------------------------------------------------
A SEQ factory reads a child by ROLE NAME ('node["key"]'), not by position.
Captured discriminants survive into the value frame and occupy slots, so
positional indices and grammar shape were two hand-synced representations -- a
captured-terminal insert shifted every later index silently (repeated off-by-N
bugs). The role tags already exist (the advisory pass-2 hints); D-18 makes the
same tag reachable from the built node via a PARALLEL 'SEQ_Node.roles' tuple
(one entry per surviving position, tag or None). The value stream is untouched --
no value wrapper (what the advisory-hint decision deliberately rejected); the
role is a sidecar on the one node kind with sibling positions to disambiguate.
Only SEQ carries roles (OR has one child; PLUS/STAR are homogeneous).

-------------------------------------------------------------------------------
A-9  THE AST-MAP ROUTER FAMILY AND THE OPAQUE-PRODUCT LAW  (D-19)
-------------------------------------------------------------------------------
The node kind a rule's factory PRODUCES is not knowable before runtime -- an OR
rule yields a different kind per branch fired. So a produced AST node carries NO
operator-interface contract upward: a parent takes it as an opaque typed value
and reads its own fields, never through a shape accessor. This is the actual
ROOT CAUSE of the no-fakery principle (corrected from the symptom "a parent never
queries internals"): the operator interface lives only on the generic CST node,
before transformation, as the contract between a rule's CST node and that same
rule's factory.
    What IS knowable at load is a rule's OWN top shape (rule_shape() ->
    SHAPE_OR/SEQ/PLUS/...), so the gate may check that. An AST_MAP value is a
    single factory for SEQ/PLUS and a ROUTER for the branching shapes (OrMap
    routes on fired branch -- int index, str role, or a tuple grouping). A
    grammar MARKER (the combinator tokens) is distinct from the operator
    interface: the marker tells which CST node a rule produces; the interface is
    a property of that node. Earlier sketches wired the two together; they are
    joined only by the interpretation step.
