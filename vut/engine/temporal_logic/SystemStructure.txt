# 2. System Structure & Interaction Model

The Temporal Logic Engine acts as the central brain of the test environment,
capable of both monitoring the System Under Test (SUT) and actively driving it.

### 2.1 The Event Stream (Input)

The fundamental unit of information is the **Event**.

* **The Stream:** The SUT generates a linear sequence of events which serves as
                  the input to the Engine.

* **Chronology:** The Stream is strictly ordered. The Engine processes events 
                  sequentially, mapping them to discrete logical time steps.

### 2.2 The Rule Space (Logic)

The Tester defines the behavior in the **Rule Space**.

* **Evaluation:** As events arrive, the Rule Space evaluates them against 
                  the defined Rules.

* **State:** The Rule Space maintains the lifecycle state of all active Rules 
             and the historical record of events.

             Additionally, scripting allows for mirroring of the or 
             following the SUT.

### 2.3 The Dual Time Model

The engine distinguishes between physical reporting and logical operation.

* **Physical Time (Time Steps):** Events are bound to real-world timestamps reported by the SUT.

* **Logical Time (The Jiffy):** The Engine operates in **Jiffies**—infinitesimal logical slices. Even if the SUT reports two events at the exact same nanosecond, the Engine processes them in separate, sequential Jiffies. This ensures that the reaction to an event (e.g., a Rule violation or a Command injection) is logically distinct from the event itself.

### 2.4 The Stimulation Channel (Output)

Unlike a passive monitor, the Engine can influence the SUT to drive test scenarios or recover from errors.

* **Injection:** The Rule Space can emit **Command Events** back to the SUT.

* **Triggers:** Commands are typically triggered by:

* **Action Blocks:** Explicit instructions in the test script (e.g., `inject(RESET_CMD)`).

* **Scope Handlers:** Automatically triggered on Scope entry/exit (e.g., `on_entry: inject(START_TRANSACTION)`).

* **Violation Handling:** Defensive actions triggered when a rule fails (e.g., "Emergency Stop").

* **Causality:** A Command Event emitted in Jiffy is consumed by the SUT and 
                 results in new Input Events in a new non-jiffy time frame.
