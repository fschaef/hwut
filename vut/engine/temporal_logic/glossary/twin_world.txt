TWIN WORLD
==========

Definition:

    A 'TWIN WORLD' is a stateful simulation implemented by the test 
    designed. It provides data context for the temporal evolvement 
    of the test. 

It may hosts a synchronous "Digital Twin" of the WORLD, authorative boundaries,
and support functions to judge the WORLD behavior. It evolves through Jiffies.
It may act as an Oracle (quote), but its functionalities exceed it.

1. DATA ENCAPSULATION:

   The "Twin World contains "Reference Agents"—Lua objects that mirror WORLD
   entities. Each agent maintains its own internal variables, state machines,
   and validation logic.

2. SYNCHRONOUS EVOLVEMENT:

   Every state change in TWIN WORLD occurs within the Jiffy Calculus (t + ε).
   This ensures the "Virtual State" is always logically aligned with the
   "Reported Event," preventing race conditions between the monitor and the
   reference model.

3. PREDICATE DELEGATION:

   Temporal Guards delegate data-heavy assertions to TWIN WORLD Agents. A Guard
   enforces the "When" (Sequence), while the TWIN WORLD Agent enforces the
   "What" (Integrity).

4. FEEDBACK LOOP (META-EVENTS):

   TWIN WORLD can influence the Rule Space by synthesizing "State-Triggered
   Events." When a virtual agent's internal logic detects a boundary breach
   (e.g., { npc.power > max }), it injects a new event into the next Jiffy.

5. INJECTION:

   The TWIN WORLD has direct access to the INJECTION hub. This allows Reference
   Agents to not only monitor but also act—injecting command events or stimuli
   back into the WORLD to drive the test toward specific edge cases or to
   respond to detected behaviors.
