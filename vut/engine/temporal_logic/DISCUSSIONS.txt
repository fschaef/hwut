LIVE QUESTIONS

  L-7  SEMANTIC LAYER -- symbol table, name resolution, validation. DESIGNED,
       NOT YET BUILT. Parser produces name-bearing AST only. The sub-questions
       below are now settled; design recorded in semantic/DISCUSSIONS.txt
       (L-7..L-17) and semantic/README.txt. Build is the next code step.
         - symbol-table shape: scope tree mirroring all nesting; one undivided
           name->symbol map per scope (semantic L-7, L-7d).
         - coexisting names: ONE shell -- modes, mode groups, state machines,
           instances, AND events compete in it; any clash is an error
           (semantic L-7d, generalizing R-37).
         - resolution: innermost-out lexical search on the head segment, then
           strict descent for the tail; dot separator, matching Luau
           (semantic L-7b, L-7c).
         - include mounting: parse-once cached, fresh scope tree per mount,
           asymmetric visibility by the parent=None graft, ordered cycle chain
           (semantic L-8, L-9, L-10).
         - unspawn target: static resolve + INSTANCE-kind check; liveness is
           runtime (semantic L-11, L-12).
       Constraints to enforce: <=1 init / <=1 deinit per reactor/aggregate;
       <=1 default per state machine; every state until-run ends 'until
       switched'; default -> defined member or VOID; every spawn/unspawn/has:/
       default target resolves; one undivided name shell forbids all in-scope
       clashes. Spawn-form checks added by R-39: singleton ref carries no
       parentheses; 'in {lvalue}' container is opaque (not resolved).

  L-6  CODE GENERATION -- AST -> target (Lua) emitter. NOT YET BUILT; after
       L-7. Tree-walk over the (validated) AST. Open: what "pure Lua" output
       strips (trace/report harness? sm/mode/event bindings?). Provides the
       serializer that L-5 needs.

  L-5  ROUND-TRIP MONKEY TEST -- parse -> serialize -> re-parse -> compare.
       Upgrades the fuzz suite from liveness/stability to correctness. Blocked
       on the L-6 serializer. (A lightweight form already exists: monkey
       '--debug' renders the walk to real source, re-lexes it, confirms the AST
       matches structurally.)

  L-4  GUARD/BODY CONVENIENCE LIBRARY. Helpers injected into the Luau sandbox.
       Further additions deferred (time_since(Event), vector math). Engine-
       provided, not third-party (portability).

  L-3  HWUT INTEGRATION DETAIL. Diff format, error reporting. Owned by HWUT

-------------------------------------------------------------------------------
DEFERRED / REJECTED  --  reasoning recorded so it is not lost
-------------------------------------------------------------------------------

  D-7  FILE SELF-NAMING ('namespace earth.europe' header in the included
       file). REJECTED. Python's lesson: the included unit is placement-
       agnostic; the INCLUDING side chooses the mount point. Self-naming
       couples a file to one location, collides when two files claim the same
       path, and blocks mounting one file at two places. See R-36.

  D-6  PARTIAL / REVERSE-ORDER NAMESPACE CLOSE ('close berlin.germany',
       'open ... in europe', dangling-at-EOF). CONSIDERED, then DROPPED in
       favour of strict balanced open/close. Partial close turns open/close
       from brackets into a cursor over a path -- breaks the recursive
       containment tree and the stackless walk that assumes balance. Strict
       bracketing is sound and already correct. See R-35.

  D-5  CROSS-PRODUCT POSITIVE COVERAGE. When a rule has several variadic
       points, vary them one at a time, NOT the cross-product. No value add;
       cross-product explodes case count for no extra defect class. See R-33.

  D-1  INDIRECT / COMPUTED ARMING ('arm[expr]'). NOT in v1. A computed ARM
       target does not threaten termination (arming only gates edges a
       reactor's rules already contribute, never adds an edge) -- so if
       revisited, that asymmetry vs computed EMIT is the justification.
       Preferred alternative for data fan-out: parameterized reactors (R-15)
       -- name literal, instance identity is data.

  D-2  CONDITIONAL ARMING SUGAR ('if not armed yet'). Superseded by the
       'armed()' guard builtin (R-17). No dedicated syntax.

  D-3  OVERLAPPING-WINDOW COUNTER. Subsumed by parameterized reactors (R-15):
       concurrent instances are the normal case now.

RESOLVED  --  decisions and the reasoning behind them
-------------------------------------------------------------------------------

  R-39  SPAWN MODEL REWORK -- binding-form axis, containers, singletons.
        Supersedes the 'as <name>' / unnamed-singleton surface of R-29/R-31
        (the verbs '!','+!','-!' stand; only the '+!' operand shape changes).
        '+!' now has three forms, decided by shape:
          - bare type name        -> re-init a 'singleton :'-declared instance;
                                      parentheses here are a SYNTAX ERROR.
          - type name '(' args ')' -> spawn into the per-kind DEFAULT container.
          - ... 'in' '{' lvalue '}' -> spawn into the named container.
        '-!' = END EXISTENCE (runs 'deinit', releases from the container), not
        merely "remove a named instance".
        Rationale:
          - 'as <name>' conflated CREATE with BIND-TO-SLOT; on a singleton that
            is contradictory. Identity now comes from how a type is DECLARED
            (singleton => by name) or from the CONTAINER (else), not from a
            name pinned at the spawn site. 'as' dropped.
          - double-creation handled WHERE IT BELONGS, the container: the
            default container is a MultiReactorContainer whose accept rule
            rejects a parameterisation already present (identity = parameters,
            R-29) -- so an anonymous '+! R(args)' stays idempotent exactly as a
            mode re-arm. A singleton is the named ScalarReactorContainer case.
          - container = "a structure that holds instances"; one
            (ScalarReactorContainer) or many (MultiReactorContainer). Accept is
            a mutexed three-call slot protocol slot_reserve/slot_set/slot_free
            (reserve returns an int key or NO_SLOT; construct runs after a
            successful reserve, OUTSIDE the lock; a rejected reserve constructs
            nothing; slot_free is idempotent). Mutex on the reserve alone
            suffices (no global lock through construct). Two base classes added
            to bootstrap.lua (3e).
          - 'in {lvalue}' is OPAQUE Luau (R-6, R-23): the parser does not
            resolve it, the semantic layer does not check it is a container;
            container-ness is a run-time fact. Cost: a typo'd container is a
            run-time error, not static -- the same opacity every Luau span
            already carries, not a new hole. REJECTED: requiring 'box' to be a
            declared, kind-known container -- would drag the static line into
            Luau lvalue space.
          - construct-inside-vs-outside-the-mutex: OUTSIDE. Holding the lock
            through a possibly-blocking construct (sprite, socket) would
            serialize all spawns; the reserve marks the slot taken, construct
            then runs unlocked, slot_set commits.
        Binding 'mg' ADDED: the mode-group self-binding, symmetric to 'sm'
        (state machine). Was missing -- a mode group's init/deinit had no name
        for itself while a state machine's did. Exactly one of 'sm'/'mg' is in
        scope, decided by the enclosing aggregate kind.
        AST: Spawn loses 'inst', gains 'has_parens' + opaque 'container';
        Singleton TopLevel node added. Grammar: '<spawn>' rewritten (parens
        optional, optional 'in {luau}'), '<singleton-def>' added; lexer gains
        KW_SINGLETON, KW_IN. Container protocol is a RUNTIME contract (bootstrap
        + codegen), not a static-layer type.
        -> SYNTAX A.1, A.2.1, <spawn>/<singleton-def>/<unspawn>; README
           (glossary, BINDINGS, AGGREGATE SPAWNING); luau/README runtime
           substrate; luau/bootstrap (3d, 3e); parser ast_nodes/grammar/lexer;
           cf. R-29 (identity = parameters, retained as the default container's
           accept rule), R-31 (verb set retained), R-6/R-23 (Luau opacity).

  R-38  INCLUDE -- 'include "<file>" as <dotted-name>'. Mounts another file's
        namespace at a path the INCLUDING file chooses. Python-model:
          - included file placement-agnostic, does not name its own home;
          - same file mountable at different paths, no self-naming collision;
          - internal refs self-relative (resolve within the file, then
            outward to its own scopes), NOT against the mounting scope;
          - load-time mount (parse file once to its own table, mount the
            unit), not textual splice.
        Parser RECORDS only (filename + mount path) as an Include node; resolve
        / parse / mount is L-7's job. Grammar: one keyword, one rule, one
        node; LL(1) holds (FIRST {include} disjoint). 'as' mandatory (explicit
        placement). 38 grammar rules.
        -> SYNTAX A.1, A.2.8; README glossary.

  R-37  NAMESPACES -- 'open <dotted-name> ... close', strictly balanced.
        Several independent namespaces, unrestricted nesting. Dotted name nests
        many levels in one 'open' ('open world.europe.berlin', not four
        'open's); bare 'close' (matching open unambiguous from nesting). Body
        is recursive <top-level>+, so a namespace contains any declaration incl.
        nested open/close. Names scoped to the namespace they are defined in;
        'as'-instance names likewise. Modes and state machines share ONE
        namespace; no mode may share a state-machine name (rest of the
        namespace question is L-7). The file itself is the implicit root
        namespace.
        -> SYNTAX A.1, A.2.7; README.

  R-36  INCLUDE DIRECTION fixed before building: caller-decides-placement,
        included file lexically self-contained. See R-38 for the mechanism and
        D-7 for the rejected self-naming alternative.

  R-35  STRICT BALANCED OPEN/CLOSE. Reaffirmed after considering partial close
        (D-6). open/close are brackets; close closes exactly what its matching
        open opened. Keeps the containment tree and the stackless walk valid.

  R-34  STACKLESS ENGINE. The LL(1) interpreter walks the grammar on an
        explicit work-stack + frame-stack, not Python recursion. Motivated by
        unrestricted namespace nesting: the recursive walker overflowed at ~100
        nested 'open's (depth_bomb FAIL 100); stackless parses 20000 in <1s.
        Rewrite preserved behaviour exactly -- of 91 recordings, only depth_bomb
        changed (FAIL->PASS); the other 90 (incl. all error-path and fuzz
        trees) reproduced bit-for-bit, proving no drift. Chose full-interpreter
        conversion (Scope 2) over patching only the namespace loop (Scope 1) to
        avoid an inhomogeneous engine that would complicate later additions.
        -> parser/README (A), (C).

  R-33  TEST ARCHITECTURE -- four HWUT drivers, choices derived from the
        compiled grammar so new rules are covered automatically:
          - cover-syntax-tree: POSITIVE, one valid case per rule shape
            (PLUS->1,2; STAR->0,1,2; OPT->absent,present; one variadic point
            at a time, no cross-product per D-5); prints the input fragment +
            AST; node_coverage asserts every node type is built.
          - cover-negative: NEGATIVE, one rule in isolation fed truncation /
            required-omission / junk-head; records diagnostics + recovery.
          - monkey-fuzz: deterministic grammar walk (DeterministicStream),
            profiles deep/wide/luau/balanced/states (seed + weights), depth-
            budgeted to terminate, capped for reviewable trees; recording is
            the assertion (deterministic AST). depth_bomb = stackless
            acceptance test. coverage = aggregate, asserts 38/38 rules and
            22/22 tree node types reached (transient InitBlock/DeinitBlock
            excluded -- sorted into parent init/deinit, never persist).
            '--debug' renders walk to real source + re-lexes (lightweight
            round-trip, ahead of L-5).
        Monkey is a stack-safety + determinism + breadth net, NOT a
        correctness oracle (a wrong tree records as "wrong but stable"); full
        correctness waits on L-5.
        -> parser/README (F).

  R-32  TABLE-DRIVEN LL(1) PARSER replaces hand-written recursive descent
        (supersedes R-4's control-plane parser). Grammar declared once as data
        (combinators SEQ/ALT/OPT/PLUS/STAR + terminals + '{luau:ROLE}'); a
        generic driver interprets it; per-rule reduce actions build the AST.
        LL(1) checked at compile time (shared-FIRST ALT branches = fatal
        LL1ConflictError), so a grammar edit that breaks LL(1) fails loud.
        Adding a construct = a grammar edit, not new driver code.
        -> parser/README (B), (C).

  R-31  AGGREGATE-ARMING VERBS -- '!' arm a single mode, '+!' spawn a named
        aggregate, '-!' unspawn one. Symmetric sigil family, all Lua-safe (no
        clash with comments '##', '-7' negative numbers, or operators).
        Replaced earlier '+'/'++'. '-!' (unspawn) added: removes a spawned
        aggregate; operand is a reference by name (bare/dotted) -- only a named
        entity can be unspawned (target validity = L-7). Earlier '--' for
        unspawn REJECTED: clashes visually with the Lua line comment.
        -> SYNTAX A.1, A.2; README.

  R-30  TERMINATORS -- 'end' closes mode_group and state_machine; causalities
        are SELF-DELIMITING (no terminator). Supersedes R-28's 'off'.
          - 'off' removed. A causality is 'on <cause> (=> <effect>)+'; each
            effect is '=>'-led, so the loop ends at the first non-'=>' token.
            The follower (top-level keyword / member keyword / 'until' / 'end'
            / EOF) is never '=>', so the rule is unambiguously self-delimiting
            (proven: effect-loop continuation token is ARROW). No closing
            keyword needed.
          - aggregates close with 'end', NOT their own 'until' causes. This is
            what makes an inline member mode in a mode_group LL(1)-parseable:
            a member mode's '(until <cause>)+' run is then followed by 'end'
            (or a member keyword), never by another 'until' that could belong
            to the group -- the boundary is decidable with one token. Modes
            still close with '(until <cause>)+'; states with 'until switched'
            (a recursive tail left-factored on 'until' so 'switched' terminates
            the run without two-token lookahead).
          - missing inline-member-in-group support, the four SYNTAX-vs-parser
            divergences, and the trigger fix ('switched' is the state closer
            only, not a general trigger) all resolved in the same pass.
        -> SYNTAX throughout; README; parser/README (B).

  R-29  LIFECYCLE & QUERY CONSOLIDATION. BEGIN/END trace frame (END mandatory,
        engine-validated; BEGIN implicit). CLOCK: synthetic-time emitter, data-
        plane only, fires between real events (distinct from rejected R-10
        wakeup queue). construct/destruct per-instance hooks (one-time).
        Idempotent re-arm: identity = parameters only; arming a live instance
        is a silent no-op. Polymorphic comparators; LURKER(args) with
        :any/:all/:none/:empty; GLOBAL_LURKER; tracer.watch.
        (Some surface here later superseded -- 'off' by R-30, the reactor verb
        set by R-31 -- but the lifecycle/query semantics stand.)
        -> README 3,4,5,6,7,9,10.

  R-28  GRAMMAR CONSOLIDATION (historical; surface partly superseded). Uniform
        bindings 'event'/'lurker', '=>' on every consequence, read-only guard
        check, 'Class.create' + 'filter' bootstrap helpers, '!=' and '~='. The
        'off' universal terminator from here is superseded by R-30; the rest
        stands. Enduring principle: a rule's shape and names must not depend on
        context.
        -> README 3-7,9,10; SYNTAX.

  R-23  DATA PLANE = TRANSPILED LUAU run by a standard Luau runtime (supersedes
        the embedded pure-Python Luau of R-4). Rule-file parser still does not
        parse Luau (R-4 line holds); opaque spans delegated to a Luau brace-
        finder helper rather than a fence delimiter (rejected: visual noise on
        the author who reads guards constantly -- cost belongs on the tool).

  R-12  THREE-FILE DOCUMENT SPLIT. README = settled fact. DISCUSSIONS = this
        log. SYNTAX = concrete syntax. Rationale kept in README as brief notes
        so settled decisions are not silently reopened.

  R-11  OBSERVED-TRACE ASSERTIONS NOT A SEPARATE FEATURE. Stream and recorded
        file are indistinguishable to the engine; any ordering/timing property
        is an ordinary rule emitting a violation event. One engine, one mode.

  R-10  PERIODIC CLOCK SIGNAL -- REJECTED. An engine emitting its own TICKs
        would generate a time line, not validate one, and need a wakeup queue.
        Periodicity belongs to whoever produces the input. (Cf. R-29 CLOCK,
        which is data-plane synthetic-time only.)

  R-6   EVENT STRUCTS LIVE IN LUAU; EMISSION DOES NOT. Field values Luau-
        evaluated; the type NAME is static (a cascade-graph edge). Same for arm.

  R-5   ONE-OBJECT-SPACE INVARIANT. One Luau table space; the control-plane
        parser builds no parallel object model. Parser owns FORM, Luau owns
        SUBSTANCE.

  R-4   SPLIT PARSER (control plane vs data plane). Control-plane parser is now
        the table-driven LL(1) engine (R-32), not hand-written descent; data
        plane is transpiled Luau (R-23). "Whole rule file in Luau" rejected: it
        surrenders the static cascade check, domain errors, grammar-as-
        enforcement.

  R-3   WATCHDOG: INSTRUCTION BUDGET, NOT WALL-CLOCK. Same interrupt point on
        any hardware; wall-clock would make verdicts hardware-dependent.

  R-2   TURING-COMPLETE LUAU BODIES; STATIC-NAME LINE. Bodies have full
        sandboxed Luau, but '=>' / arm take statically literal names -- those
        names are cascade-graph edges.

  R-1   CASCADE TERMINATION STATICALLY CHECKABLE. "No event type twice at T"
        makes a cascade finite. With the static-name line every emittable type
        is literal, so the cascade graph is built by static inspection. Cycles
        are not errors.

  R-0   NO CHECK MODE; ONE ENGINE. It runs rules over a time line and produces
        a time line. Verification = HWUT comparing the deterministic report
        against a nominal recording (R-22). One-engine-one-mode stands.
