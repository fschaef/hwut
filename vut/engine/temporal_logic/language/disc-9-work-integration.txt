(C) RULING-NEEDED
------------------------------------------------------------------------------
C-1  RULED (R-34): '=>' REJECTED for named arguments; 'name = value'
     stands (D-28). RESIDUAL, open: the port-map's OUTPUT association --
     '=' cannot say "flows out to"; the form is RESERVED in 12.5 until a
     spelling is ruled.
     Original fork text follows for the review:
     NAMED-ARGUMENT / PORT BINDER: '=>' vs '='.
     Draft (3.0, 8): 'port => value' binds by name; the PORT-MAP form
     dissolves argument/result into port DIRECTION -- one binder serves
     both ('cloud_a => pc1, center => c'); sinks ride it
     ('rejects => kill_sprite'); the one-token law lists '=>'.
     Engine (D-11, settled, exercised): named arguments are 'name = value'
     (elab-main.vut 'boost = 2').
     These cannot coexist for the same act. Options:
       (a) adopt '=>' as THE port binder, retire '=' named args (migrate
           D-11 surface: one fixture, LANGUAGE 2.1);
       (b) keep '=' for inputs, invent a second spelling for output
           binding -- splits the wiring-diagram reading the draft builds
           the port-map on.
     Coordinator lean: (a) -- the documents are authoritative and the
     port-map form structurally needs one direction-neutral binder.
     (Supersedes the earlier todo note that leaned toward keeping '='.)
     Canary note: '=>' as binder inside parens vs the effect marker is
     position-separated; the lexer already orders '=x=>','=>','==','='.

C-2  RULED BY LEAN (R-27, pending FR review): commas within a section,
     sections juxtaposed (the D-23 form governs all panels).
     Original fork text follows for the review:
     PANEL ENTRY SEPARATION AND THE GROUPING SUGAR.
     Draft 2.0: entries stack by newline; a line starting '<name> :'
     inherits the relation verb above (elision, no commas). The
     implemented aspect panel (D-23) is comma-separated. The lexer is
     whitespace-insensitive, so "newline" cannot carry law; the elision
     works only for TYPED entries ('a : float b : float' splits on
     (ID,':'); untyped 'rate retries' does not split).
     Options:
       (i)   commas (as implemented, D-23) -- deviates from the draft's
             written form;
       (ii)  juxtaposition, panels require typed entries -- faithful, but
             outlaws 'knows: rate' untyped;
       (iii) semicolons -- harmonises with the has:-block 'name: type;'.
     Touches works, clockworks, aspects alike. FR rules once for all
     panels.

C-3  'while' IN WORK BODIES.
     Draft bodies use unbounded 'while' (ex. 10, 14). The engine bans
     unbounded loops in command-blocks -- the rationale is INSTANT
     semantics (an effect completes within its instant), not loops per
     se. Proposal to ratify: work bodies are ordered program flow, not
     instant-bound -- 'while' is lawful there; the instant constraint
     applies TRANSITIVELY to works called from effect positions (this is
     parked item 4, synchronous functions, in new clothes). Needs an
     explicit law: which call positions demand instant-boundedness, and
     what the checker verifies.

C-4  RESOLVED (R-29): the composite kind word is 'class', name-first
     ('sprite : class ...'); 'type' spans primitives, classes, specs.
     The draft's 'type: sprite' spelling is superseded.

C-5  BARE 'finish' JUMP.
     Draft 2.4: bare 'finish' jumps to the unique 'finish:' terminal --
     one lexeme as bare word AND colon keyword. Lexically fine (both
     token kinds exist); wants an entry in 1.1's bare-word exception list
     when F-9 lands. Confirm the pair is intended.
