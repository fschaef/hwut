todo-8 -- E_ScopeKind names rule kinds in core (core-purity debt)
=================================================================
DECIDED IN PRINCIPLE (core/ holds no rule-language vocabulary in code);
NOT YET BUILT. Surfaced verifying the D-32 seam.

WHAT
  core/scope_types.py defines E_ScopeKind with members NAMESPACE / MODE_GROUP /
  STATE_MACHINE -- rule-language aggregate names, in core code. Every other core
  module (resolution.py, module_proxy.py, resolved_module.py, program.py) is now
  clean of rule kinds; the join takes them via injected ResolutionPolicy. This
  enum is the last hardcoding.

WHY DEFERRED
  Fixing it is the parked scope_tree engine/policy split (NEXT-CHAT-STARTER: "a
  later clean engine/policy split of resolver+scope_tree is open, NOT urgent").
  build_scopes consumes E_ScopeKind directly; the clean shape is core declaring a
  GENERAL scope-kind tag (e.g. an opaque str/enum the application supplies) and
  semantic/ owning the NAMESPACE/MODE_GROUP/STATE_MACHINE vocabulary -- the same
  tables-declared-in-core / filled-by-application cut as D-32, applied to scope
  kinds. Doing it under D-32 would be scope creep; it is its own change.

SHAPE WHEN BUILT
  - core: E_ScopeKind keeps only GROUND (the one structural kind core needs to
    mark a unit root), or becomes an open tag; the descent already routes on
    ResolutionPolicy.scope_head_kinds, not on E_ScopeKind, so the join is
    unaffected.
  - semantic/: owns the rule scope-kind names; scope_tree.py stamps them.
  - tree-wide terminological invariance on any rename (code, params, docstrings,
    tests, GOOD).
