LANGUAGES, TOOLS, FORMATS -- the coverage roads, and what is witnessed
==============================================================================

THE THREE AXES, AND WHO OWNS WHICH. A LANGUAGE names a registry entry;
the entry lists TOOLS in preference order; 'elect' takes the first the
machine has; the tool's FORMAT names the reader. Fifteen tool names,
seven formats, one record. The record is the unifier -- everything
below dies at harvest.

ON A 'UNIFYING BINARY FORMAT'. The unifying FORMAT exists and is not
binary: the VUT-COVERAGE record -- text, delta-coded, versioned,
measure-tagged, one writer per key space. Its being TEXT is load-
bearing: the GOOD files read as specifications, a record diff is a
legible fact, and 'grep' is a query tool. At these sizes binary buys
nothing and costs inspection. What 'hwutcov' SHOULD name, if anything,
is the unifying EXECUTABLE: one entry point with verbs --

    hwutcov elect <language>          name the tool this machine serves
    hwutcov instrument <build-argv>   amend a build line (the build-
                                      node provision)
    hwutcov probe <executable>        can it REGISTER coverage? refuse
                                      by name before the run spends
    hwutcov run <argv>                wrap where the road wraps
    hwutcov report <work-dir>         the named second call
    hwutcov harvest <work-dir>        artifact -> record
    hwutcov merge <record>...         where the measures admit it

-- so the orchestration's build and run nodes consume the component
without importing it, and records remain the only interchange.
