(disc-2  THE SESSION ROAD: (c) BUILT, UNRECORDED.)
------------------------------------------------------------------------------
A coverage run never takes the session road: it runs one process per
choice ('orchestrator/run/coverage_dispatcher.py:108', 'interactive=
False' on the configuration it hands down), so one granularity, no new
key, nothing asked of any tool. The 'OPEN BESIDE' -- refuse where a
configuration asks for both 'interactive' and coverage, or silently take
the single-run road -- is answered by that line: silently. MEASURED
2026-10-04 (audit r10). No RATIONALE entry states it; this note stands
until one does ('adm/WORK/TODO.txt' band E, 'rulings owed').

disc-5  A MERGE MEETS HIT COUNTS
------------------------------------------------------------------------------
THE FORK. Merge is the UNION of ranges (D-5), and a union has no answer
for two different counts over one line.

  (a) REFUSE, by name ('CountsNotMergeable'). What is built.
  (b) SUM the counts -- which forces per-line storage on the merged
      record, i.e. exactly the grain this format exists to avoid.
  (c) DROP the counts and say so in the merged header.

RECOMMENDATION. (a) stands until somebody wants an aggregate of counted
records; then (c), never (b). Counts are off by default, so this is a
corner nobody is in yet.

disc-7  WHAT CONSUMES THE INDEX
------------------------------------------------------------------------------
BUILT: the index itself (index.py) -- the segmentation, the queries, and
'of_change(change_db) -> the runs that executed those lines'.

THE FORK. What turns a DIFF into that 'change_db', and what receives the
answer?

  (a) A NEW FACE, 'hwut.affected', that reads a diff and prints the
      runs -- the author pipes it into a wish themselves. Smallest, and
      touches no existing component.
  (b) A WISH SOURCE: 'hwut.run --affected <diff>' resolves through
      'plan/wish.py' like any other selection. Most useful, and it edits
      an existing face.
  (c) BOTH, (a) first.

RECOMMENDATION. (c). (a) is purely additive and can land while other
work is in flight; (b) waits for a quiet tree.

WHATEVER IS BUILT MUST SAY THE LIMIT (RATIONALE D-8): the answer is a
SUGGESTION, never a clearance. A face that prints a test list without
saying so invites exactly the false green the whole framework is built
to prevent.

RULED SINCE (D-42): the gathered output directory IS the stored fold;
nothing is rebuilt from per-case records, which the run removes.

disc-9  HARDWARE DESCRIPTION LANGUAGES -- the record cannot hold what a
        simulator measures
------------------------------------------------------------------------------
SUPERSEDED IN PART (2026-08-24) by TEST/REAL_PARSING_INPUT/PROVENANCE.txt and
RATIONALE D-12. The text below is kept AS IT WAS RULED; it is not
rewritten, because the reasoning was sound on what it knew and the
correction is a matter of EVIDENCE, not of argument. What the witnesses
overturned:

    the 'NO LINE' column      verilator and ghdl seat toggle, branch-arm
                              and cover points at a FILE and a LINE.
                              Four-of-eight becomes two-of-eight.
    'not merely not built'    the verilator '.dat', the ghdl psl.json
                              and the ucis xml are READ TODAY, each
                              against a witnessed artifact.
    the lcov road             is POLLUTED, not merely lossy: the export
                              misfiles toggle onto 'DA' lines. The road
                              now says '--coverage-line'; the native
                              '.dat' has its own reader and stands first.
    unmergeability            was a property of the anonymous DIGEST,
                              not of the measurement. Named points merge.

WHAT STANDS UNCHANGED. Option (b) -- a second record shape keyed by BIN
-- still awaits a real artifact, and the UCIS reader has now PROVED the
gap structural rather than incidental: FSM, assertion and covergroup
bins are LINE-LESS BY THE XSD ITSELF, not merely by the absence of an
open-source emitter. The vendor tools remain candidates with no reader.
The mandatory statement of option (a) shrinks to 'FSM and covergroup
coverage are not measured here'.

------------------------------------------------------------------------------

WHAT WORKS TODAY, and it is more than expected. VHDL and Verilog line
coverage needs NO new reader:

    verilog / systemverilog   'verilator --coverage', then
                              'verilator_coverage --write-info' -> an
                              LCOV TRACEFILE, which is read
    vhdl                      GHDL on the gcc backend -> gcov data,
                              which is read

So the open-source road is served by registry entries alone. That is
also the whole of what is served.

THE PROBLEM. Line coverage is a SMALL PART of what an HDL verification
flow measures, and the rest does not fit this record at all:

    statement / line     file + line          FITS -- this is what we hold
    branch               file + line + arm    todo-8; a third list
    condition / MCDC     file + line + term   todo-8's neighbour
    toggle               a SIGNAL, and its bits          NO LINE
    FSM state            a STATE of a machine            NO LINE
    FSM transition       an EDGE between two states      NO LINE
    functional           a COVERGROUP, a coverpoint,
                         a BIN, a CROSS                  NO LINE
    assertion            a named property, and how
                         often it was attempted, hit,
                         and vacuously passed            NO LINE

The record is keyed 'file -> line ranges'. Four of those eight have no
line at all: a toggle belongs to a SIGNAL, a bin to a COVERGROUP. There
is no honest place to put them.

WHY THIS IS NOT MERELY 'not built yet'. A reader that took a simulator's
database, kept the line part and dropped the rest would report a design
as '92% covered' while discarding the coverage the verification engineer
came for. That is a FALSE GREEN of the loudest kind -- and it is worse
than the ordinary sort, because the number LOOKS like the number the
engineer asked for.

    THE ASYMMETRY OF ERROR (PHILOSOPHY 7) applies exactly: the missing
    functional coverage cannot report itself, and the line percentage is
    a plausible-looking substitute for it.

THE FORK.

  (a) LINE COVERAGE ONLY, AND SAY SO. HDL is admitted for the line part
      alone; every rendering over an HDL record carries a stated line
      ('functional, toggle and FSM coverage are not measured here').
      Small, honest, and useful to anyone who wants 'which test touched
      this process'.

  (b) A SECOND RECORD SHAPE, beside the line one -- keyed by BIN rather
      than by line, with its own merge. The index (D-8) then answers
      'which test hit this bin', which is the same question and the same
      value. Considerable work, and it is a second format to version.

  (c) NOT AT ALL. Refuse HDL languages by name, as Pascal is refused --
      'this build does not measure hardware coverage'. Loses the line
      coverage that already works, for nothing.

RECOMMENDATION. (a) now -- it costs registry entries, which are already
written -- with the STATEMENT mandatory, not optional. (b) when somebody
actually verifies hardware with this framework; it is not speculative
work to be done in advance.

IF (b) IS EVER BUILT, the interchange standard is UCIS (Accellera's
Unified Coverage Interoperability Standard): Questa's '.ucdb', VCS's
'.vdb' and Cadence's databases all export toward it, and writing a
reader per vendor database instead would be three readers for one
format. Note that UCIS is an API with an XML interchange, not a text
file somebody greps -- it is a larger undertaking than every reader in
this component put together.

THE VENDOR TOOLS in the default table -- 'vcover' (Questa), 'urg' (VCS),
'imc' (Xcelium) -- are CANDIDATES WITH NO READER, deliberately. A shop
that has one gets a refusal naming it, which is the truth, rather than
silence.

        a third is one 'register' call.

        BUILT (2026-10-03, D-43 pass 4): every measure is carried into
