HOW TO INTEGRATE A COVERAGE
==============================================================================

PURPOSE

This document is the procedure for ADMITTING ONE MORE COVERAGE TOOL
into the component: what to do, in what order, and where each piece
goes. It is walked once per tool, by a developer of this component.

It does not explain how a test run OBTAINS coverage -- that chain
(build the coverage target, wrap, report, harvest) is README section 5
and RATIONALE D-19, built in 'operations/coverage_action.py'. And it does not restate the laws of
the record or of a reader; those live in README.txt and RATIONALE.txt
and are only POINTED AT from here.

WITNESS
------------------------------------------------------------------------------

Run the real tool over a real source file. Keep what it wrote under
'WITNESS-<topic>/<language>/', and add to 'WITNESS-<topic>-artifacts.txt':
the exact commands with tool versions, and what the artifact shows that
a specification would not have told you.

    lua 5.4.6, luacov 0.16.0:
        lua -lluacov demo.lua && luacov
    FINDING: the stats file cannot tell 'never run' from 'not
    executable'; only the REPORT can. The reader reads the report.

No reader is written from a specification alone, and no alias is placed
on belief -- the road is decided by the artifact. Where the tool cannot
run here, a fixture answering the format's OWN INVARIANT stands in, the
substitution is stated at the fixture, and the witness remains owed.


ALIAS
------------------------------------------------------------------------------

The artifact turned out to be a format already read: one line in
'readers/__init__.py', one candidate in the registry, done.

    ALIAS_DB:          "gcovr": "lcov"
    ROOT_CONF_TEXT:    c { coverage = [..., "gcovr", ...] }
                       (services/_boundary.py -- the shipped table, D-26)

An alias is a FRAMEWORK over a shared format: it is invoked as the
framework it reads through, and stamps its own name. A tool that needs
its own call form or its own second call deserves a framework class.


FRAMEWORK
------------------------------------------------------------------------------

The artifact is a format already read, but the tool is invoked its own
way: one 'CCoverageFramework' subclass naming the existing format.

    class FooFramework(CCoverageFramework):
        name   = "foo"
        format = LcovFormat()                        # what it writes

    register(FooFramework())

'wrap', 'report_argv' and 'instrumented_f' ALL HAVE BASE DEFAULTS --
'argv unchanged', 'no second call', 'cannot check'. State one only
where the tool genuinely does that thing; where it does not, say WHY
in the class docstring rather than writing the default out. 'instru-
mented_f' never answers False for want of a way to know.


FORMAT
------------------------------------------------------------------------------

The artifact is a new format: one module under 'readers/' holding a
'CCoverageFormat' and the framework that writes it.

    class FooFormat(CCoverageFormat):
        name   = "foo-json"
        suffix = (".json",)                  # what the walk collects

        def absorb(self, accumulator, path):
            ...                              # ONE artefact file, folded in

        def record_of(self, accumulator, source_root, config, counts_f):
            ...                              # -> a CoverageRecord

    class FooFramework(CCoverageFramework):
        name   = "foo"
        format = FooFormat()

    register(FooFramework())

'read' IS THE BASE'S, and is not overridden: it walks the artifact
directory, collects by 'suffix' in sorted order, calls 'absorb' per
file, answers None where nothing was absorbed (ABSENT, which is not an
empty measurement), and computes 'counts_f' from the configuration.
Override it only where that walk genuinely does not fit -- 'go' does,
because its 'counts_f' depends on a mode discovered DURING the walk.

'wrap' and 'report_argv' ARE THE BASE'S TOO, defaulting to 'argv
unchanged' and 'no second call'. Eight of the registered frameworks
instrument somewhere this component does not reach -- at build time,
on the run's own command line, through a JVM agent, from inside the
process -- and say so in a line of their class docstring rather than
in code.

THE RECORD IS REACHED BY ONE OF THREE DOORS, never built by hand:

                        the artefact's own shape
                                   |
          +------------------------+------------------------+
          |                        |                        |
     line-shaped              an ENTRY               a FILE DATABASE
   path -> {line: ...}         ITERABLE            the format built itself
          |                        |                        |
          v                        v                        v
  reader.line_record_of     reader.record_of      self.record_from
   cobertura, jacoco       gcov, go, lcov,      ghdl_psl, simplecov,
                           luacov, python_cov     ucis, verilator
          |                        |                        |
          +------------------------+------------------------+
                                   |
                                   v
                        record.CoverageRecord
                    +----------------------------+
                    | language  tool  source     |
                    | counts_f  version  run     |
                    | file_db: path -> FileCov.  |
                    +----------------------------+
                                   |
                                   v
                        record.FileCoverage
                    +----------------------------+
                    | path        RELATIVE (D-4) |
                    | executable  EX, ranges     |
                    | covered     CV, ranges     |
                    | counts      per CV range   |
                    | measure_db  tag -> points  |
                    +----------------------------+

'record_from' EXISTS SO THE HEADER IS FILLED ONCE: 'source' is the
FORMAT's name (one format is written by several tools), 'tool' is left
EMPTY for the framework to stamp in 'harvest' (D-7), and 'run' is left
empty because a reader knows the artefact and not the run -- whoever
holds the id calls 'record.seated' (D-8, D-18). Four readers filled
those five fields by hand before it existed.

The laws a format must obey -- absence is None, paths made relative,
the gather set applied, EX never invented, the pair never the
percentage, no tool stamped -- and a framework -- spawn nothing, name
the call -- are 'reader.py' docstring and README section 6. Read an
existing module of similar shape first; 'simplecov.py' is a small one.


MEASURE
------------------------------------------------------------------------------

Only where the artifact carries an axis the record does not hold yet
(line and branch exist; toggle and cover exist). One 'register' call in
'measure.py': a name, a record tag, an encoding, and the honest answer
to whether two records holding it merge.

    register(NamedPointMeasure(name="toggle", tag="TG"))

The axis enters at a FILE and a LINE or it does not enter (disc-9,
RATIONALE D-12).


REGISTER
------------------------------------------------------------------------------

Make the tool electable:

    ROOT_CONF_TEXT     the language's 'coverage' list in the shipped
                       root conf ('services/_boundary.py'), in
                       preference order -- readable formats first. THE
                       TABLE IS NOT IN THIS COMPONENT (D-26): an author's
                       tree carries its own copy in 'hwut-root.conf'.
    EXTENSION_DB       only where the source extension is new; it
                       serves 'hwut.cov convert' and the record header

A candidate with no reader is still listed: the machine then refuses
BY NAME instead of reporting no coverage. An empty candidate list is
itself an answer ('this build vouches for no tool here') -- never
invent one.


PROVE
------------------------------------------------------------------------------

One HWUT choice in 'TEST/test-readers.py'. The fixture is the tool's
bytes, pasted verbatim. The choice PRINTS what the reader made of them
-- plus the format's own cross-check where one exists -- and the
recorded GOOD file is the specification. No assertions.

    cd TEST && python3 test-readers.py foo > GOOD/test-readers.py--foo.txt
    # audit the file line by line, THEN bless it

Re-record 'GOOD/hwut.cov--formats.txt': the generated tool/format table
gained a row, and a reader admitted without it turns the suite red
(RATIONALE D-13).


LEDGER
------------------------------------------------------------------------------

One line each, history only -- what was built, when, against which
witness:

    DISCUSSIONS.txt todo-2           the reader ledger
    OVERVIEW-coverage-roads.txt      the road walked, the finding

Do not copy the tool/format table anywhere; it has one author, the
registry, and 'hwut.cov formats' prints it (RATIONALE D-13).
