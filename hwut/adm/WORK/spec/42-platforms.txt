2  THE COMMAND (rulings 9, 12)
==============================================================================

    -p <name>          repeatable; ADDS <name> to S
    --exclude-local    takes 'local' out of S

    Both are WISH words (engine/orchestrator/plan/wish.py): 'Wish' gains
    'platform_tuple' (the '-p' names, in order, no doubles) and
    'exclude_local_f'. Spelt back by 'Wish' as typed.

    S = ({local} - ({local} if exclude_local_f else {})) | set(platform_tuple)

    A '-p' name no conf of the walk names is a NOTE, not a refusal: "NOTE
    -p lab-3: no bubble below requires it".
    '--exclude-local' with no '-p': REFUSED, "'--exclude-local' leaves no
    platform -- add '-p <name>'".

    WHO TAKES THEM: 'hwut.run', 'hwut.play' -- the faces that run a test
    (ruling 7). Every other face that reads the wish refuses them by name,
    "'-p' is for the faces that run: hwut.run, hwut.play", with one
    exception, 'hwut.sanitize', which takes them and runs nothing (ruling
    12). 'hwut.run.stability' and 'hwut.cov.run': later; refused until then.
    [VERSION 3, built at P-3:] 'hwut.sanitize' is 'hwut.sanitize.propose'
    (the face of the family that reads the wish). A face that takes only
    SOME wish words ('parse_wish(take_tuple=...)', services E-219:
    'hwut.execute', 'hwut.remove.propose') does not know '-p' at all, and
    refuses it as any word it does not know. The words are SHOWN only by
    the faces that take them: their usage ('PLATFORM_USAGE_TOKEN_TUPLE')
    and help ('PLATFORM_HELP'), not the wish's own help -- which every
    face that refuses them prints.

3  THE DECISION (rulings 10, 12, 19; THE RULE)
==============================================================================

    Before the first event the walk reads the conf of every bubble at or
    below the top (E-200), a bubble with F = {} included (ruling 19), and
    computes per bubble B:

        Q(B) = the names of B's 'platform' list; {local} where it has none
        F(B) = S ∩ Q(B)

    REFUSED at the start, every B named, where any |F(B)| > 1:
        REFUSED: support/: requires local, linux; specified local, linux
                 => narrow with '--exclude-local -p linux', or run without '-p'

    Then per bubble, outermost first, a bubble handed over hiding its own
    inner bubbles (they are decided over there), a bubble NOT run hiding
    none:
        F(B) == {}         NOT RUN, reason 'available'
        F(B) == {local}    explored and run here, as today
        F(B) == {f}        platforms.is_available(f, spec):
                             (False, why)  NOT RUN, reason 'reachable'
                             (True, "")    HANDED to f (section 5)

    A bubble HANDED or NOT RUN is never explored here: nothing of it is
    interviewed (R-44) or built here. Its TEST directories are found by the
    walk alone (names, 'test_directory' of its confs).

    [VERSION 4, built at P-4:]
    - THE BUBBLES are the walk's: the one governing the top (the nearest
      'hwut-root.conf' at or above it), then every inner one in walk order,
      none where '--no-bubbles' stands. A bubble is named by its path from
      the top: '.' its own, '..' one above it.
    - THE REFUSAL is a 'SelectionError' raised at the orchestrator's call;
      'hwut.run' says "REFUSED: ..." as for any refused selection. Several
      bubbles: one pair of lines each. Two '-p' platforms both required:
      "=> narrow to one: '-p linux' or '-p win11'".
    - A bubble NOT RUN is walked for its inner bubbles only. Its confs are
      read and THEIR FAULTS ARE NOT THE RUN'S (ruling 21).
    - The '-p' NOTE of section 2 is asked of every bubble decided, walked
      or not.
    - HANDED until P-5: a 'not-run' event, reason 'handed', text
      "<B>/: platform '<f>': handing over: P-5".
    - The exit status where nothing ran is EMPTY (3), as for any run that
      runs nothing: 'not-run' changes it no more than that.

4  THE HELPER: engine/platforms/ (rulings 14, 15, 16, 17, 20)
==============================================================================

    engine/platforms/__init__.py     the four services, dispatched on 'kind'
    engine/platforms/local.py        'local'
    engine/platforms/container.py    'container'

    is_available(name, spec)  -> (bool, str)
        RETURN: (True, ""), the platform can run a bubble now.
                (False, why), else -- 'why' one line, the NOTE's text.
    start(name, spec, write)  -> (bool, str)
        RETURN: (True, ""), the platform is ready.
                (False, why), else.
    run(name, spec, bubble, wish, sink) -> int
        RETURN: int, the far run's exit status. Every far event reaches
                'sink' as it happens (section 5).
    stop(name, spec)          -> None
        Called in a 'finally', a signal included (E-55).
    keys(kind)                -> tuple[str]
        RETURN: tuple[str], the keys the kind knows beside 'name', 'kind'.
    check(name, spec)         -> tuple[(str, str)]       [VERSION 2, P-2]
        RETURN: tuple of (key, text), the faults of the entry's own keys,
                found by the kind (ruling 14); empty where it reads.

    LOCAL: is_available is (True, ""); start, stop do nothing; run is never
    called (the orchestrator runs a local bubble itself).

    CONTAINER:
      is_available   the engine on PATH, and 'image inspect <image>' 0,
                     or 'recipe' a file. Else, e.g.
                       "no podman or docker on PATH"
                       "image 'hwut-dev' absent and no recipe"

      run            <engine> run --rm -i

                         -v <root>:<root>   -w <root>/<bubble>
                         -e HOME=/tmp       (as 'hwut.dev.podman.enter')
                         <image> <root>/hwut/bin/hwut.run --silent
                         --log /dev/stdout <the wish's words for B>
                     no '-p': the far run starts with S = {local}. 'the
                     wish's words for B': its targets re-rooted at B (a
                     target outside B dropped), its labels and wishlist
                     words as given.
                     <root> the directory holding 'hwut/', mounted at its
                     own path, as 'hwut.dev.podman.enter' does: the tree
                     over there is the tree here (CONTRACT: TREE, HWUT,
                     RESULTS -- what the far run writes lands where a
                     local run writes it).
      stop           nothing beyond '--rm'.

    [VERSION 5, ruled 2026-11-03 -- the fork of P-5, (a): "continue"; built
    at P-5:]
      run            <engine> run --rm -i  <user as above>
                         -v <home>:<home>   [-v <bubble>:<bubble>]
                         -w <bubble> -e HOME=/tmp <image>
                         <home>/hwut/bin/hwut.run --silent
                         --events /dev/stdout --as-platform=<name> <words>
                     <home> the directory holding the hwut that runs here
                     ('hwut/'): both sides one version (CONTRACT: HWUT);
                     <bubble> the bubble's directory, mounted where it lies
                     outside <home> -- its own 'hwut-root.conf' bounds the
                     far climb. THE STREAM: 'hwut.run --events <file>'
                     writes each event as its line ('line_of'), the time
                     from 'tree-begun', flushed at once -- a word for a
                     hwut that reads another, not shown in the usage.
                     '--as-platform=<name>' (THE RULE: over there 'local'
                     IS the platform): the far decision reads a bubble
                     requiring <name> as requiring 'local' -- the switch is
                     not obeyed again (ruling 3).
                     <words>: 'Wish.far_argv' -- targets and directory
                     rules re-rooted at the bubble, one outside dropped, a
                     bare name kept, every other word as given. A wish
                     wanting nothing of the bubble (targets or '--dir'
                     rules, none reaching in): the bubble is not handed.
      stop           also terminates a far run still standing -- a signal
                     at the near run (E-55) leaves none behind.

5  THE STREAM (ruling 20)
==============================================================================

    'container.run' reads the far stdout line by line; per line
    'event_of(line)' (engine/protocol/line.py), then:

        tree-begun, tree-done          swallowed: the near run has its own
        an event with 'directory'      'directory' = <bubble>/<directory>
                                       ('.' becomes <bubble>)
        every event                    'platform' = <name> added
        a line 'event_of' cannot read  a 'fault' event, the line verbatim:
                                       "<bubble>/: platform 'linux' said: ..."

    and puts it on the orchestrator's queue, as a local event.
    The far exit status: 0 or 1 is told by the events; any other is a
    'fault' event, "<bubble>/: platform 'linux' ended with status <n>".

    'hwut.play' [VERSION 6, ruled 2026-11-03: "yes to play"]: the bubble
    governing its directory is decided as for 'hwut.run'
    ('bubble.governing_decision'): refused; not run -- its NOTE, "nothing
    played: the bubble is not run here", EMPTY (3); handed -- the far
    'hwut.play --as-platform=<f> <words>' run there in the same directory,
    its lines relayed ('platforms.relay', a fifth service: what play shows
    is text, not events), its recording on the same disk, its status the
    face's; here, as ever.

    THE NEAR 'tree-begun' lists a handed bubble's TEST directories (found
    by the walk, section 3), so a viewer knows them before they report.
    [VERSION 5:] The handed bubbles run after the local directories, one
    after another; their failures count into the near 'tree-done'. A
    'start' that fails (the image's build) is the bubble NOT RUN,
    'reachable'. 'run' reads the far stream in a worker thread; 'stop'
    runs in a 'finally'.
