    target         the board, simulator or emulator

    loader         the vendor tool that puts an image on the target, run

    bench          one named entry of 'bench { }': a target, its link and
                   its loader
    platform       where hwut runs a bubble (spec/42); a definition that
                   provides a bench's name has that board attached

    WHAT THE USER DOES -- everything else is done by the modules; the
    protocol (Part A) stays hidden from the user.

       user           hwut          make+loader     hwut_remote         agent
         |              |                |                |               |
         |  ONCE PER BENCH                                                |
         |  wire the target; install the vendor tool                      |
         |  hwut.sanitize.bench.defaults; fill in the entry               |
         |  python3 -m hwut_remote list: what is attached, which entry    |
         |    names it                                                    |
         |  name it in the 'provides' of the platform it is attached to   |
         |              |                |                |               |
         |  ONCE PER TEST                                                 |
         |  copy a prototype: support/remote/proto/<name>/                |
         |  its bubble specifies the bench: platform = [ "<name>" ]       |
         |  put the UUT beside the agent: verilog -- in the top           |
         |    level; c, python -- write uut_run(stim, report)             |
         |  write the test application: vectors, prints                   |
         |  hwut.play; accept the GOOD                                    |
         |              |                |                |               |
         |  EVERY RUN                                                     |
         |-- hwut.run ->|                |                |               |
         |              |-- the bench's device present? else not run      |
         |              |-- build ------>|                |               |
         |              |                |-- image id? flash if stale --->|
         |              |-- run a choice ---------------->|               |
         |              |                |                |-- open ------>|
         |              |                |                |-- reset ----->|
         |              |                |                |-- vectors --->|
         |              |<- rows, '##' lines -------------|               |
         |<- verdict ---|                |                |               |

    The protocol of Part A runs inside 'open', 'reset' and 'vectors'.

    The host reads and writes bytes of a map; one verb, 'x', applies a
    stimulus and returns the outcome and the report. Every reply is the
    content of a read. hwut learns two things: the block 'bench { }' of
    hwut-root.conf, and which platform provides a bench; it looks for a
    bench's device and never talks to a board.

    Running example: an 8-bit registered adder on a MAX 10 at 50 MHz,
    LATENCY 1; a = 03, b = 04, sum = 007. Stimulus a[15:8] b[7:0]
    (2 bytes), report sum[8:0] (2 bytes).

    Every rule of this design is a statement about one axis, or one of the
    couplings below. Any combination of axis values not excluded there is
    meaningful. The axes and their laws are stated here only; sections 4
    to 21 specify each axis without repeating its law.

    axis               values                         owner         sect.
    ----               ------                         -----         -----
    A agent impl.      verilog, c, python             target/<impl>/    9
    B time domain      wall, virtual                  entry key        13
                                                      'time'
    C transport        serial, tcp, udp, ssh, launch, hwut_remote.     12
                       can, visa; a plugin's key      link, visa, a
                                                      plugin
    D loader           quartus, openfpgaloader,       loader module,   14
                       openocd, esptool, copy, none   entry key
                                                      'loader'
    E bench reset      reload, probe, line, reopen,   loader module    15
                       scpi, power                    'reset', entry
                                                      key 'power'
    F image identity   id = H(inputs, toolchain);     Makefile,        14
                       board: equal, differs, absent  map 08
    G address space    regions * access (section 5)   MAP.txt           5
    H verb             r, w, x  (p reserved)          PROTOCOL.txt      6
    J wait contract    mode * LATENCY * timeout *     agent            8
                       reset length                   parameters,
                                                      map 0e, 14
    K outcome of 'x'   00 none, 01 done, 02 timeout,  map 19 [1:0]      7
                       03 expired
    L agent life       fresh in {1, 0} * last         map 19 [7], 18    7
    M reception        reply, other token, noise      hwut_remote.     10
                                                      line, session
    N recovery         acted, not acted, restarted,   hwut_remote.     10
                       busy, refused, silent, ended   session
    O picture class    row, '##'                      the writer       18
    Q ownership        collision group * providing    hwut (R-32),     16
                       platform                       platforms

    THE LAW OF EACH AXIS

    A  An agent implementation implements MAP and PROTOCOL; verilog counts its
       timeout in the clock it shares with the UUT, c and python in ticks.
    B  In wall time every host wait is bounded in seconds; in virtual
       time only hwut's caps bound it.
    C  A transport carries bytes, or lines as datagrams, between host and
       agent; only a UART on the path has a bit rate ('baud').
    D  A loader flashes iff the agent's image differs from the built id,
       and succeeds iff they are equal afterwards.
    E  After a bench reset the agent is in its start state: last = ff,
       fresh = 1; an instrument is in its '*RST' state.
    F  The id has one source, the hash of the inputs; stale iff the board's
       id differs.
    G  A byte operation on a byte that does not permit it is refused.
    H  'r' never acts; 'w' and 'x' write 'last' before they act; a
       duplicate never acts; every reply is the content of a read.
    J  Every wait of the agent ends within 'timeout' counts.
    K  01 and 02 are behaviour of the UUT; 03 is a failure.
    L  fresh holds from agent start until the reset write; last is ff only
       since start.
    M  Only a verified line with the expected token is a reply; the agent
       answers only verified lines; everything else is counted.
    N  Recovery is decided by one idempotent read; nothing is applied
       twice.
    O  A row is a function of the stimuli, the wait contract and the UUT.
    Q  One owner per board; within a collision group the build and the run
       of one application are adjacent; a board's tests run only on the
       platform that provides its bench, and only while its device is
       present.

    THE COUPLINGS -- every place where two axes depend on each other; all
    are necessary.

    coupling      statement                                         sect.
    --------      ---------                                         -----
    A * K         verilog yields outcomes 00, 01, 02; c and python      9
                  yield 00, 01, 03 with the poll seam, 00, 01 with
                  the run seam
    A * J         only verilog has LATENCY and RESET_CYCLES; c and      9
                  python report mode 0 (wait for done)
    J * O         the wait contract is part of every row's meaning:    18
                  the writer prints it as a row
    J * J         timeout >= max(LATENCY, RESET_CYCLES); a write        8
                  below is refused: '! limit'
    G * deadline  an address may wait: 'x' and the reset write wait    10
                  up to timeout / clock; every other address answers
                  at once
    B * C         time = virtual sets link_margin and boot to inf on   13
                  any transport
    C * deadline  a link with 'baud' adds two line times               10
    C * E         on transports 'launch' and 'ssh' the bench reset is  15
                  reopening; on 'visa' it is '*RST', '*CLS'
    C * D         loader 'copy' requires transport 'ssh'; loader       14
                  'esptool' uses the serial address as its target;
                  transport 'visa' requires loader 'none'
    D * E         reload: quartus with a .sof, openfpgaloader; probe:  15
                  openocd; line: esptool; reopen: launch, ssh; scpi:
                  visa; power: any, when 'power' is set
    L * H         the host never sends a 'w' or 'x' with the token in   6
                  'last'; the agent takes one that arrives as a
                  duplicate
    L * N         reconciliation compares 'last' with the token and    10
                  with the previous 'last'
    M * C         one command is outstanding at a time; the token      12
                  alphabet relies on that, not on the transport's
                  order; on udp a duplicate delayed past the next
                  command is excluded only by a delay below one
                  round trip

    The column 'sect.' names where the coupling is put to work; the
    statement stands here only.

4  THE LINE
==============================================================================

        b x 0403 *2b95\n
        | | \__/  \__/
        | |  |     +-- CRC-16 over "b x 0403"
        | |  +-------- bytes in address order: 04 03 = 0x0304, little-endian
        | +----------- verb
        +------------- token 0..f: the host chooses, the reply echoes it

        b 010700 *8bff\n      the reply: status 01, report 07 00

    LINE   := TOKEN ' ' BODY ' *' CRC '\n'
    TOKEN  := one hex digit
    BODY   := words of [a-z0-9]+, or '!' and a word, single spaces between
    BYTES  := hex digit pairs, contiguous, in address order
    CRC    := CRC-16/CCITT-FALSE: poly 0x1021, init 0xffff, refin false,
              refout false, xorout 0; check("123456789") = 29b1;
              input TOKEN ' ' BODY as transmitted, not ' *';
              four lowercase hex digits, most significant first
    length <= 80 bytes, trailer and '\n' included

    NOISE, on both sides counted and never answered: a line whose CRC
    fails, a line over 80 bytes, '\r', and every byte outside
    [a-z0-9 !*\n]. An empty line flushes a partial line.

==============================================================================
5  G -- THE ADDRESS SPACE
==============================================================================

    A linear, byte-addressed space; a multi-byte value is little-endian.

    offset len  access  name      content
    ------ ---  ------  ----      -------
    00     4    r       magic     'hwut' (68 77 75 74 on the wire)
    04     4    r       proto     1
    08     4    r       image     IMAGE_ID (section 14)
    0c     1    r       stim len  SW, 1..32
    0d     1    r       rep len   RW, 1..32
    0e     1    r       mode      [0] 1: sample LATENCY cycles after apply;
                                      0: wait for done to rise
                                  [1] 1: run seam (c, python); 0: poll
    0f     1    r       discard   lines discarded since start, stops at ff
    10     4    r       clock     Hz of the count 'timeout' uses
    14     4    rw      timeout   counts a wait may take (section 8)
    18     1    r       last      token of the last 'w' or 'x'; ff after
                                  start
    19     1    r       status    [1:0] outcome, [7] fresh (section 7)
    1a     RW   r       report    the UUT's outputs
    3f     1    w       reset     any write resets the UUT          waits
    40     SW   rw      stim      the UUT's inputs
    100    ..   rw      bus       optional: the UUT's own registers, or
    ..ffff                        the MCU's memory; no wait states; word
                                  buses take aligned 4-byte runs
    10000.. -   -       xfer      reserved (o-5)

    REFUSED with '! limit': every other address, a read of a w-only byte,
    a write of an r-only byte, a length of 0, a read of more than 35
    bytes, an access a word bus cannot take.

    THE SESSION IN ADDRESSES

    hello    r 0 1a    (00 .. 19: identity, contract, last, status)
    reset    w 3f 01
    vector   x <stim>
    recover  r 18 2+RW (last, status, report)

==============================================================================
6  H -- THE VERBS
==============================================================================

    host --> agent       agent --> host              acts
    r <addr> <len>       the bytes of r addr len     no
    w <addr> <bytes>     the bytes of r 19 1         yes
                         (status, after the write)
    x <bytes>            the bytes of r 19 1+RW      yes: the apply and the
                         (status, report)            wait of section 7
    p                    ! unknown                   reserved

    DUPLICATE -- a 'w' or 'x' whose token equals 'last' does not act; its
    reply is the reply of the table, the state the first one left. The
    host takes it as it takes any reply, by its token (section 10).

    REFUSALS -- the command did not act; sent only for verified lines:

        ! unknown   verb not known
        ! syntax    malformed body
        ! limit     section 5; and 'x <bytes>' with a byte count other
                    than SW
        ! busy      an 'x' or the reset write is pending

==============================================================================
7  K, L -- OUTCOME AND AGENT LIFE
==============================================================================

    status (19)   [1:0] outcome of the last 'x'   [7] fresh

    outcome  00  none: no 'x' since start or since the reset write
             01  done: the report holds the UUT's answer
             02  timeout: no done within 'timeout' UUT cycles -- data
             03  expired: no done within 'timeout' ticks -- a failure

    'x <bytes>', inside the agent:

        "b x 0403"
            |
            +--> last   <- b
            +--> stim   <- 04 03
            +--> strobe apply, one cycle -----------> UUT
            +--> wait (section 8) --> outcome <- 01 | 02 | 03
            +--> reply: status, report  "b 010700"

    THE RESET WRITE: last <- token; UUT reset (section 8); outcome <- 00;
    fresh <- 0; report unchanged; reply: status.

==============================================================================
8  J -- THE WAIT CONTRACT
==============================================================================

    mode 0   the agent waits for done to rise after the apply strobe
    mode 1   done is not used; the report is sampled LATENCY cycles after
             the strobe
    timeout  counts any wait may take: an 'x', a reset
    reset    verilog: uut_rst high for RESET_CYCLES; c, python: complete
             when uut_reset() returns

    stim and report are stable from the strobe to the sample.

    The wait contract is mode, LATENCY, timeout and its unit.

==============================================================================
9  A -- THE AGENT IMPLEMENTATIONS
==============================================================================

    VERILOG (target/verilog/):

              +---------------------- agent -------------------------+
    uart_rx ->| phy > line > CRC > parser > map -+- stim[SW*8] ------+-> UUT
    uart_tx <-| phy < line < CRC <---------------+  apply -----------+->
              |                                  |  uut_rst ---------+->
              |  timeout counter (clk)           +<- done -----------+--
              |                                  +<- report[RW*8] ---+--
       clk -->|  bus master (optional):                              |
              |    addr wdata we re rdata ---------------------------+<> bus
              +------------------------------------------------------+
       parameters  SW, RW (1..32, refused otherwise at synthesis),
                   IMAGE_ID, CLOCK_HZ, TIMEOUT, LATENCY (0: mode 0),
                   RESET_CYCLES, BAUD
       phy_stdio.v replaces phy_uart.v by $fgetc / $fwrite and calls
       $fflush after every '\n'

    C (target/c/) and PYTHON (target/python/):

       hooks, from the port     int      agent_getc(void);  /* -1: none */
                                void     agent_putc(int c); /* '\n' flushes */
                                uint32_t agent_tick(void);
                                /* getc reads an interrupt- or DMA-fed ring
                                   of at least two lines; on udp the
                                   datagrams' bytes, putc's '\n' sends
                                   one datagram */
       seam, from the writer    void uut_reset(void);   /* the UUT only */
         run (default)          void uut_run(const uint8_t *stim,
                                             uint8_t *report);
                                /* returns when done; may block */
         poll                   void uut_start(const uint8_t *stim);
                                int  uut_done(uint8_t *report); /* 1: done */
       main loop                for (;;) agent_poll();
       The writer provides one of the two seams; the agent reports it in
       mode [1]. With the run seam the agent is deaf while uut_run runs:
       no '! busy', no outcome 03; a call that never returns is "agent
       silent" (section 10). With the poll seam the main loop never
       blocks.
       'clock' = the rate of agent_tick;
       elapsed = (uint32_t)(agent_tick() - start), wrap-around tolerated

    Outcomes and mode per implementation: couplings A * K and A * J
    (section 3).

    Every implementation passes the 'x' oracle of
    target/verilog/TEST/test-agent.py: the reply to 'x' equals
    the bytes of the following 'r 19 1+RW'; a duplicate 'x' returns the
    same bytes and does not apply.

==============================================================================
10  M, N -- RECEPTION AND RECOVERY
==============================================================================

    RECEPTION (host): a verified line with another token is a late reply,
    noted and discarded.

    DEADLINE, per command:

        deadline = waits + line_time + link_margin
        waits      timeout / clock    'x' and the reset write; else 0
        line_time  2 * 80 * 10 / baud  when the entry has 'baud'; else 0
        link_margin                    the entry's (section 13)

    THE LADDER

        no reply by the deadline:
          r       --> resend, new token
          w, x    --> r 18 2+RW --+-- last = token          --> acted: the
                                  |                             bytes after
                                  |                             last are the
                                  |                             reply
                                  +-- last = previous last  --> not acted:
                                  |                             resend, new
                                  |                             token
                                  +-- anything else         --> restarted
        fresh = 1 in any status after the session's reset --> restarted
        ! busy                  --> wait one deadline, resend; counts as a
                                    failure
        ! unknown|syntax|limit  --> raise
        end of file (launch,    --> silent
        ssh)
        3 failures in a row     --> silent; any reply with the command's
                                    token resets the count

        restarted, silent --> close the link, bench reset (section 15),
                              reopen, hello; then raise: the choice fails

    A LOST REPLY -- acted:

    6 x ffff *23d9 ----------------------> last := 6, outcome 01,
          <---- 6 01fe03 *3ddb               report fe 01
                crc("6 01fe03") = 1d99 != 3ddb: noise
    7 r 18 4 *5e0c ---------------------->
          <---- 7 0601fe01 *edd4           last 6 = token: the reply is
                                           01fe01

    A LOST COMMAND -- not acted (the previous 'x' had token 2):

    3 x 0403 *a722 -------X
    4 r 18 4 *9679 ---------------------->
          <---- 4 02010700 *eff0           last 2 = previous: resend
    5 x 0403 *27e9 ---------------------->
          <---- 5 010700 *8783

    A REBOOT -- the agent restarted since the session's reset:

    8 x 0403 *718d ---------------------->
          <---- 8 810700 *dca5             fresh = 1: restarted

    key           axis  meaning

    baud          C     bit rate of the UART on the path
    dtr, rts      C     levels set before open; false = deasserted, the
                        pin high
    low_latency   C     FTDI latency timer 1 ms
    link_margin   C, B  seconds added to every deadline, or inf
    time          B     wall (default) | virtual
    boot          B     seconds the hello may take, or inf; mandatory
    loader        D     quartus | openfpgaloader | openocd | esptool |
                        copy | none
    cable         D     quartus: the cable as jtagconfig lists it
    board         D     openfpgaloader: the board name it knows
    cfg           D     openocd: the board configuration
    image_offset  D     esptool: offset of the merged image
    agent         C, D  ssh and copy: the agent's path on <host>
    power         E     a command that power-cycles the board

    VALIDATION. hwut validates a map of maps of scalars;
    entry.get(name) validates the KEYS and the one-transport rule
    (section 12), and refuses a placeholder: "bench max10: fill in
    serial". A plugin's transport key is known once registered; the other
    keys of its entry beside the table's B, D and E keys are the
    producer's, checked by it. An inner root's benches are its own
    (D-56). A /dev/serial/by-id path names the board on every host.

    THE HUB -- hwut_remote, what the writer imports:

    create_hub(name, note=None, image_id=None, image=None, failures=3)
                                   -> Hub
        entry.get(name); the producer registered under the entry's
        transport key; producer(entry, note); the Hub opened (section 12)
    add_plugin(key, producer)      registers a producer under a transport
                                   key; a key taken is refused
    Hub        reset(), close(); a context manager; the base of every hub
    LinkHub    a Hub over the agent's map: vector(stim) -> int | TIMEOUT,
               read(addr, n), write(addr, bytes), contract(); a producer
               gives it open, send(bytes), recv(deadline) -> bytes, close;
               line, CRC, token and the ladder are LinkHub's (sections 4,
               10)
    VisaHub    a Hub over an instrument: query(cmd) -> str, write(cmd),
               opc(); no agent, no map (section 22)
    TIMEOUT    section 18

    The seven built-in producers are registered by add_plugin: six
    LinkHubs, serial, tcp, udp, host (ssh), launch, can, and one VisaHub,
    visa. A system with another protocol (section 22) may implement Hub
    whole and register it the same way. A plugin is registered by the
    test's own code, before create_hub:

        from hwut_remote import create_hub, add_plugin, LinkHub
        add_plugin("bridge", lambda entry, note: LinkHub(BridgeLink(entry),
                                                         entry, note))
        bench { lab { bridge = "usb:1-3"  boot = 2.0  loader = none } }

    hwut-root.conf that has none, with '<device>', '<cfg>', '<host>'
    placeholders; a tree with a block is left as it is and told so; one
    line per bench written.

    OPENING:

    host                                         agent
    serial: DTR/RTS set before open, exclusive, low latency, input flushed
    '\n'

    THE MAKEFILE (the writer's); the rule for TMP/image_id is the shared
    fragment host/image_id.mk, included:

    RE        := $(HWUT_REMOTE)
    INPUTS    := $(sort $(wildcard src/*.v $(RE)/target/verilog/*.v) \
                        uut.qsf uut.sdc Makefile)
    TOOLCHAIN := quartus_sh --version
    include $(RE)/host/image_id.mk

    # host/image_id.mk (HWUT_REMOTE: the directory support/remote):
    TMP/image_id: FORCE
    	mkdir -p TMP
    	(cat $(INPUTS); $(TOOLCHAIN)) | sha256sum | cut -c1-8 > $@.new
    	cmp -s $@.new $@ || mv $@.new $@
    	test -f TMP/image_id.vh -a ! TMP/image_id.vh -ot $@ || \
    	  echo "\`define IMAGE_ID 32'h$$(cat $@)" > TMP/image_id.vh
    uut.sof: TMP/image_id
    	quartus_sh --flow compile uut
    flash: uut.sof
    	python3 -m hwut_remote.quartus \
    	        flash max10 uut.sof $$(cat TMP/image_id)
    .PHONY: flash FORCE

    INPUTS names everything that changes the image; TOOLCHAIN names the
    compiler's version command. TMP/image_id changes only when the hash
    does.

    THE TEST:  @hwut { build = "make flash" }

    THE LOADER MODULE, hwut_remote.<loader>, the same for every loader:

        python3 -m hwut_remote.<loader> \
                flash <bench> <image> <image-id>

          else: close; flash; reopen; hello within 'boot';
                exit 0 only if the image is now running

    loader   flash
    ------   -----
    quartus  quartus_pgm -c <cable> -m jtag -o "p;<image>"  (.pof: "pv;")

    none     -- (launch: the image is the command's argument)

16  Q -- OWNERSHIP
==============================================================================

    The tests of one board are a collision group (R-32). The board is
    attached to the platform whose definition provides its bench's name;
    the board's bubble specifies that name (spec/42, 'provides'):

    a hwut-root.conf the walk reads (the name resolves across all):
        platform = [ { name = "local", provides = [ "max10" ] } ]
    the board's bubble, support/remote/proto/de10-lite/hwut-root.conf:
        platform = [ "max10" ]

    THE BENCH PROBE. A platform used under a provided bench name is
    available only while the bench's device is present: serial, the
    device path exists; can, the interface exists; tcp, udp, ssh, launch,
    visa and a plugin's key, not probed. A miss is '[PLATFORM not reachable]'
    with the NOTE "bench max10: no device", the bubble not run. hwut
    looks; it never opens the link.

    CONDITION ON HWUT: no other build of the group runs between the build
    and the run of one application. Delivery step 4 verifies it.

    Two roots holding one board are detected only as "stale agent" or
    "bench busy".

==============================================================================
18  O -- SESSION SCOPE AND THE PICTURE
==============================================================================

    A session is one choice: it opens, resets, applies, closes.
    create_hub() opens the link and says hello; the writer resets;
    Hub.vector() and Hub.write() raise unless this hub has reset; leaving
    the 'with' block closes the link.

    The writer prints the wait contract as a row, Hub.contract().
    Everything else the session knows is a '##' line, delivered through
    'note'.

    ## agent: proto 1  image 3f9a07c1  stim 2  report 2  50 MHz
    ## discarded 12 bytes, 0 lines
    contract: sample 1 cycle after apply, timeout 10000000 cycles
    ## stim = a[15:8] b[7:0]   report = sum[8:0]
    0304 007
    ff01 100
    ffff 1fe
    <hwut-end>

    Hub.vector() returns the report as an int, or hwut_remote.TIMEOUT on
    outcome 02; TIMEOUT formats as 'timeout' under any format spec.
    Outcome 03 raises. A recovery adds a '##' line where it happened and
    leaves the rows unchanged. A read at the bus (100 and above) is
    followed by 'r 19 1' and checked for fresh.

==============================================================================
19  THE TEST, AS THE WRITER WRITES IT
==============================================================================

    # @hwut { build = "make flash"  collision = [ test-max10-timing.py ] }
    import sys
    from hwut_runner import HwutRunner
    from hwut_remote import create_hub

    VECTORS = [(0x03, 0x04), (0xff, 0x01), (0xff, 0xff)]

    def note(text): print("##", text)

    def adder():
        image = int(open("TMP/image_id").read(), 16)
        with create_hub("max10", note=note, image_id=image,
                        image="uut.sof") as hub:
            hub.reset()
            print(hub.contract())
            print("## stim = a[15:8] b[7:0]   report = sum[8:0]")
            for x, y in VECTORS:
                print(f"{x:02x}{y:02x} {hub.vector((x << 8) | y):03x}")

    HwutRunner(sys.argv, "Adder on MAX 10;", {"adder": adder}).run()

    Nothing runs at import: '--hwut-info' needs no build and no board.
    The bubble's hwut-root.conf specifies platform = [ "max10" ]; the
    test names the bench, never the platform. The hub finds the bench
    reset by the entry's 'loader'. The writer never sees a token, a CRC,
    a byte order or a recovery.

==============================================================================
22  SYSTEMS WITH THEIR OWN API: HIL, ROS 2, ECUS, INSTRUMENTS
==============================================================================

    A system with its own real-time target and host API -- dSPACE through
    ASAM XIL, NI VeriStand -- with its own middleware -- ROS 2, SOME/IP
    -- or with its own protocol -- an ECU through XCP or UDS, an
    instrument through VISA and SCPI -- takes the
    place of the agent, the line, the map and recovery (sections 4 to
    10). The rest stays:

    ours                               theirs
    ----                               ------
    build: deploy the model or system  the real-time target, its loop rate
      definition; its checksum is the  the stimulus, executed on the target
      image identity, printed as '##'  the capture, triggered and
      and compared                       timestamped on the target
    ownership: collision group,        the host API and its errors
      providing platform
    session: one choice = one run
    picture: rows and '##'

    THE SESSION, for every such system:

        configure -> arm stimulus -> arm capture -> start -> wait until the
        (load,       on the target    with a trigger         capture is
        deploy)                       in model time          complete
                                                               |
        rows <-- capture.rows <-- fetch <-- stop <--------+

    RULES
      rows come only from captured, target-timestamped samples, at stated
        model times; never from a read during the run
      every value has a stated resolution and unit, or is matched by a
        pype quantity
      the system's own verdict (a sequence's return value) is a row
      an error of the host API fails the choice; its text is a '##' line

    ROS 2: the UUT is a node or a stack; the test application is a node
    itself (rclpy). It publishes stimuli and subscribes to results,
    recording each message with its header stamp.
      simulation  Gazebo (or another simulator) publishes /clock;
                  use_sim_time = true for every node; the bench entry has
                  time = virtual; the simulator runs in lockstep, so the
                  stamps are model time and the RULES above hold
      real robot  stamps are wall time: rows hold final states and the
                  stack's own verdicts only; every timed value is a '##'
                  line
      build       the colcon workspace; its image identity is the hash of
                  the package sources and the ROS distribution
      provenance  ROS distribution, RMW implementation, ROS_DOMAIN_ID as
                  '##' lines; each test uses its own ROS_DOMAIN_ID

    AUTOMOTIVE ECUS
      XCP         measurement and calibration (pyxcp): DAQ lists bound to
                  ECU events are the capture, their ECU timestamps the
                  model time; the A2L file names the variables; the A2L's
                  EPK is the image identity
      UDS         diagnostics, ISO 14229 (udsoncan, over CAN ISO-TP or
                  DoIP): each request and its positive or negative
                  response is a row; the session (default, extended) and
                  the security access level are part of the row's
                  meaning, printed as rows; timing parameters are '##'
      SOME/IP     Adaptive AUTOSAR services: the ROS 2 rules apply --
                  rows from timestamped messages under simulated time,
                  final states and verdicts on a real network
      AUTOSAR Classic SWCs are reached through the C agent: the writer's
      uut_run calls the component's RTE ports (Rte_Write, Rte_Call,
      Rte_Read); on the host the same seam runs against RTE stubs.

    INSTRUMENTS (SCPI), through VisaHub:

        bench { dmm { visa = "USB0::0x2A8D::0x1301::MY59001234::INSTR"
                      boot = 5.0  loader = none } }

        with create_hub("dmm", note=note) as dmm:   # '## idn: ...'
            dmm.reset()                             # *RST, *CLS
            dmm.write("CONF:VOLT:DC 10,0.001")
            dmm.write("INIT"); dmm.opc()
            print(f"v = {float(dmm.query('FETC?')):.3f} V")

      open      pyvisa opens the resource; '*IDN?' within 'boot' is a
                '##' line; no answer: "no instrument"
      write, query
                send one message; then 'SYST:ERR?' until '+0': any other
                entry raises with its text, after a '##' line
      opc       '*OPC?' within the VISA timeout; the host never sleeps
      reset     '*RST', '*CLS', the error queue read empty
      a VISA error raises; its text is a '##' line

    capture.rows(samples, times, fmt) -> [str]
      samples  (t, v1, v2, ...) in model time, ascending
      times    the model times to report
      fmt      the row format, e.g. "t={:.3f} rpm={:.1f} torque={:.1f}"
      each row holds the last sample at or before its time; a time before
      the first or after the last sample raises

    The bench README carries seven worked test applications: ASAM XIL
    (dSPACE), VeriStand, ROS 2 with Gazebo, XCP, UDS, SOME/IP, SCPI
    through VisaHub; and one uut_run over RTE ports.
