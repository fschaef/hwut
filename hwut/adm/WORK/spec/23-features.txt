A CLAIM is a sentence of what the software does, and what implements it:

    claim       implemented by                 stated in
    ---------------------------------------------------------------------
    aggregate   claims below it                the tree of the central file
    leaf        test runs                      <component>/TEST/hwut-features.conf
                                               (the link: a test's block)

Both speak with 'title' (one line), 'doc' (as many lines as it takes, triple
quotes), 'documents' and 'keys'. A test carries 'title' and 'doc' as well.

A COMPONENT is a directory that is not a TEST directory. It is no claim of
its own any more: the claims are the leaves in its TEST directory and the
aggregates of the tree. The TEST directory is the component's own and no
level of anything.


1  THE FEATURE FILE (a TEST directory's)
______________________________________________________________________________

    features {
        keys = ["algorithm"]
        childs {
            line-pairing { title = "Two streams are aligned line by line."
                           doc   = "..."
                           keys  = ["heavy"] }
            missing-side { title = "A line present on one side only is shown whole." }
            007          { title = "Names may be digits." }
        }
    }

    keys          keys that apply to every feature of the file.
    childs        the leaves; the KEY of each is its NAME -- what a test
                  writes to link to it, unique in the file. A name is an
                  identifier (section 4).
    title, doc, documents, keys   as in section 0.

A TEST directory's file states nothing else. A key standing twice, a name
that is no identifier, a directory reference are faults; the first stands.
Component files outside TEST directories ARE NO LONGER READ: 'hwut.features.init'
and 'register' name one that stands (a vocabulary of the past).


2  THE LINK
______________________________________________________________________________

    # @hwut {
    #     title    = "Pairing"
    #     features = ["line-pairing"]
    #     choices { gap { features = ["line-pairing", "missing-side"] } }
    # }

'features' is a test parameter like every other: at the root for the whole
test, in a choice for that choice (the choice's list REPLACES the root's,
'[]' links nothing), in 'app_defaults'. A name is looked up in the feature
file of the test's own TEST directory and nowhere else. The link exists in
the test's block only.


3  THE CENTRAL FILE  [v10]
______________________________________________________________________________

'hwut-root-features.conf' stands beside 'hwut-root.conf'. It is written by
'hwut.features.init' with a header of '#' comments that says what each section
is; it is a registry, not a generated file: keep it under version control.

    # ... header: external ids stay constant for external references; if
    # those references change, only the left sides here are edited ...
    features {
        directory_map {
            "Qm9xB_2a" = "gateway/router"          # directory id -> path
            "Zk3aT-7c" = "gateway/most"
        }
        tree {
            gateway {                                # an AGGREGATE
                title = "CAN-MOST gateway"
                keys  = ["product"]
                childs {
                    forwarding {
                        title  = "Frames reach their destination."
                        childs {
                            "router.forward" = "Qm9xB_2a:forward"   # a LEAF
                            "most.send"      = "Zk3aT-7c:send"
                        }
                    }
                }
            }
            "new-thing" = "Qm9xB_2a:new-thing"       # registered, not placed
        }
        retired {
            "scroll-old" { id = "Qm9xB_2a:scroll"    # a leaf, as it was
                           title = "The view scrolls by one line." keys = ["display"] }
            "old-group" { title = "..."              # an aggregate, as it was
                          childs { "x.y" { id = "Zk3aT-7c:y" title = "..." } } }
        }
    }

directory_map   directory id -> path (below the directory holding
                'hwut-root.conf') of a COMPONENT directory that owns a TEST
                directory with a feature file. Only such directories have
                an id. The id is generated, never edited: base64url without
                padding, 8 characters, always quoted. A moved directory
                changes this ONE line; every id below stays valid.
tree            a child that is a block is an AGGREGATE; a child that is a
                string is a LEAF (left: external id, right: internal id).
                Leaves at the top level of 'tree' are UNPLACED ('register'
                puts new leaves there; the author moves the line).
retired         the claims no longer made, stored as they were. A block with
                'id' is a leaf, a block with 'childs' an aggregate.

Rules:
- Every id stands once: an internal id in exactly one place (tree or
  retired), an external id once, an aggregate key once. Twice is a fault.
- ONE NAMESPACE: aggregate keys and external ids share it. An external id
  equal to an aggregate key is a fault.
- An internal id in 'retired' is never bound again (a TEST file still
  defining that name is told "retired, rename it"); an external id in
  'retired' never appears in the tree again; a newly generated directory id
  is checked against every id in the file, retired lines included.
- A test that links to a retired leaf: "links a retired feature".
- REVIVAL is by hand: the definition back into the TEST file, the line back
  into the tree, the block out of 'retired'. No face.
- The file holds the CURRENT state. History is configuration management's.
- Lazy: no face reads the TEST files or this file unless it needs them.


4  IDS AND NAMES  [v10]
______________________________________________________________________________

    internal id    <directory id>:<name>      "Qm9xB_2a:forward"
                   seen by tools and the report; written in the tree's right
                   sides and in 'retired'; stable across moves of the directory
    external id    the left side of a leaf line; what the world refers to.
                   First generated as the directory path, dotted, plus the
                   name ('gateway.router.forward'); the author may edit it
                   BEFORE it is given out. After that it stays.
    aggregate key  the key of a block in the tree; unique in the file; its
                   position is its path 'gateway/forwarding'
    tree path      aggregate keys joined by '/': 'gateway/forwarding'; a leaf
                   in a path is written by its external id

IDENTIFIERS (o-10, RULED 2026-10-13, NOT YET BUILT): names, aggregate keys
and the words of an external id follow Unicode UAX #31 (XID_Start /
XID_Continue), widened by DIGITS at the start and '-' in the continue part;
NFC enforced (a word not in NFC is a fault, never silently changed); no case
folding. An external id is such words joined by '.'. No '/', blank, '*', '{',
',' in an external id: a fault of the file, named with its line, the entry
unread. 'str.isidentifier()' implements the classes.


5  THE REPORT  [v10]
______________________________________________________________________________

'hwut.report.features [--directory=<path>]' prints the tree of the central
file: aggregates -> leaves -> test runs and their verdicts, each aggregate
with title and counts, each leaf with its external id (and, with the report's
long form, its internal id), its effective keys, its state and verdict.
RETIRED claims are listed in a block of their own ('--matrix' omits it).

OUTSIDE THE RELATION, named below the tree: a test run naming a feature its
TEST directory does not define; 'NONSENSE?' -- a test run linking to no
feature, where the directory states features; a document a claim names that
does not stand; a statement that is not read; every disagreement of section 7.

BUILT (step 4a, bundle 121): 'feature_view.py' joins the central file with
the relation's TEST directories (links, verdicts), and 'hwut.report.features'
prints it where the central file stands: AGGREGATE <tree path> with a 'state'
line and the counts '<n> implemented, <n> open; <n> ok, <n> fail', each leaf
'[IMPLEMENTED ok|fail]' or '[OPEN]' with 'internal <id>  (<directory>)' and
its effective keys, then UNPLACED, RETIRED (those below the directory asked),
and OUTSIDE THE RELATION with "feature, defined and not registered" and the
detector's findings. '--matrix' names a column by its leaf's state, 'not
registered' where it has none. An empty aggregate reads 'OPEN  (nothing
below it)'. BUILT (step 4b, bundle 122): '--html' / '--ods' write the document of the
view ('feature_document.document_of_view'): a row per leaf under its
external id, 'Aggregate' (its tree path, '(unplaced)') and 'Internal id'
('<id>:<name>  (<directory>)') in the columns of component and published id,
the states 'IMPLEMENTED ok', 'IMPLEMENTED fail', 'OPEN' with their own tree
boxes and style; the tree of aggregates, each with its state and counts. A
feature defined and not registered has no row (the page names it). A
document of the files of the past keeps its bytes.

'NONSENSE?' IS NO FAILURE (services E-145). FEATURE FILES ARE NOT MANDATORY: a
TEST directory without one is named nowhere.

'--matrix', '--code', '--html', '--ods', '--cov-*' stand as in VERSION 9
(table per TEST directory; the code only a feature's runs reached; the feature
document with four tabs; the tree interactive), with the words of section 6.
The 'Features' tab carries the external id, the internal id and the tree
path. 'hwut.run' prints NO feature report (o-5); it prints ONE HINT LINE
(section 7).


6  STATES  [v10] (o-14)
______________________________________________________________________________

    implementation axis        verdict axis
    IMPLEMENTED                ok | fail
    OPEN                       fail
    RETIRED                    none

    leaf        IMPLEMENTED = at least one test run linked; OPEN = none.
                RETIRED = its block stands in 'retired'.
                verdict ok = every linked run passes (or has a verdict).
    aggregate   RETIRED where all below are retired (or it stands in
                'retired'); otherwise retired claims below are ignored and
                it is IMPLEMENTED only if every remaining claim is, else OPEN.
                verdict ok only if everything below is ok.
    empty       an aggregate with nothing below it: OPEN (ASSUMED, unconfirmed)
    OPEN        implies fail. RETIRED has NO verdict, no count, no exit status.

The words PROVEN / FAILING / UNPROVEN of VERSION 9 mix the two axes. The
report may keep them as a reader's summary ("IMPLEMENTED ok", "IMPLEMENTED
fail", "OPEN"), with the axes beside them.


7  THE DETECTOR: REGISTER AND SANITIZE  [v10]
______________________________________________________________________________

ONE implementation judges the central file against the directories and the
TEST files. 'hwut.features.register' ADDS and DETECTS; 'hwut.sanitize.propose
--relations' proposes in the same vocabulary; 'hwut.sanitize.apply' acts. No
second path. 'register' never changes a left side, never retires, never
pairs on its own.

    kind          what disagrees                                 cure
    ---------------------------------------------------------------------
    no-root-file  features stand, no central file               init
    dir-new       a directory owning a TEST feature file has    register
                  no id
    dir-gone      an id's path does not stand (or: most of the  redirect
                  names registered under it stand elsewhere --  <id> <path>
                  the SWAP check)
    dir-twin      a path under two ids / an id twice            fold <id>
                                                                <first id>
    leaf-new      a leaf defined in a TEST file, in no line     register
    leaf-gone     a line names a leaf no TEST file defines      repoint
    leaf-twin     an internal id twice                          said; the author
    name-clash    external id = aggregate key                   said; the author
    retired-use   a retired internal id defined again / an      said; the author
                  external id of 'retired' in the tree
    unplaced      a leaf at the top level of 'tree'             a hint
    (root-test    struck 2026-10-19, the book's D-3: the root's own TEST
                  directory gets an id standing for '.', as any other)
    linked-retired a test links a retired leaf                  a hint
    old-vocabulary component files, 'hwut-feature-map.conf'      migrate

BUILT (step 2, 'feature_detector.py', test-feature_detector.py): the kinds
above except 'linked-retired' (it needs the test links; step 4). Findings are
judged as the tree will stand once the proposals are applied: the leaves of a
directory paired by 'redirect' are not said again, a leaf of a gone directory
without a partner is said by the directory, the second id of a twin defines
nothing.

THE PROPOSAL LINES ARE 'hwut.sanitize' LINES (built step 3c): one
vocabulary for the detector, 'hwut.features.register' and
'hwut.sanitize.propose'; the old value in the note, which no reader of
commands reads (E-130):

    register <dir>
    redirect <id> <new path>                  # from <old path>
    repoint <external id> <new internal id>   # from <old internal id>
    fold <id> <first id>                      # one path, two ids
    # unpaired <id | external> <what> (candidates: ...)   -- a NOTE

Where the central file stands, 'hwut.sanitize.propose --relations' takes the
detector's lines (and says the unpaired ones as NOTEs); where it does not,
the relation of VERSION 9 is judged as before. 'hwut.sanitize.apply' and
'hwut.sanitize <verb>' JUDGE AGAIN: a line is done only where the detector
proposes exactly that line now, else it is NOTHING; a redirect that is half
of a swap takes its mate along in one edit.

PAIRING (a gone with a new; DETECTION ONLY, every pairing is named on its
proposal line):

    1  directories: the overlap of the feature names registered under the
       gone id with those defined in the unregistered directory; paired only
       where mutually best, unique, and the overlap is at least half of the
       gone id's names. Else 'unpaired ... (candidates: ...)'.
    2  leaves inside one directory: an equal name is the same leaf. A leaf
       renamed leaves no title behind -- a live leaf is a line of ids, its
       title stands in the TEST file only -- so there is nothing to compare:
       a directory with exactly ONE gone and exactly ONE new leaf pairs
       them (named on the line); with more, 'unpaired' lists the candidates.
       (CORRECTED 2026-10-14: the first statement said "equal title".)
    3  leaves across directories (a block moved by hand): the one gone name
       and the one new name that are EQUAL, unique.

The suffix rule of VERSION 9 is gone. A gone entry is never retired by a
tool: it stays reported. Retirement is 'hwut.features.retire'.

THE HINT (built step 3c). Where the central file stands, 'hwut.run' ends
with ONE line when features DEFINED in TEST directories below the run's
directory have no line in it -- new, renamed, or their directory moved:

    3 feature(s) not registered => hwut.features.register

It is no report (o-5 stands), the exit status is unchanged, it walks only
below the run's directory and reads the central file once; anything that
goes wrong in it costs the run nothing. 'hwut.help' names each feature
under "FEATURES -- defined, not registered". (DECIDED 2026-10-14: what is
DEFINED and unregistered is measured, not what a test LINKS -- the run
keeps no list of its links, and a rename makes the defined name new.)

'hwut.run' is not affected otherwise: a test runs and is judged whether or
not its links resolve.


8  THE FACES  [v10]
______________________________________________________________________________

    hwut.features.init              writes 'hwut-root-features.conf' with
                                    initial directory ids, the leaves placed
                                    unplaced, the header comments; refuses a
                                    tree holding the old vocabulary and names it
    hwut.features.register [dir]    recursive from the current directory
                                    (default) or the directory named: adds
                                    what is new, detects (section 7). Below
                                    the top only entries whose directory lies
                                    below are judged
    hwut.features.retire <id>       moves the claim into 'retired'; an
                                    aggregate with everything below it. Text
                                    moved, never composed
    hwut.features.move <dir> <new>  'mv' and the one 'directory_map' line
    hwut.features.key.add <id> <key>
    hwut.features.key.remove <id> <key>   [--all <key>: everywhere]
    hwut.features.tree [<base>]     prints the tree below <base>
        --list                      one line per leaf: <tree path>/<external id>
        -b                          aggregates only (branches)
        -e                          adds the external id to each leaf

BUILT (step 3a, bundle 118): 'init', 'register', 'tree' -- services/lib/
features/, test-faces.py. 'register' prints every line it adds, names every
disagreement with its proposal, and folds the unplaced hints into one counted
line; exit 0 where everything agrees, 1 where something is named. Generated
directory ids never begin with '-' (they are typed on command lines).

BUILT (step 3c, bundle 120): 'hwut.sanitize register | redirect | repoint |
fold' (section 7), the hint of 'hwut.run' and its part in 'hwut.help';
'register' moved into the engine ('feature_registry_act.register') so the
face and the sanitizer share it. test-proposals.py.

BUILT (step 3b, bundle 119): 'retire', 'move', 'key.add', 'key.remove'
-- services/lib/features/ (key/ for the two key faces), the multi-file acts
in 'feature_registry_act.py', test-acts.py. Every new text is computed and
held against its faults before anything is written. 'retire' carries a
leaf's own definition; the keys a TEST file states for all its features
are not carried. A retired aggregate is re-indented to its new place
(layout only). 'move' undoes the rename where the central file cannot be
written.

'--list' and '-b' lines can be handed to '-F' as they stand. Retired claims
are not listed. 'hwut.move' (a test with its feature) rewrites the leaf's
line; 'hwut.rename' adapts nothing; 'hwut.remove' names the features left
without a linked run. The sanitizer's 'relate/unrelate/retire' of VERSION 9
are replaced by the proposals of section 7 ('redirect', 'repoint', 'fold'
callable as 'hwut.sanitize <kind>', as 'relate' was).

'amend.py' text surgery is reused for every edit; what is not edited stays
byte for byte. The HOCON dialect (triple quotes, 'none', duplicate key =
fault) is reused.


9  KEYS  [v10]
______________________________________________________________________________

    effective keys of a leaf = its own
                             + those of its TEST file
                             + those of every aggregate above it

Keys travel DOWNWARD only. "Aggregate has key k" is DERIVED, never written.
Directory nesting contributes nothing. KEYS ARE NOT LABELS (labels: sets of
runs, ephemeral, '-l'; keys: durable categories of features, '-k').


10  RESTRUCTURING: THE SCENARIOS  [v10]
______________________________________________________________________________

Judged against the model (R-96, 22 scenarios, 8 messes, 14 use cases):

    a TEST directory or component moved, renamed (by hand)    dir-gone +
                                                  dir-new -> 'redirect', ONE line
    ... with the tool                              hwut.features.move: one line
    a component moved with n TEST directories      n redirects, one prefix
    the root moved                                 every path shifted: one rewrite
    cp -a of a TEST directory                      new id, its leaves unplaced
    a leaf renamed in its file                     leaf-gone + leaf-new: repoint
    a leaf moved to another TEST file              repoint across directories
    merge / split of leaves                        the author; gone stays reported
    an aggregate moved / renamed / a leaf re-placed  pure tree edit; internal ids
                                                  never change; an aggregate key
                                                  rename changes its path only
    a retired name defined again                   retired-use
    a block cut from the tree and not pasted       leaves reported leaf-new at
                                                  the top; a customised external id
                                                  is lost (version control)
    two branches register the same directory       dir-twin -> fold
    the map lost                                   restore from version control;
                                                  'register' refuses to create one
                                                  where features stand
    a subtree cut into another repository         ids regenerate from paths; carry
                                                  lines by hand from
                                                  'hwut.features.tree --list'

Natural messes without bad intent end as 'unpaired'/'ambiguous', never as a
silent wrong binding, provided the SWAP check exists. Rule for authors:
register after each structural step.


11  THE WISH  [v10]
______________________________________________________________________________

    -F, --feature <tree-path>   a path of the tree, '<base>/<feature>' or an
                                internal id '<dir id>:<name>' (o-16): an
                                aggregate brings its subtree, a leaf is named
                                by its external id. '*' one level, '**' any
                                depth, '{a,b}' choice. Lines of
                                'hwut.features.tree --list' / '-b' fit as
                                they stand. Repeats UNION; narrows the rest.
    -e, --feature-ext <id>      leaves by EXTERNAL id (exact, or '*' in a
                                word). A retired id is REFUSED by name.
    -k, --keys <expr>           the grammar of '-l' over EFFECTIVE keys. A key
                                no feature carries is refused by name.

BUILT (step 4c, bundle 123, 'feature_wish._view_case_set_of'): where the
central file stands the view answers. '-F' over tree paths ('*' any part of
one level, '**' any levels, '{a,b}'; a glob without '/' and without glob
characters is '**/word'; one with them and without '/' is ONE level from the
top) or, with ':', over internal ids; '-e' over external ids, whole, '*' any
characters. '-F' and '-e' are ONE union, '-k' narrows it. An external id that
names no feature (no glob) is REFUSED by name, as a retired one is (DECIDED:
a customer's id selecting nothing silently is the failure the wish exists to
prevent); a retired internal id named by '-F' is refused. Where no central
file stands '-e' is refused ("hwut.features.init"). The usage line of every
face that takes the wish gained '[-e|--feature-ext <id>]...'; 16 pages that
print it were re-recorded after their difference was shown to be that alone.

'-F', '-e' and '-k' together: a run is wanted where ONE of its leaves satisfies
all that are given. A run linked to nothing is wanted by none.
'hwut.report.list -F ... -e ... -k ...' round-trips as a wishlist.
('-FE' as one token is not used.) The cache is per process (feature_wish.py).
