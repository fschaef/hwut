INTENT
------------------------------------------------------------------------------
A PROJECT HAS ONE REFERENCE. The root holds what the project is: its
platforms and their tools, its languages, its ignore list, its labels,
its feature registry. Below it, hwut.conf refines -- in TEST or in any
directory above a TEST -- and never reaches above the root.

    <project>/hwut-root.conf      platform, tools, language-setup, ignore,
                                  app_defaults; hwut-root.labels, features
    <project>/**/hwut.conf        refines; 'requires' adds (o-57)
    climbing from .../TEST        stops at the first hwut-root.conf

MEASURED (c317557): four inner roots stand in hwut's own tree.

    support/hwut-root.conf                requires 14 tools; language-setup
                                          (17 entries), ignore, app_defaults
                                          -- every one equal to the top's
    support/test_writing/python/TEST/     requires nothing: there to cancel
                                          support/'s requires (o-54)
    support/remote/model/                 requires nothing; ignore adds
                                          'fake_agent.py'
    support/remote/iverilog/              requires iverilog, replacing
                                          support/'s (o-54)

Their only work that the top does not do is o-54: an inner root's
'requires' REPLACES. Everything else is a copy E-200 forced ("said here
again"). With 'requires' stated where a need arises, none of the four
is needed.

RULED
------------------------------------------------------------------------------
R-1  ONE hwut-root.conf PER PROJECT (2026-11-15: "my wish was to have a
     single hwut-root.conf for a project that talks about platforms etc.
     that is all others would have to become 'hwut.conf' files").

R-2  THE CLIMB STOPS AT THE FIRST ROOT; BEYOND IT NOTHING IS SEEN
     (2026-11-15: "When we are in /a/b/c/d/e/f/TEST and we find a
     /a/b/c/hwut-root.conf while going backwards, we stop there; a
     /a/b/hwut-root.conf or any other configuration file would be beyond
     our radar." -- "outside the project we cannot make any assumptions
     on how people call their files"). The inside half of E-200, kept.

R-3  A hwut-root.conf BELOW THE ROOT IS ANOTHER PROJECT, NOT WALKED FROM
     ABOVE (q2 (b), 2026-11-15):
         NOTE  vendor/lib/: a project of its own (hwut-root.conf)
               => run hwut inside it
     Read out: the outside half of E-200 ("every way in") is retired. The
     note is also the migration: whoever holds an inner root today reads
     it and chooses -- a project of its own, or a hwut.conf.

R-4  EACH DIRECTORY DECIDES; HANDED OVER GROUPED BY PLATFORM (q1 (a),
     2026-11-15: "I tend towards (a)"). 'requires' names tools and adds
     downwards (o-57 stands); "all of the above requires" is said once
     in a non-TEST hwut.conf ("we can do this in a non-TEST hwut.conf").
     A directory runs on the first defined platform announcing all it
     requires (o-58); the directories a platform takes go to it in ONE
     run. BUBBLES ARE RETIRED (2026-11-15: "let us think about bubbles.
     what would they serve?").

R-5  NO PLATFORM -> REFUSED; A PLATFORM LACKING WHAT IT DECLARES -> FAIL
     (2026-11-15: "If there is no platform that has it, it refuses. If a
     platform does not work as expected (does not have the tool), the
     according test fails with the message of 'platform does not provide
     tool'.")
         platform local does not provide tool iverilog
         (not on PATH: iverilog, vvp; hwut-tools.rst probe)
     AMENDS E-226: a probe that misses no longer withdraws the tool from
     'local' (no NOTE, no skip, no fall to the next platform); the
     declaration is the contract, its breach a failing case. A tool
     without a 'probe:' line is taken as declared (E-226 stands there).

R-6  A DIRECTORY NO PLATFORM CAN TAKE IS COUNTED REFUSED (o-1 (a),
     2026-11-15): its cases count 'refused' in RESULTS ('..., 12
     refused'), the directory is marked in the final tree -- as o-59
     counts a case refused for its header. Answers the book's D-84 and
     its section 5 Q1.
     WHAT IS COUNTED (o-3 (b), 2026-11-15): its TEST directories --
     'RESULTS: ..., 15 directories not run' (services E-229).

R-7  EVERY PLATFORM CHECKS ITSELF (o-2 (b), 2026-11-15: "A container is
     a platform"). hwut over there probes the tools of the platform it
     runs as ('as_platform') before its first case; a miss fails that
     platform's cases with R-5's sentence:
         platform linux does not provide tool gfortran
         (not on PATH: gfortran; hwut-tools.rst probe)
     One probe, one place, used on both sides.

FOR THE BOOK (2026-11-15: "make this point later to the book writers what
can be a platform: container, remote interaction socket/infra ..."):
  say what a platform IS -- a place hwut runs that announces tools. Built
  kinds (c317557): 'local' (this machine) and 'container'. Remote
  execution (support/remote, hwut_remote) is today a TEST talking to an
  agent over a link, not a platform kind; whether a socket or an infra
  host becomes a kind is not ruled.

R-8  '--no-bubbles' AND '!<hwut-root>' REFUSED BY NAME (o-4, 2026-11-15:
     "refuse"), as '--no-boundary' (E-202); services E-230.
