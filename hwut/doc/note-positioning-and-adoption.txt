NOTE — positioning and adoption
===============================

Nothing here is ruled. This is material for a later decision.

THE CLAIM THAT HOLDS
--------------------
An assert can only fail on a hypothesis the author already had.
A blessed picture fails on everything.

That asymmetry is the whole value. It is why characterising an
unfamiliar system with HWUT takes an afternoon.

The second claim, which is the deeper one:

A GOOD file is a formal, authoritative expression that a behaviour is
correct. It is grounded on an expert's competence. An expert judges
correctness far better when the behaviour is described clearly.
Therefore free expression is not decoration — it is what makes the
expert's judgement reliable, and the reliability of that judgement is
what makes the test statement trustworthy.

Free expression -> better judgement -> trustworthy blessing.
That chain is the argument. Lead with it.

WHERE NOT TO FIGHT
------------------
Not against pytest for the centre of the Python world. Defaults, IDE
buttons, and what the junior already knows decide that ground, and
none of them are decided on merit.

WHERE TO STAND
--------------
Ground the assert model is bad at:

  - compilers, parsers, code generators
  - command line tools
  - protocol stacks
  - cross-language systems
  - legacy characterisation, where no specification exists at all

INTEROPERATE RATHER THAN REPLACE
--------------------------------
  - pytest plugin: HWUT tests run inside suites that already exist.
    (Ruled worth doing.)
  - JUnit XML output: HWUT results appear in dashboards that already
    exist.

Both are distribution, not architecture. They cost little and they
remove the two standard objections before they are raised.

THE DIFFERENTIATORS, RANKED
--------------------------
See note-independence-coverage-build.txt. In order of how little
anyone else can answer them:

  1. The build folded into the test result. A test that does not
     compile is a failed test, not an aborted suite.
  2. One coverage record spanning all languages in the repository.
  3. Language independence with nothing installed into the subject.
     The HWUT for C is the HWUT for Haskell.
  4. Tolerant comparison: analogies, numeric tolerance, potpourri.
  5. --hwut-info choice combinatorics.

Free description of behaviour is the value, but it is not the
differentiator — see note-neighbouring-tools.txt. Lead with 1 to 3.

THE DEMONSTRATION
-----------------
Not a feature tour. Point HWUT at a repository it has never seen, in
languages it was never taught, and produce a behavioural net and a
coverage figure by lunch without modifying a line of it.

The legacy-binary variant of the same demonstration carries the value
claim; the polyglot variant carries all five differentiators at once.

Coverage benchmarks travel further than philosophy. Keep them
prominent and keep them reproducible.

THE NAME
--------
HWUT — the Hello-Worldler's Unit Test. Pronounced "hood".
The "ha-what?" mishearing is a hook, not a liability.

Remaining cost is search: what a stranger finds when they look for
"hwut". Worth checking before release and worth a canonical domain and
a distinctive first-page snippet if it looks thin.
